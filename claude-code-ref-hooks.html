Усі події хуків

33 події за документацією на 2026-09-04; встановлена 2.1.236 знає 31

Перехоплювач подій (hook) — це твоя команда, яку Claude Code запускає сам, коли в сесії стається щось конкретне: почалась сесія, викликається інструмент, агент закінчив відповідати. Ця сторінка — таблиця всіх подій, на які можна почепити таку команду: коли кожна спрацьовує, за чим фільтрує, що приходить на вхід і що можна віддати на виході.

Тут немає тесту, немає позначки «пройдено» і цієї сторінки немає в сертифікаті. Довідник не проходять — до нього повертаються. Якщо ти ще не робив жодного перехоплювача, спершу прочитай модуль 16 «Перехоплювачі подій (hooks)»: там пояснено, як влаштований файл налаштувань, що таке matcher і чому exit 1 нічого не блокує. Сюди повертайся по подробиці.

Як влаштована ця сторінка

Перехоплювач описується трьома рівнями вкладеності, і колонки таблиці повторюють ці рівні: 

flowchart TD
  E["Подія — КОЛИ запускати: PreToolUse"] --> M["matcher — ЗА ЯКИХ УМОВ: лише Bash"]
  M --> H["Обробник — ЩО ЗАПУСТИТИ: команда, HTTP, MCP, промпт, агент"]
  H --> I["Вхід: JSON у стандартний потік вводу"]
  I --> S["Твоя команда"]
  S --> O["Вихід: JSON на stdout + код завершення"]
  O --> D["Claude Code вирішує, що робити далі"]

  style D fill:#2A211C,stroke:#D97757,color:#F0EEE6

Три рівні конфігурації й два канали відповіді. Колонки великої таблиці нижче — це «коли», «за яких умов», «що приходить» і «що можна віддати».

Три речі, яких немає в жодній таблиці документації

Ці три обмеження в документації розкидані по різних розділах, і кожне з них ламає хук мовчки: помилки немає, хук не запускається — і все. Тому вони йдуть першими.

1. Десять подій не мають matcher — і доданий ігнорується без попередження

Документація каже це одним рядком: «якщо додати поле matcher до події, яка його не підтримує, воно мовчки ігнорується». Наслідок: хук, який ти вважав вузьким, спрацьовує щоразу. Ось повний список таких подій:

UserPromptSubmitPostToolBatchStopTeammateIdle TaskCreatedTaskCompletedWorktreeCreateWorktreeRemove MessageDisplayCwdChanged

Фільтрувати їх можна тільки всередині власного скрипта: прочитати JSON зі стандартного потоку вводу й вийти з кодом 0, якщо подія не та, яку ти чекав.

2. Поле if працює рівно на п'яти подіях

if — це другий, точніший фільтр обробника: він написаний синтаксисом правил дозволів ("Bash(git *)", "Edit(*.ts)") і дивиться не лише на назву інструмента, а й на його аргументи. Але працює він тільки на подіях про інструменти:

PreToolUsePostToolUsePostToolUseFailure PermissionRequestPermissionDenied

Дослівно з документації: «On other events, a hook with if set never runs» — на будь-якій іншій події хук із if не виконається жодного разу. Не помилка, не попередження, не рядок у журналі: тиша. Якщо твій хук на SessionStart чи Stop ніколи не спрацьовує — перше, на що варто подивитись, це чи не лишилось у ньому if.

Ще три правила if, на яких спотикаються:

  • Одне правило на обробник. Немає ні &&, ні ||, ні списку. Треба дві умови — пиши два обробники.
  • Фільтр приблизний за задумом. Коли Claude Code не може розібрати, які саме команди запустить рядок Bash (наприклад, там $TOOL git push), він запускає хук на всяк випадок. Через це if не годиться як жорсткий заборонний бар'єр — для заборони є система дозволів.
  • Тека без глибини. "Edit(src/**)" накриває теку src лише в робочій теці. Щоб накрити src на будь-якій глибині, пиши "Edit(**/src/**)". До версії 2.1.214 поведінка була протилежна.

3. Дефолтний timeout різний — і не завжди 600 секунд

Таймаут задають полем timeout в обробнику, у секундах. Коли поля немає, Claude Code бере одне з цих значень:

Випадок Дефолтний таймаут Що з цього виходить
command, http, mcp_tool 600 с десять хвилин — базове значення для більшості подій
prompt 30 с обробник-промпт іде до швидкої моделі
agent 60 с обробник-агент устигає зробити кілька викликів інструментів
події UserPromptSubmit, PreModelSwitch, PostModelSwitch 30 с знижений дефолт для command/http/mcp_tool: ці події тримають сесію, поки хук не відповість
подія MessageDisplay 10 с хук стоїть між моделлю й екраном; при таймауті показується оригінальний текст
подія SessionEnd 1,5 с на ВСІ хуки разом спільний бюджет, а не на кожен хук. Явний timeout у налаштуваннях піднімає бюджет до цього значення, максимум до 60 с

Що робить таймаут, теж залежить від події. На більшості — хук скасовується, його вивід відкидається, і рішення не виноситься взагалі. Два винятки варто знати напам'ять: на PreToolUse хук, який завис, не блокує виклик (не розраховуй на завислий скрипт як на гейт), а на PreModelSwitch, навпаки, скасований по таймауту хук блокує перемикання моделі.

Таймаут не діє на фоновий хук — той, що запущений із "async": true.

Спільні поля входу

Хук отримує JSON у стандартний потік вводу (для http-обробника — тілом POST-запиту). Ці поля приходять усім подіям; те, що специфічне для події, — у великій таблиці нижче.

Поле Що в ньому
session_id ідентифікатор поточної сесії
prompt_id UUID промпта, який обробляється зараз. Збігається з атрибутом prompt.id у телеметрії OpenTelemetry. Немає, поки не було першого вводу
transcript_path шлях до файла розмови. ⚠ Файл пишеться асинхронно й може відставати від пам'яті: якщо потрібен останній текст поточного ходу, бери last_assistant_message з входу події Stop, а не читай транскрипт
cwd робоча тека на момент запуску хука
permission_mode режим дозволів: default, plan, acceptEdits, auto, dontAsk, bypassPermissions. ⚠ Режим, підписаний у програмі як Manual, приходить сюди як default, а не manual. Приходить не всім подіям
effort об'єкт із полем level: low, medium, high, xhigh, max. Якщо модель не підтримує заданий рівень, тут стоїть той, що реально відпрацював
hook_event_name назва події, яка спрацювала
agent_id тільки коли хук спрацював усередині субагента. Так відрізняють виклик із субагента від виклику з головної розмови
agent_type ім'я агента (Explore, security-reviewer). Приходить, коли сесія запущена з --agent або хук спрацював у субагенті

Змінної середовища $CLAUDE_MODEL не існує. Поточну модель бачить лише SessionStart (поле model, і не завжди), а стежити за нею впродовж сесії треба хуком PostModelSwitch — у нього приходять from_model і to_model.

Спільні поля виходу й коди завершення

Хук відповідає двома каналами одразу: текстом на stdout і кодом завершення. Якщо на stdout лежить JSON (текст починається з { і закінчується }), Claude Code читає з нього поля. Ці поля приймають усі події — хоч частина подій їх відкидає, і в таблиці подій це зазначено.

Поле Що робить
continue за замовчуванням true. false зупиняє обробку повністю й перебиває будь-яке рішення самої події
stopReason текст, який побачить людина, коли continue дорівнює false. Моделі не показується
suppressOutput ⚠ не робить нічого. Поле приймається, але не діє: вивід успішного хука й так не показується в розмові, а лягає в журнал відлагодження
systemMessage попередження, яке побачить людина
terminalSequence escape-послідовність термінала: сповіщення робочого столу, заголовок вікна, звук. Дозволені лише OSC 0/1/2/9/99/777 і BEL; усе інше ігнорується цілком. Це єдиний законний спосіб «пікнути»: хуки працюють без керуючого термінала й писати в /dev/tty не можуть

Довжина рядків виходу (включно з additionalContext і systemMessage) обмежена 10 000 символів: довше зберігається у файл, а на місці лишається початок і шлях до файла.

М'якший варіант — additionalContext: розмова так само триває, але в стрічці це підказка, а не помилка. ⚠ Стеля — 8 продовжень поспіль, далі Claude Code перекриває хук. Приклад із документації про великі репозиторії: хук отримує шлях до транскрипту, тож скрипт може переглянути сесію й запропонувати правку CLAUDE.md, «поки прогалина свіжа»
StopFailure хід обірвався через помилку API замість нормального завершення тип помилки: rate_limit · overloaded · authentication_failed · oauth_org_not_allowed · account_on_hold · billing_error · invalid_request · model_not_found · server_error · max_output_tokens · unknown error; іноді error_details, last_assistant_message нічого: вивід і код завершення ігноруються повністю — крім terminalSequence. Подія для журналу й сповіщень
PreCompact перед ущільненням контексту що запустило ущільнення: manual (команда /compact) · auto (вікно контексту заповнилось) trigger, custom_instructions (те, що ти дописав до /compact; при автоматичному — null) блокує: exit 2 або decision: "block". ⚠ Наслідок різний: якщо ущільнення запустилось завчасно, розмова триває неущільненою; якщо воно вже рятує від переповненого вікна — поточний запит впаде з помилкою. systemMessage і continue відкидаються
PostCompact ущільнення завершилось ті самі manual · auto trigger, compact_summary — сам згенерований підсумок розмови без рішення. systemMessage і continue відкидаються

Інструменти й дозволи — 7 подій

У всіх п'ятьох подіях про інструменти matcher фільтрує за назвою інструмента: Bash, Edit|Write, Read, Glob, Grep, Agent, WebFetch, WebSearch, AskUserQuestion, ExitPlanMode, PowerShell, Workflow і будь-який інструмент MCP. Інструменти MCP звуться mcp__сервер__інструмент, і щоб накрити весь сервер, потрібне саме mcp__memory__.*: без .* рядок читається як точна назва й не збігається ні з чим.

Подія Коли спрацьовує matcher Вхід Вихід
PreToolUse параметри виклику готові, сам виклик ще не пішов. Це найраніша точка: спрацьовує до будь-якої перевірки режиму дозволів назва інструмента — будь-яка, крім EndConversation tool_name, tool_input, tool_use_id блокує. permissionDecision: allow · deny · ask · defer (відкласти виклик) + permissionDecisionReason. updatedInput переписує аргументи інструмента, additionalContext додає контекст. ⚠ Не спрацьовує на файли, підтягнуті через @ у промпті: вони вставляються без виклику інструмента, і хук на Read їх не побачить

Текст іде моделі як зворотний зв'язок. ⚠ Не спрацьовує на відмови до виконання: невідома назва інструмента чи неправильні аргументи не дають ні цієї події, ні PreToolUse; відмова в дозволі дає PreToolUse, але не цю подію

PostToolUse у цей момент спрацьовує стільки разів, скільки було інструментів, і одночасно немає tool_calls — масив із описом кожного виклику в пакеті блокує: decision: "block" зупиняє робочий цикл до наступного звернення до моделі. Місце для контексту, який залежить від набору інструментів, а не від одного
PermissionDenied автоматичний режим відхилив виклик інструмента. ⚠ Тільки автоматичний: ручна відмова в діалозі, блокування хуком і правило deny сюди не потрапляють назва інструмента tool_name, tool_input, tool_use_id, reason відмова вже сталась, код завершення й stderr ігноруються. Єдине рішення — retry: true: сказати моделі, що спробувати ще раз можна. Для відмов, винесених без вердикту перевіряльника, retry ігнорується
Notification Claude Code надсилає сповіщення. Хук спрацьовує навіть тоді, коли сповіщення робочого столу вимкнені: налаштування міняє спосіб, а не сам факт події тип сповіщення: permission_prompt · idle_prompt · auth_success · elicitation_dialog · elicitation_url_dialog · elicitation_complete · elicitation_response · agent_needs_input · agent_completed · quota_auto_resume_fired · quota_auto_resume_stale · quota_auto_resume_disabled message, notification_type, іноді title не блокує, код завершення й stderr ігноруються. Сповіщення робиться полем terminalSequence. ⚠ Тайминг: у терміналі permission_prompt чекає ~6 секунд без твого набору, а idle_prompt — ~60 секунд після відповіді. Потрібен сигнал одразу — бери PermissionRequest

Діалоги MCP-серверів — 2 події

MCP (Model Context Protocol) — спосіб під'єднати до Claude Code зовнішні сервери з інструментами; про нього модуль 18. Такий сервер може посеред роботи попросити ввід у людини — це й називається elicitation.

Подія Коли спрацьовує matcher Вхід Вихід
Elicitation MCP-сервер просить ввід посеред задачі. За замовчуванням Claude Code показує діалог людині; хук може відповісти замість неї й діалог не показувати взагалі ім'я MCP-сервера mcp_server_name, message; іноді mode, url, elicitation_id, requested_schema відповідає або блокує: action — accept / decline / cancel, і content зі значеннями полів форми при accept. exit 2 — відмова
ElicitationResult людина вже відповіла на діалог, відповідь ще не пішла назад серверу ім'я MCP-сервера mcp_server_name, action; іноді mode, elicitation_id, content блокує або переписує: action і content можуть замінити те, що ввела людина. exit 2 блокує відповідь — вона перетворюється на відмову

Хто блокує, а хто ні

  • Рівні складаються, а не заміняють один одного. Налаштування користувача, проєкту й локальні додають свої хуки до керованих, а disableAllHooks ззовні керованих налаштувань керовані хуки не вимикає.
  • У субагентах виконуються ті самі хуки з файлів налаштувань, керованої політики й плагінів. Вхідний JSON тоді несе agent_id і agent_type, тож гейт на PreToolUse накриває субагентів автоматично.
  • Хук у frontmatter субагента живе, поки той працює, і подія Stop там автоматично перетворюється на SubagentStop. Хук навички, навпаки, лишається зареєстрованим до кінця сесії — прибрати його після першого вдалого запуску можна полем once: true (працює тільки у frontmatter навички).
  • Довіра до теки — і тут дві різні відповіді. В інтерактивній сесії Claude Code не запускає хуки з жодного файла налаштувань, поки ти не приймеш діалог довіри до теки. А в -p і в SDK діалог не показується взагалі й тека вважається довіреною — тому хуки, закомічені в чужому .claude/settings.json, там виконаються. Перед claude -p над чужим репозиторієм документація радить три речі: переглянути .claude/, запуститись із --bare або додати --settings '{"disableAllHooks": true}'.
  • allowManagedHooksOnly в керованих налаштуваннях блокує твої хуки — користувацькі, проєктні, локальні й плагінні (крім плагінів, увімкнених примусово самою організацією).
  • Меню /hooks — тільки для читання. Воно показує всі налаштовані хуки з позначкою типу й джерела (User Settings, Project Settings, Local Settings, Plugin Hooks, Session Hooks), але нічого не додає й не змінює: правити треба сам JSON.

Як це читати

strings дістає з програми всі текстові рядки; grep -q мовчки перевіряє, чи є там потрібний. Порожня відповідь означала б, що всі 33 події на місці. Дві надруковані назви — це і є розрив: збірка 2.1.236 знає 31 подію з 33.

Межа методу: знайдений рядок доводить, що назва в програмі є, а не те, що подія працює точно так, як описано. Зворотний бік надійніший: якщо назви немає — події немає напевно. Для контролю варто прогнати той самий рядок із вигаданою назвою (ZzqqEventFake) — вона мусить дати «немає».

Другий спосіб, без strings: написати в .claude/settings.json неіснуючу подію й запустити claude doctor — програма надрукує перелік подій, які знає. На 2.1.236 у ньому 31 рядок. ⚠ claude doctor виходить із кодом 0 навіть тоді, коли знайшов зламані налаштування, тому як перевірку в автоматичному конвеєрі його брати не можна.

Чого тут немає

  • Як написати перший хук — це модуль 16 «Перехоплювачі подій (hooks)»: приклади, типові граблі, вправа на власній машині.
  • Повні схеми tool_input для кожного інструмента (Bash, Edit, Read, Glob, WebFetch і решта) — вони різні в кожного інструмента й змінюються разом із ними. Дивись розділ «PreToolUse input» на сторінці документації.
  • Ключі settings.json — окремий довідник «Ключі settings.json».
  • Слеш-команди й гарячі клавіші — довідник «Усі команди й клавіші».
Одне попередження, яке не можна пропустити

Обробник типу command виконує команди оболонки з твоїми повними правами: він може змінити, видалити або прочитати будь-що, до чого має доступ твій обліковий запис. Хуки з чужого репозиторію, плагіна чи навички — це чужий код на твоїй машині. Читай їх перед тим, як дозволити.
