Ключі settings.json

223 ключі · звірено з документацією 2026-09-04 · перевірки на macOS 26.5.2, збірка Claude Code 2.1.236

settings.json — текстовий файл, у якому записано, як поводиться Claude Code: що йому дозволено робити без запитання, якою моделлю він відповідає, як виглядає екран. Цей довідник перелічує всі ключі, які Claude Code із таких файлів читає, і для кожного каже дві речі: що він робить і в якому саме файлі його має сенс писати.

Друга частина важливіша за першу. Найчастіша поразка з налаштуваннями — не помилка в синтаксисі, а правильно написаний ключ у файлі, з якого він не діє. Помилки при цьому немає: Claude Code мовчки читає файл далі. Тому колонка «Область» у кожній таблиці стоїть поруч з описом, а перед таблицями йде розділ про дев'ять пасток.

Це не урок — його не проходять

Тут немає тесту, ця сторінка не рахується в прогрес і не входить у сертифікат. Сюди повертаються з питанням «як називався той ключ» і йдуть далі. Найшвидший спосіб — Ctrl+F (на Mac Cmd+F) і шматок назви.

Пояснення «навіщо це взагалі» живе в уроках: файли й порядок їх перекриття — модуль 13, дозволи — модуль 7, пісочниця — модуль 8, перехоплювачі подій — модуль 16.

Термін придатності цієї сторінки — короткий

Перелік знімали двічі: 3 вересня 2026 року в ньому було 222 ключі, 4 вересня — 223. За одну ніч додався permissions.blockReadsOutsideWorkingDirectories. Це не аномалія, це швидкість, з якою змінюється Claude Code.

Тому: якщо ключа тут немає — це не означає, що його немає. Звіряй із першоджерелом: довідник налаштувань у документації. Як перевірити конкретний ключ на своїй машині — пастка 9.

Чотири файли — і хто на кого впливає

Ключів багато, а файлів, у які їх пишуть, лише чотири. Плюс п'ятий, окремий, для шести ключів — про нього в розділі «Глобальний конфіг».

Записи ~/.claude означають теку .claude у твоїй домашній папці; на Windows це %USERPROFILE%\.claude. А .claude без тильди — тека всередині проєкту.

Порядок перекриття

Коли той самий ключ трапляється в кількох місцях, виграє найвищий рівень із тих, що його задають. Зверху вниз:

  1. керовані налаштування організації — їх не перекриває ніщо;
  2. аргументи командного рядка — прапорці, з якими ти запустив claude, на одну сесію;
  3. локальний .claude/settings.local.json;
  4. спільний проєктний .claude/settings.json;
  5. свій ~/.claude/settings.json.

Змінні середовища в цьому стосі не рівень. Для кожної пари «змінна + ключ» рішення своє: ANTHROPIC_MODEL з оболонки перебиває ключ model з будь-якого файла, а ANTHROPIC_DEFAULT_MODEL діє лише тоді, коли ключа model немає ніде.

Списки складаються, а не заміняють

Якщо той самий ключ-масив (наприклад, permissions.allow) заданий у кількох файлах, Claude Code складає списки, а не бере один. Так само складаються перехоплювачі подій і claudeMdExcludes. Винятків чотири, і всі — про моделі: fallbackModel, modelPicker, availableModels і modelSettings беруться цілком з одного джерела.

Коли правка починає діяти

Claude Code стежить за файлами налаштувань і підхоплює більшість змін на льоту — без перезапуску, включно з permissions, hooks і помічниками облікових даних. Але три ключі читаються один раз, на старті сесії:

  • model — міняється командою /model посеред сесії;
  • effortLevel і modelSettings — командою /effort;
  • outputStyle — це частина системного промпта, тож потрібен /clear або перезапуск.

Дев'ять пасток, через які правильний ключ не працює

Усе нижче — не рідкісні випадки, а поведінка за замовчуванням, задокументована й неочевидна. Якщо налаштування «не спрацювало», спершу шукай себе тут.

1. auto і bypassPermissions із проєктного файла мовчки не діють

Ключ permissions.defaultMode задає режим, у якому стартує сесія. Два його значення — auto і bypassPermissions — з .claude/settings.json і .claude/settings.local.json не застосовуються. Помилки немає, попередження немає; сесія стартує у звичайному режимі, і людина думає, що режим зламався.

Куди класти: у ~/.claude/settings.json, у керовані налаштування — або передавати прапорцем --permission-mode на одну сесію. До версії 2.1.257 bypassPermissions діяв із будь-якого файла; саме тому старі поради в мережі суперечать нинішній поведінці.

2. Пісочниця має власну, вужчу область

Ключів sandbox.* тридцять сім, і область у них не одна на всіх. Дванадцять із них проєктний файл не вмикає.

Тільки з керованих налаштувань (чотири): sandbox.bwrapPath, sandbox.socatPath, sandbox.filesystem.allowManagedReadPathsOnly, sandbox.network.allowManagedDomainsOnly.

Зі свого або керованого файла (вісім): sandbox.allowAppleEvents, sandbox.ripgrep, sandbox.filesystem.disabled, sandbox.network.strictAllowlist, sandbox.network.tlsTerminate, sandbox.credentials.allowPlaintextInject, sandbox.credentials.awsPairs, sandbox.credentials.sigv4. Решта двадцять шість — з будь-якого файла, зокрема сам sandbox.credentials і його підключі files та envVars.

Це та сама пастка, що з auto: проєктний файл їх не вмикає. Логіка одна — чужий репозиторій не повинен мати змоги послабити твою пісочницю.

3. Сім ключів, де суворіше значення виграє в керованого

Загальне правило «керовані налаштування перекривають усе» має рівно сім винятків. Для них Claude Code бере суворіше значення, звідки б воно не прийшло. Це зроблено так, щоб політика організації не могла ввімкнути тобі те, що ти вимкнув свідомо.

5. Правила deny не тримають довільні підпроцеси

Заборони Read(...) і Edit(...) діють на вбудовані файлові інструменти Claude і на ті команди Bash, які Claude Code упізнає як файлові — cat, head, tail, sed. Вони не діють на довільний підпроцес: скрипт на Python чи Node, який відкриває файл сам, пройде повз заборону.

Документація дає з цього рівно один вихід: якщо потрібна заборона на рівні операційної системи — вмикай пісочницю (sandbox.enabled). Заборона в permissions.deny — це межа для агента, а не для процесів.

Ще дві дрібниці того ж розділу. Перевірка файлових шляхів іде тільки проти правил Read(...) і Edit(...): якщо написати Write(docs/**) чи Glob(docs/**), правило приймуть, але ніколи не звірятимуть — і на старті буде попередження. І шаблон "*" в імені інструмента забороняє всі інструменти, а "mcp__*" — усі інструменти MCP.

6. Одна скісна риска на початку шляху означає не те, що здається

Read(/secrets/**) у своєму файлі ~/.claude/settings.json захищає не теку secrets у проєкті, а ~/.claude/secrets/**. Одна скісна риска прив'язує шлях до джерела налаштувань, а не до кореня диска.

ЗаписЩо означає
//шляхабсолютний шлях від кореня файлової системи
~/шляхвід домашньої теки
/шляхвід того місця, з яким пов'язаний сам файл налаштувань
шлях або ./шляхвід поточної теки

Тобто щоб правило зі свого файла діяло в кожному проєкті, потрібен запис із // або з ~/. На Windows шляхи нормалізуються до POSIX-вигляду: C:\Users\anna стає /c/Users/anna, тож усі .env на диску C — це //c/**/.env, а на всіх дисках — //**/.env.

7. Виключення CLAUDE.md складаються, а керовані не виключаються

claudeMdExcludes — список файлів пам'яті, які пропустити. Списки з різних областей складаються, тому виключення з проєктного файла не заміняє твоє, а додається до нього. Виключити керований CLAUDE.md, який розгорнула організація, не можна взагалі — виключення діють лише на свої, проєктні й локальні файли пам'яті.

9. Перелік випереджає твою збірку — і випереджає її сильно

Документація описує найсвіжішу версію. Встановлена на машині — майже завжди старіша. На 4 вересня 2026 року розрив був такий: у каналі latest — 2.1.260, локально встановлено 2.1.236. Двадцять чотири версії різниці.

Наслідок практичний: щонайменше дев'ять ключів із цієї сторінки в збірці 2.1.236 не існує взагалі — keybindingFlavor, modelPricing, promptCacheTtl, subagentPromptCacheTtl, managedSourcesBehavior, desktopSessionCleanupPeriodDays, modelSettings, timeFormat і permissions.blockReadsOutsideWorkingDirectories. У таблицях вони позначені мінімальною версією.

Рух буває і в інший бік: permissionExplainerEnabled у збірці 2.1.236 ще є, а у 2.1.257 його прибрали разом із поясненням команди по Ctrl+E.

Перевірити конкретний ключ на своїй машині можна без запуску Claude Code. Команда strings дістає з бінарного файла всі текстові рядки, а grep -c рахує, скільки разів у них трапилось слово. Нуль означає, що твоя збірка про цей ключ не знає:

Читається так: spellcheck вимагає 2.1.235, встановлено 2.1.236 — ключ на місці, 31 збіг. modelSettings вимагає 2.1.251, timeFormat — 2.1.257: обох немає. Останній рядок — контрольний: вигадана назва теж дає нуль, і це доводить, що нуль означає «немає», а не «команда не спрацювала». Без контрольного рядка перевірка нічого не варта.

Ім'я користувача в запрошенні на знімку замінене на вигадане — сама команда домашнього шляху не друкує, бо бере "$(which claude)" замість абсолютного шляху до програми.

Межа цього способу

strings шукає збіг підрядка, а не оголошення ключа. Тому короткі назви зі звичайних англійських слів дають хибні спрацювання: timeZone у збірці 2.1.236 показує 19 збігів, хоча сам ключ потребує 2.1.257 — timeZone є стандартним параметром у JavaScript і трапляється в бінарнику з іншого приводу. Нуль — доказ; ненульове число — лише привід перевірити інакше.

Чотири готові приклади

Ці фрагменти можна скопіювати у файл налаштувань як є. Якщо в тебе там уже щось написано — злий об'єкти вручну, а не додавай другу пару фігурних дужок: у файлі має бути один зовнішній об'єкт.

Закрити файли з секретами

Приклад із документації дослівно. Заборонені файли зникають і з пошуку, і з видачі файлових інструментів; редагувати й створювати їх теж не можна. 

{
  "permissions": {
    "deny": [
      "Read(./.env)",
      "Read(./.env.*)",
      "Read(./secrets/**)",
      "Read(./config/credentials.json)",
      "Bash(curl *)"
    ]
  }
}

Нагадування з пастки 5: це межа для агента, а не для процесів, які він запускає.

Свій рядок стану

Показує назву моделі й відсоток заповнення контексту. Потрібна встановлена програма jq — вона витягує значення з JSON, який Claude Code подає скриптові на стандартний вхід. padding додає два символи відступу; є ще refreshInterval у секундах, і менше за одиницю він не буває. 

{
  "statusLine": {
    "type": "command",
    "command": "jq -r '\"[\\(.model.display_name)] \\(.context_window.used_percentage // 0)% context\"'",
    "padding": 2
  }
}

Прибрати підпис Claude із комітів

Щоб підпису не лишилось узагалі, потрібні всі три поля: порожній commit, порожній pr і sessionUrl: false. Старий ключ includeCoAuthoredBy усе ще читається, але щойно ти задаси attribution.commit або attribution.pr — він ігнорується. 

{
  "attribution": {
    "commit": "",
    "pr": "",
    "sessionUrl": false
  }

Чого в цьому переліку немає

Сторінка перелічує ключі settings.json — і тільки їх. Поруч живуть чотири інші набори налаштувань, які теж міняють поведінку Claude Code, але пишуться деінде:

ЩоДеКуди дивитись
змінні середовища в оболонці або в ключі env цих же файлів довідник змінних середовища. Через env будь-яку з них можна застосувати до всіх сесій або розкотити на команду
події перехоплювачів усередині ключа hooks сам ключ є в розділі про автоматизацію, а повна таблиця всіх подій — окремий довідник цього курсу
слеш-команди й гарячі клавіші ніде — вони вбудовані окремий довідник цього курсу
решта ~/.claude.json той самий файл, але поза шістьма ключами з останнього розділу там лежить твоя сесія входу, конфігурації серверів MCP і стан кожного проєкту (зокрема рішення про довіру до теки). Claude Code пише цей файл для себе — правити його руками не треба

Окремо: CLAUDE.md, .mcp.json, SKILL.md навичок і файли субагентів — це не налаштування, а вміст, який Claude Code читає. Ключі тут лише вмикають і вимикають їх.

  • Файли, порядок перекриття, поведінка зламаного файла й сім винятків — сторінка Claude Code settings, той самий день.
  • Прив'язка шляхів у правилах дозволів — сторінка Permissions, той самий день.
  • Дві пари ключів MCP — сторінка MCP, розділ «Disable a server without removing it».
  • Перевірка ключів у бінарнику — запущено на macOS 26.5.2, zsh 5.9, Claude Code 2.1.236, 4 вересня 2026. Версія в каналі latest того ж дня — 2.1.260.

Переклад описів — наш; формулювання документації скорочені до одного речення. Там, де точне слово має значення (назви значень, шляхи, підстановки), воно лишене англійською як є, бо саме так його треба писати у файлі.
