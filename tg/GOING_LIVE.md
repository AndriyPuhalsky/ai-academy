# Запуск наживо: хостинг і домен (Cloudflare Pages + GitHub)

Доповнення до `DEPLOY_CHECKLIST.md` (той — про Supabase, файли й smoke-тест).
Цей — конкретно про **хостинг, домен і авто-деплой**. Рекомендований стек:
Cloudflare Pages (хостинг) + Cloudflare Registrar (домен) + GitHub (авто-деплой).

> Інтерфейси час від часу змінюються — назви кнопок звіряй у поточних доксах Cloudflare.

---

## 0. Передумови
- [ ] Акаунт GitHub (безкоштовний) і встановлений `git` (Модуль 5 курсу — якщо треба нагадати).
- [ ] Акаунт Cloudflare (безкоштовний).
- [ ] Проєкт готовий локально (усі файли цієї сесії розкладені за структурою).
- [ ] `config.json` у корені з РЕАЛЬНИМИ supabase `url`+`anonKey`.

---

## 1. Код → GitHub
```bash
cd /шлях/до/проєкту
git init
git add .
git commit -m "AI Академія — продакшн"
# створи приватний репозиторій на github.com (напр. ai-academy), тоді:
git remote add origin https://github.com/ТВІЙ_ЛОГІН/ai-academy.git
git branch -M main
git push -u origin main
```
- [ ] Переконайся, що `.env` НЕ потрапив у репозиторій (його тут і не має бути — креди в `config.json` через `anonKey`, що публічний).

---

## 2. Cloudflare Pages → підключити репозиторій
1. [ ] Cloudflare Dashboard → Workers & Pages → Create → Pages → Connect to Git.
2. [ ] Авторизуй GitHub, обери репозиторій `ai-academy`.
3. [ ] Налаштування збірки:
   - **Framework preset:** None
   - **Build command:** *(порожнє — у нас статика, збірки немає)*
   - **Build output directory:** `/` *(корінь репозиторію)*
4. [ ] Save and Deploy. За хвилину отримаєш живу адресу виду `ai-academy.pages.dev`.
5. [ ] Відкрий `*.pages.dev` — сайт має працювати (вхід, курси). Якщо так — хостинг готовий.

> Далі кожен `git push` у `main` САМ оновлює сайт (Cloudflare пересоберe й опублікує).
> Альтернатива без Git: Pages → Direct Upload (перетягнути папку). Але GitHub зручніше.

---

## 3. Купити домен (Cloudflare Registrar)
1. [ ] Cloudflare Dashboard → Domain Registration → Register Domains.
2. [ ] Знайди вільну назву (придумай 2–3 варіанти). `.com` ≈ $10/рік за собівартістю.
3. [ ] Купи — домен одразу в твоєму акаунті, DNS уже тут.

> Хочеш українську зону (`.com.ua`, `.in.ua`, `.ua`)? Cloudflare Registrar їх зазвичай НЕ продає —
> бери в українського реєстратора (напр. imena.ua, ukraine.com.ua), а потім або переведи NS на
> Cloudflare, або просто додай CNAME на `*.pages.dev` у того ж реєстратора (див. крок 4, варіант Б).

---

## 4. Під'єднати домен до сайту
**Варіант А (домен у Cloudflare — найпростіше):**
1. [ ] Workers & Pages → твій проєкт → Custom domains → Set up a custom domain.
2. [ ] Введи домен (і за бажання `www`). Cloudflare сам додасть потрібні DNS-записи й видасть SSL.
3. [ ] За кілька хвилин домен веде на сайт (HTTPS автоматично).

**Варіант Б (домен в іншого реєстратора):**
1. [ ] У DNS реєстратора додай CNAME: `@`/`www` → `ai-academy.pages.dev`.
2. [ ] У Pages → Custom domains додай свій домен; дочекайся валідації.

---

## 5. Supabase для проду
- [ ] Прогнати міграції за `DEPLOY_CHECKLIST.md` (схема → rebuild → certificate_progress → telegram).
- [ ] Supabase → Authentication → URL Configuration → **Site URL** = `https://твій-домен`
      (і додай його в Redirect URLs). Це потрібно для коректних листів підтвердження пошти.
- [ ] `config.json` уже містить реальні `url`+`anonKey` — нічого більше для входу не треба
      (auth читає кореневий `config.json` для всіх курсів).
- [ ] Telegram-бот лишається як є (його викликає Telegram, не браузер — CORS не потрібен).
- [ ] Сертифікат: QR будується відносно живої адреси, тож на домені перевірка працює автоматично.

---

## 6. Перевірка наживо
- [ ] Відкрий `https://твій-домен` — сайт вантажиться, є «Увійти».
- [ ] Smoke-тест із `DEPLOY_CHECKLIST.md` (вхід один раз на обох курсах, прогрес `X/12` і `X/22`,
      квізи, сертифікат, кнопки бота, сповіщення про реєстрацію).
- [ ] Зроби тестовий `git push` (дрібна зміна) → переконайся, що сайт сам оновився.

## Оновлення сайту (після запуску)
Зміни локально → `git add . && git commit -m "опис" && git push`.
Cloudflare Pages автоматично пересоберe й опублікує за ~хвилину. Відкат — на попередній deploy у панелі Pages.

---

## Другий проєкт у майбутньому
- Той самий акаунт Cloudflare тримає скільки завгодно проєктів Pages (кожен — окремий сайт/домен), безкоштовно.
- Якщо другому проєкту потрібна база — окремий проєкт Supabase (free tier дозволяє кілька активних на організацію).
- Власний сервер (напр. FastAPI) — ось тоді Docker/VPS; для статики + Supabase він не потрібен.
