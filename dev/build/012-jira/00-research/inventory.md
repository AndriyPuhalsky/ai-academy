# Інвентар сторінок і компонентів курсу «Jira з нуля» — щоб білд не знайшов нічого «відсутнього»

**Складено кореневою сесією 2026-09-17** за уроком 005: тоді дизайн намалював hero, компонент і
лендінг, а сторінку уроку, довідники, пілюлю прогресу й бренд сертифіката білд «дознаходив» сам.
Тут — **усе, що побачить користувач**, з позначкою, хто це робить і чи потрібен макет. Правило
приймання дизайну №11 (бриф): **кожен рядок зі станом «новий» або «є, потребує стану/значення»
має макет або явну позначку дизайн-сесії «є в 009, без змін»**.

Стани: **є** — компонент системи 009, використовується як є · **є, потребує стану/значення** —
компонент є, але для 012 потрібен новий стан, значення або дані · **новий** — у системі немає,
потрібен макет · **дані** — лише вміст/конфіг, без макета.

## В. Що дизайн має віддати (перелік для `SUMMARY.md` і `handoff/`)
1. Акцент `jira`: 4 примітиви + блок слота (5 імен) + монограма й капс для медальйона.
2. Компонент «вікно»: CSS для шести станів і всіх варіантів з таблиці вище, токени `--win-*`,
   реєстр §7.0, поведінка на 390 px (рейка ховається, дошка прокручується всередині з підказкою
   §41), стан без міток, `prefers-reduced-motion` для hero-версії.
3. Лендінг `jira.html`: hero (анімація ≤ 6 с + reduced-motion фінальний кадр), карта 23, полиця,
   блок автора, дисклеймер у футері, «для кого», результати, форма уроку, сертифікат.
4. Сторінка уроку з вікнами в контексті — на реальному `modules/jira-03.html` (три вікна різних
   станів) або `jira-01.html`.
5. Довідник 3 — підтвердити, що шаблону `-ref-commands` вистачає, або домалювати блок «карта
   інтерфейсу» з вікнами без міток.
6. Явні позначки «є в 009, без змін» для всього, що не малюється, — щоб білд не гадав.
