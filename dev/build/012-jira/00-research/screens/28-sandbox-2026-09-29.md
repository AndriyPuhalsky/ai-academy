Запити подано помічнику **українською, дослівно з `term`-блоків уроку**; жоден не вимагав уточнення.

| Сценарій | Запит (дослівно з уроку) | Що зробив помічник | Результат |

## 2. `WEB-3` після створення (MCP `getJiraIssue`, `view: full`)

| Поле | Значення | Для уроку |
| --- | --- | --- |
| `key` | `WEB-3` | звичайний ключ, без позначки ✓ |
| `issuetype` | `Task`, `hierarchyLevel: 0` | звичайний тип, «машинного» немає ✓ |
| `reporter` | «Користувач Jira», `accountType: atlassian` | **власний акаунт того, хто підключив сервер** — ⚠ №2 j22 закривається ✓ |
| `creator` | той самий акаунт, `accountType: atlassian` | те саме |
| `assignee` | `null` | 🔴 **порожньо** — запит виконавця не називав; вікно W1 j22 каже «Денис Романюк». Порожній виконавець на екрані картки — «Unassigned · Assign to me» (`screens/06`) |
| `priority` | `Medium` | ✓ (вікно вже виправлене хвилею 7) |
| `duedate` | `2026-09-25` | ✓ |
| `description`, `comment` | порожні | запит їх не задавав — у W1 опис і коментар мусять бути поясненими як додані людиною |
| `changelog` | `total: 0` | API-історія починається з першої правки, не зі створення; рядок «created» вкладки `History` — лише через браузер |

Для порівняння «людина / Automation for Jira»: у `HR-2` (перехід на `Interview` з правилом workflow `Assign a work item`,
2026-09-28) автор усіх трьох записів історії — той самий акаунт, `accountType: atlassian`; правило workflow пише в історію від
імені того, хто зробив перехід. Записів від Automation for Jira на sandbox поки немає (flows не запускались) — порівняння
з уроком 14 наживо не зроблене.

Опис інструмента історії в самому MCP-сервері (не довідка Atlassian, лише орієнтир): «Do not infer automation from
author.accountType — a script running under a person's token reads "atlassian".»

## 3. Крос-продуктовий запит на Free (⚠ №3 j22, `facts-free-plan.md` №14b)

| --- | --- |

підсумуй») сервер **відмовляє з 403**. Confluence: `getAccessibleAtlassianResources` показує `confluence` у продуктах, але
API Confluence віддає 404 — **Confluence на sandbox не працює** (відповідь на питання журналу 2026-09-29).

## 5. Типи робіт і рівні ієрархії (MCP `listJiraProjectIssueTypesMetadata` + `hierarchyLevel` з карток)

| Спейс | Типи (дослівно) |
| --- | --- |
| `REM` | Workstream · Task · Sub-task |
| `HR` | Workstream · Task · Sub-task |
| `MARK` | Campaign · Task · Sub-task |
| `MY` | Task · Sub-task |

Рівні: `Workstream` і `Campaign` — `hierarchyLevel: 1` (довідка про цей рівень: «level 1, by default called Epic»; сам
Epic на sandbox не заміряно — робіт цього типу немає); `Task` — `0`; `Sub-task` — `-1`. Описи
типів (дослівно): Workstream — «Workstreams track a set of related work and activities that work towards a larger
deliverable.» · Campaign — «Campaigns are coordinated and strategic series of tasks designed to achieve a measurable goal.»
· Sub-task — «A small piece of work that's part of a larger task.» `REM-2` (Task) має `parent = REM-1` (Workstream).

Закриває частину `open-claims.md` §11 №3 (які типи є) і №6 (тип зветься `Sub-task`); сама сторінка `Work types`, кнопка
`Add work type` і назва секції підзадач на картці — лише браузером.
