## 2. Читач і результат курсу

### Хто читає
Людина **не з ІТ**, яка чула слово «Jira» як щось для програмістів: маркетолог, бухгалтер,
виконроб, HR, власник кав'ярні, або людина, що хоче навести лад у власних справах. Команда —
до десяти людей або одна людина. Не знає, що таке «беклог», «спринт», «JQL», і не мусить.
Читає лінійно один раз; повертається до довідників.

### Для кого це (лендінг, `audience.for`)
1. Ти ведеш справи команди в чатах, таблицях і на стікерах — і щось постійно губиться
2. Ти чув(ла), що Jira — «складна штука для айтішників», і хочеш перевірити це сам(а)
3. У тебе до десяти людей — або ти один(одна) — і платити за інструмент не хочеться
4. Тобі потрібно, щоб колеги подавали заявки (рахунки, довідки, закупівлі) в одне місце, а не в особисті
5. Ти готовий(а) один раз розібратись, як воно влаштоване, замість тикати навмання

### Для кого ні (`audience.not`)
1. Тобі потрібні схеми дозволів, журнал аудиту чи портфельне планування — це платні плани, курс їх не вчить
2. Ти шукаєш курс про Scrum для dev-команди — тут Scrum лише оглядово
3. Тобі потрібна Jira Data Center / Server — курс лише про Cloud
4. Ти чекаєш, що Jira сама наведе лад — вона лише тримає те, що ти в неї поклав

### Результати (`outcomes.items`, шість, дієсловами)
| text | hint |
| ---- | ---- |
| Завести сайт і спейс для своєї команди за вечір | І назвати сайт так, щоб не пошкодувати: на безкоштовному плані назву потім не змінити. |
| Вести роботу картками: створювати, призначати, коментувати, закривати | І бачити ту саму роботу як дошку, список, календар і таймлайн — без дублювання. |
| Знаходити будь-що одним запитом | Мовою запитів JQL: «мої прострочені», «без виконавця», «за тиждень» — і зберігати як фільтр. |
| Налаштувати спейс під свою сферу | Свої статуси, свої поля, свої типи роботи — і знати, коли «менше полів» краще. |
| Доручити рутину автоматизації | Нагадування, авто-призначення, «усі підзадачі готові → задача готова» — без програмування. |
| Приймати заявки від колег через портал | Бухгалтерія, HR чи господарка отримують заявки в чергу з термінами, а не в особисті повідомлення. |

## 5. Форма уроку — вісім блоків (успадковано з 005, крок 2 змінено)

1. **Навіщо це** · 2. **Як це виглядає на екрані** (**вікно застосунку**, не термінал) · 3. **Як це
працює** (Mermaid) · 4. **Зроби сам** (кроки словами, у сюжеті) · 5. **Як перевірити, що вийшло** ·
6. **Типові граблі** · 7. **Часті питання** · 8. **Підсумок і наступний крок** · + квіз 6 питань.
Норма: **1–5 вікон** на урок, **≥ 1 Mermaid**, JQL і smart values — у `term` з кнопкою «Копіювати».

Нижче — таблиці фаз у форматі 005 (`код | назва | слаг | що всередині`) і **картка кожного уроку**.
Поле «Теми» картки = колонка «що всередині»: **усе назване мусить прозвучати** (правило автора №3).
`⚠` у картці — факт або екран, який автор перевіряє наживо перед написанням.

**Обов'язково в `j01`:** урок існує, бо головне упередження аудиторії — «Jira для програмістів».
Перше вікно курсу — дошка `MARK` з людськими назвами карток, не `PROJ-4213`.
**Обов'язково в `j02` — інакше курс бреше:** межа Free названа до того, як людина створила сайт.
**Чому `j03` і `j04` окремо:** `j03` — руки (акаунт, сайт, де що на екрані), `j04` — голова (словник);
разом вони перевантажують новачка, а словник потрібен усім наступним урокам як довідка.

#### j01 · Jira не лише для ІТ
- **Результат:** людина розуміє, яку задачу Jira закриває для *її* сфери, і може пояснити колезі
  різницю Jira / JSM / Confluence / Trello одним реченням кожну.
- **Теми (мусять прозвучати):** справи губляться в чатах і таблицях → одне місце з картками;
  дошка = колонки-етапи, картка = справа; для кого Jira (команда до десяти, будь-яка сфера),
  для кого ні (потрібні дозволи/аудит → платні плани; Server/DC); сімейство: **Jira** (робота
  командою), **Jira Service Management** (заявки від інших людей через портал), **Confluence**
  (документи й база знань), **Trello** (простіші дошки без workflow/JQL); що курс покриє
  (Cloud, Free, англійський UI з українськими поясненнями) і чого ні (Scrum глибоко, Server).
- **Вікна (2):** W1 `board` — «Jira Cloud · дошка спейсу Маркетинг · звірено 2026-09-DD»: три

#### j04 · Словник Jira
- **Результат:** людина називає кожен елемент картки й дошки правильним словом і розуміє
  ієрархію Epic → Task → Subtask.
- **Теми:** **space (project)** — контейнер; **work item (issue)** — одиниця роботи; **work type
  (issue type)**: Epic, Task, Subtask (у software ще Story, Bug); **ключ** `REM-2` = ключ спейсу
  + номер, не змінюється при перейменуванні; **summary** / **description**; **status** і
  **категорія статусу** (To Do / In Progress / Done — три кольори); **assignee** (один) /
  **reporter** (автор); **priority**; **labels** (вільні слова, свої в кожного спейсу);
  **due date** / **start date**; **parent** і ієрархія; **comments**, **attachments**,
  **linked work items** (blocks / relates to), **watchers** (око), **@-згадки**; **Your work /
  For you**; components — лише company-managed, згадка в ЧаПи.
- **Вікна (3):** W1 `item` — «Jira Cloud · картка `REM-2` «Електрика: погодити кошторис» ·
  звірено …»: заголовок, статус In Progress, права панель Details (Assignee ТМ, Parent `REM-1`,
  Priority High, Labels `електрика`, Due date, Reporter ОК), опис, Subtasks (`REM-3`), Linked
  work items, Activity → Comments; мітки ①…⑧ на полях + легенда. W2 `board` — анатомія
  картки на дошці `REM`: назва, дедлайн, іконка типу + ключ, аватар; мітки ①…④. W3 `list` —
  список `REM`: колонки Work · Assignee · Reporter · Priority · Status · Due date = ті самі поля
  в таблиці; мітки: ① одна колонка = одне поле.
- **Mermaid:** `flowchart TB` — «site → space → work item → поля» + друга гілка ієрархії
  `REM-1` Epic → `REM-2` Task → `REM-3` Subtask.
- **Зроби сам:** відкрий будь-яку картку у своєму `MY` (створи одну, якщо порожньо — назва
  «Замовити борошно на тиждень»); знайди на екрані вісім полів із легенди W1; додай собі мітку
  `тест` і зніми її.
- **Як перевірити:** ти можеш показати пальцем ключ, статус, автора й виконавця на одній картці.
- **Граблі:** статус ≠ категорія (двадцять статусів, три категорії); reporter ≠ assignee;
  «Done» ≠ видалено; мітки з різним регістром — різні мітки; Epic — не папка, а батько.
- **Квіз — 6 тем:** з чого складається ключ; статус vs категорія; assignee vs reporter; що таке
  watcher; labels vs components; що таке parent.
- **Джерела:** `support.atlassian.com/jira-software-cloud/docs/` (розділи «What are work items»,
  «Work types», «Fields»; ⚠ слаги досі з `issue`), `screens/06-work-item.md`, `03-board.md`, `04-list.md`.
- **Стабільність:** 🟡 — терміни перейменовували двічі за два роки; при кожному релізі звірити
  пари «поточне (колишнє)» у легендах.
- **Межа:** не вчити створювати й вести (`j05`), не пояснювати workflow (`j10`).

#### j07 · Пошук і JQL
- **Результат:** людина пише запит «мої прострочені в цьому спейсі», зберігає його як фільтр і
  підписується на нього.
- **Теми:** поле Search у верхній панелі (швидкий пошук) → сторінка **All work** · перемикач
  **Basic / JQL** · граматика **`поле оператор значення`** · оператори `=`, `!=`, `~` (містить),
  `>`, `<`, `IN`, `IS EMPTY` · `AND` / `OR` / `NOT`, дужки · `ORDER BY … ASC|DESC` · функції
  `currentUser()`, `now()`, `startOfDay()`, `startOfWeek()`, `endOfMonth()` · відносні дати
  `-7d`, `2w` · **`project`** у JQL — досі старе слово; `status` — назва як рядок і залежить від
  мови/спейсу, надійніше **`statusCategory`** · **Save filter** (назва, опис, доступ) · сторінка
  **Filters** · **підписка** на фільтр (лист за розкладом) · **share** (група / спейс / усі
  залогінені; публічно — вимкнено адміністратором за замовчуванням) · **bulk change** з
  результатів пошуку (ліміт — довідник 3) · «Fix error» і підказка синтаксису.
- **Вікна (3):** W1 `list` — «Jira Cloud · All work, режим JQL · звірено …»: рядок Basic/JQL,
  запит `project = MARK AND statusCategory != Done ORDER BY due ASC`, результати; мітки:
  ① перемикач Basic/JQL, ② поле запиту, ③ Save filter, ④ результати = той самий список. W2 `list`
  (варіант «помилка») — той самий екран із червоною рамкою «JQL error: The value 'Done' does not
  exist for the field 'status'» і кнопкою Fix error; мітки: ① текст помилки, ② Fix error.
  W3 `form` — діалог Save filter: Name «Мої на цьому тижні», Description, Access; мітки: ① назва,
  ② доступ.
- **`term`-блоки (з кнопкою Копіювати), 8 запитів сюжету:** `assignee = currentUser() AND
  statusCategory != Done` · `due <= endOfWeek() AND statusCategory != Done` · `due < now() AND
  statusCategory != Done` (прострочені) · `assignee IS EMPTY AND project = MARK` · `labels =
  дозволи` · `summary ~ "круасан"` · `project IN (MARK, REM) AND updated >= -7d ORDER BY updated
  DESC` · `reporter = currentUser() AND created >= startOfMonth()`.
- **Mermaid:** `flowchart LR` — «запит = поле → оператор → значення; блоки з'єднує AND/OR;
  наприкінці ORDER BY».
- **Зроби сам:** створи й збережи три фільтри: «Мої на цьому тижні», «Прострочені (усі спейси)»,
  «Без виконавця»; підпишись на «Прострочені» щопонеділка; поділись «Без виконавця» з усіма
  залогіненими.
- **Як перевірити:** сторінка Filters показує три фільтри; «Прострочені» повертає рівно ті
  картки, у яких дедлайн у минулому й статус не Done.
- **Граблі:** `status = Done` не знаходить нічого, бо статус названо інакше → `statusCategory`;
  `=` проти `~`; `ORDER BY` лише в кінці; Basic-режим «з'їдає» складний запит; збережений
  фільтр приватний, тому дашборд колеги порожній; лапки навколо значень із пробілами.
- **Квіз — 6 тем:** структура запиту; статус vs statusCategory; що робить `currentUser()`;
  де зберігається фільтр; навіщо share; що таке підписка.
- **Джерела:** `support.atlassian.com/jira-software-cloud/docs/` (розділ «JQL»: «Use advanced
  search with Jira Query Language», «JQL fields», «JQL operators», «JQL functions», «Save your
  search as a filter»), `…/edit-multiple-issues/` (bulk, `facts-free-plan.md` №7); `screens/15`, `16`.
- **Стабільність:** 🟢 — JQL не змінювався роками; після релізу звірити лише вікна.
- **Межа:** JQL у flows — `j15`; вичерпні таблиці полів/функцій — довідник 1, в урок не тягнути.

#### j09 · Team-managed vs company-managed

#### j13 · Scrum і Kanban — і коли вони не потрібні
- **Результат:** людина розуміє два методи оглядово, ставить WIP-ліміт на дошці `WEB` і чесно
  вирішує, чи потрібні їй спринти (найчастіше — ні).
- **Теми (оглядово, рішення власника):** **Kanban** — безперервний потік: колонки-етапи,
  **ліміт колонки** (Column limit / WIP): не більше N карток «у роботі», підсвічування при
  перевищенні · **Scrum** — робота порціями часу: **беклог** (упорядкована черга), **спринт**
  (1–4 тижні), планування → робота → огляд; **Sprints** як фіча спейсу (Features → Sprints,
  «Requires a backlog»); **Estimation** (story points або час) · звіти software-спейсу оглядово:
  burndown (скільки лишилось у спринті), velocity (скільки команда робить за спринт),
  cumulative flow (де накопичуються картки) · коли **не потрібно**: кав'ярні не треба спринтів —
  треба потік і дедлайни; Scrum виправданий для команди, що постачає порціями (сайт `WEB`) ·
  один крок руками: **ліміт колонки** In Progress на `WEB`.
- **Вікна (3):** W1 `board` — дошка `WEB` (Kanban): колонки To Do · In Progress (**Max 3**, три
  картки, підсвічена) · Done; мітки: ① ліміт колонки, ② підсвічування перевищення, ③ картка Bug
  `WEB-2`. W2 `list` (варіант «Backlog») — вигляд Backlog: секція «Sprint 1» (порожня, кнопка
  Start sprint) і секція Backlog з картками ⚠ зняти після увімкнення Sprints у sandbox; мітки:
  ① спринт, ② беклог, ③ Start sprint. W3 `settings` — Features: Sprints, Estimation, Standups in
  Jira з перемикачами; мітки: ① Sprints «Requires a backlog», ② Estimation.
- **Mermaid:** `flowchart LR` — два потоки поруч: Kanban (безперервно) і Scrum (цикл спринту).
- **Зроби сам:** створи `WEB` «Сайт» як team-managed software (Kanban); у налаштуваннях дошки
  постав ліміт In Progress = 3 ⚠ шлях; створи 4 картки і переведи 4 в In Progress — подивись
  підсвічування; **спринт не запускай** — лише відкрий Features і прочитай опис Sprints.
- **Як перевірити:** колонка In Progress підсвічена при 4 картках; Features показує Sprints
  вимкненим.
- **Граблі:** «Kanban-шаблон» без лімітів — просто дошка; спринти в команді з двох людей —
  ритуал без користі; velocity на трьох картках нічого не означає; увімкнені Sprints додають
  Backlog і плутають, де картки.
- **Квіз — 6 тем:** що робить WIP-ліміт; спринт vs потік; що потрібно для Sprints; що показує
  burndown; коли Scrum не треба; де вмикаються фічі.
- **Джерела:** `support.atlassian.com/jira-software-cloud/docs/` («Set column limits» ⚠ слаг,
  «Enable sprints in team-managed», «Backlog», «Reports overview»), `atlassian.com/agile`
  (Kanban, Scrum — огляд); `screens/03`, `08`, `10`.
- **Стабільність:** 🟢 — методи стабільні; звірити лише шлях до ліміту колонки.
- **Межа:** не вчити Scrum практично (рішення власника); дашборди — `j08`.

#### j18 · Jira Service Management
- **Результат:** людина розуміє, чим сервіс-спейс відрізняється від звичайного, і що колеги
  подають заявки без місця в Jira.
- **Теми:** **JSM** — окремий продукт на тому ж сайті (додає власник сайту) · **сервіс-спейс**:

  поля форми, група порталу · **черга** (queue) — список запитів за JQL для агентів · **SLA** —
  «відповісти за N годин», робочий календар, зупинка при «Waiting for customer» · **канали**:
  портал, **пошта** (у сервіс-спейсу є своя адреса ⚠ на Free — звірити), віджет — оглядово ·

  Facilities, Legal, **Finance**, General ⚠ назви · **портал може бути українською** (мова
  Customer Portal у списку локалізованих; Jira-UI агента — англійський) ⚠ звірити очима ·

  аванс» · «Замовити довідку» · «Закупівля», лінк «Requests»; мітки: ① тип запиту, ② пошук по
  базі знань, ③ мої заявки. W2 `list` (варіант «черги») — рейка черг «Всі відкриті · Нові ·
  Мої · SLA горить», таблиця Key · Summary · Reporter · Status · Time to first response; мітки:

  запиту, SLA-панель, поле відповіді з перемикачем **Reply to customer / Add internal note**;

#### j19 · Практикум: заявки до бухгалтерії
- **Результат:** портал `FIN` приймає чотири типи заявок, у черзі видно SLA, Ігор отримує
  призначення автоматично, Соломія — лист про результат.
- **Теми (12 кроків):** (1) типи запитів: Подати рахунок · Заявка на аванс · Замовити довідку ·
  Закупівля ↔ типи роботи · (2) **форма** кожного типу: поля (Сума, Постачальник, Дата, Вкладення)
  ⚠ Forms на Free — перевірити, інакше поля запиту · (3) групи порталу (Гроші · Документи) ·
  (4) **черги**: «Нові» (`status = Open`), «Мої» (`assignee = currentUser()`), «SLA горить»
  (⚠ JQL для SLA) · (5) **SLA** «Time to first response: 1 робочий день», календар Пн–Пт 9–18,
  пауза в Waiting for customer · (6) **flows**: created + тип запиту → Assign Ігор; transitioned

#### j22 · Jira + Claude Code через MCP
- **Результат:** людина підключила Jira до Claude Code, знайшла свої прострочені справи
  запитом українською й створила три картки зі списку — з підтвердженням кожного запису.
- **Теми:** **MCP** — стандартний «розʼєм» між помічником і застосунком (місток: урок
  `claude-code-18` курсу «AI Термінал» — там про MCP загалом) · **Rovo MCP Server** Atlassian:
  хмарний, доступний усім Cloud-сайтам, **включно з Free**; ліміт викликів на годину — довідник 3
  · підключення з Claude Code: `claude mcp add --transport http atlassian https://mcp.atlassian.com/v2/mcp`
  ⚠ endpoint розходиться між двома сторінками Atlassian (`/v2/mcp` vs `/v1/mcp/authv2`) —
  перевірити наживо перед публікацією · **OAuth-згода** в браузері: обрати сайт, дозволити
  доступ; `/mcp` у Claude Code показує стан · що вміє (інструменти сервера ⚠ назви з
  developer.atlassian.com): пошук за JQL, отримати роботу, створити, оновити, коментувати,
  список спейсів; Confluence — сторінки · **три сценарії**: (1) «покажи мої прострочені в
  MARK» → JQL з `j07` під капотом; (2) «підсумуй, що зробили за тиждень у REM» → читання +
  текст; (3) «створи три задачі зі списку: …» → запис із підтвердженням · **безпека**: спершу
  читання; кожен запис — підтвердження; токен/сесія — особисті; ліміт викликів; не давати
  помічнику «зроби все» · **Rovo в UI** (Ask AI, Improve Task, Add agent) — на Free апсел; **MCP —
  інший шлях** · ризик: якщо MCP на Free упреться в ліміт кредитів Rovo — REST API з API-токеном
  як запасний шлях (лише згадка) ⚠ · **куди далі**: Atlassian Community, Atlassian Learning
  (безкоштовні курси й бейджі), сертифікація ACP — платна; Community Champion — хто це.
- **Вікна (2) + `term`-блоки:** W1 `form` — OAuth-згода Atlassian «Allow access to your
  Atlassian account»: сайт, перелік дозволів, Accept ⚠ зняти при підключенні (домен
  `id.atlassian.com` — перевірити дозволи розширення); мітки: ① сайт, ② дозволи, ③ Accept.
  W2 `item` — картка `WEB-3` «Оновити ціни на сайті» з коментарем «Створено через Claude Code
  за списком від Оксани» і reporter = власник; мітки: ① reporter — людина, а не «Automation»,
  ② коментар як слід. `term` (за контрактом 005, з Копіювати): `claude mcp add --transport http
  atlassian https://mcp.atlassian.com/v2/mcp` · `/mcp` (вивід стану) · діалог: запит
  українською → виклик інструмента → підтвердження → результат (зняти з реального запуску).
- **Mermaid:** `sequenceDiagram` — Claude Code → MCP-сервер Atlassian → Jira Cloud (OAuth,
  запит, відповідь, підтвердження запису).
- **Зроби сам:** підключи MCP, пройди OAuth; запит (1); запит (3) з трьома реальними справами;
  перевір у Jira.
- **Як перевірити:** `/mcp` показує atlassian підключеним; три нові картки з тобою як reporter;
  жодного запису без твого «так».
- **Граблі:** підключено не до того сайту (кілька акаунтів у браузері — як у sandbox 2026-09-17);
  помічник «покращив» назви без прохання; ліміт викликів на годину; кнопка Ask AI в Jira — це не
  MCP; endpoint зі старої статті.
- **Квіз — 6 тем:** що таке MCP; чи є на Free; що дає OAuth-згода; читання vs запис; чому Ask AI
  ≠ MCP; куди далі вчитись.
- **Джерела:** `developer.atlassian.com/cloud/rovo-mcp/` (getting started, tools), `support.atlassian.com/rovo/docs/`
  («Getting started with the Atlassian Remote MCP Server», «Rovo usage limits» — `facts` №14,
  14b), `atlassian.com/platform/remote-mcp-server`, `modules/claude-code-18.html` (місток),
  `code.claude.com/docs/en/mcp` (Claude Code MCP); `community.atlassian.com/learning`.
- **Стабільність:** 🔴 — MCP, кредити, endpoint; після кожного релізу перезапускати «Зроби сам».
- **Межа:** не вчити Claude Code (курс «AI Термінал»); не вчити REST API (v2).

## Наскрізні правила авторингу

1. **Версія біля кожного вікна:** датований заголовок «Jira Cloud · … · звірено РРРР-ММ-ДД»; дата
   = день, коли автор бачив екран у sandbox або знімок у `screens/`. Вікно «за документацією»
   позначається так у заголовку.
2. **Жодного вигаданого екрана.** Напис у вікні — той, що є в `screens/` або на живому екрані
   sandbox (через кореневу сесію). Немає знімка — описати словами й позначити ⚠ у звіті.
3. **Скелет уроку — вісім блоків** (розділ 5), порядок незмінний; квіз `id="quiz"` дев'ятий.
4. **1–5 вікон на урок, іспит — 0**; мітки ①②③ (`aria-hidden`) завжди з легендою `<ol>`; вікно
   без міток валідне.
5. **Мінімум одна Mermaid-діаграма**; workflow — тільки `stateDiagram-v2`; текст вузлів у лапках;
   `<br/>` у розмітці не вживати (пастка 010).
6. **JQL і smart values — у `term` з кнопкою «Копіювати»**; копіюється лише `.term__in`; один
   запит = один блок.
7. **Термінологія:** перша згадка в курсі — «поточне (колишнє)»: work item (issue), space
   (project), work type (issue type), flow (automation rule); далі — поточне. У JQL/URL/smart
   values старі слова лишаються і пояснюються один раз (`j04`, `j07`, `j14`).
8. **Числа лімітів — лише довідник 3** з датою; в уроках — «обмежено, дивись довідник 3».
   Винятки: 10 користувачів Jira Free, 3 агенти JSM Free.
9. **Англійський UI, українське пояснення**; у вікнах — EN-написи як на екрані; у легендах — UA.
10. **Посилання — на розділи** `support.atlassian.com/<product>/docs/` (слаги застарівають);
    суть дублюється в уроці. Сторінки планів — дві названі в `facts-free-plan.md`.
11. **Sandbox: пастка мови.** Спейси в sandbox створювати з мовою акаунта **English**, інакше
    статуси народжуються російськими/українськими і ламають JQL у вікнах.
12. **Апсели Free не описувати як функції:** See plans, Ask AI, Improve Task, Add agent, Try
    Confluence now — називати тим, чим вони є.
13. **Квіз — 6 питань**, іспит — 26; `explain` без «перший/третій варіант» (`js/quiz.js` тасує);
    довжина варіантів не підказує (007); ситуаційні питання, не «скільки».
14. **Один агент — одна сторінка; git не виконує; звіт `.md` у `01-authoring/reports/`**
    (джерела, що описано словами, чого не знайшов, розбіжності, знахідки сусідам).

## Уточнення до карток після хвилі 2 (j04–j10, ніч 2026-09-17 → 18) — джерела у `reports/jNN.md`

Картки вище не переписувались; ці рядки мають пріоритет над карткою, якщо розходяться. Рецензентам і
наступним авторам — читати разом із карткою.

1. **j04 · Мітки.** «Мітки з різним регістром — різні» — джерела немає, в урок не пішло. «Labels — свої в кожного
   спейсу» — докси кажуть «Labels are global» (уточнення про company-managed), про team-managed мовчать; в уроці
   не стверджується ні те, ні інше. Закривається А/Б у sandbox. «Виконавець рівно один» — без прямої цитати.
2. **j04/j05 · `Summary` → `Title`.** Докси попереду екрана (open beta); писати `Summary`, як на екрані, обидва слова
   назвати. Пара `work type (issue type)` введена в j04.
3. **j05 · «Зроби сам».** Крок «познач картку зіркою» замінено на «напиши коментар»: вкладка `Starred` показує спейси,
   не роботи. «Action items не шукаються JQL» — джерела немає, лише доведене (чекбокс без ключа/статусу/дошки).
4. **j06 · Таймлайн.** «Залежності/capacity — платні» в урок не взято: `Dependency management` у таблиці планів —
   порожній рядок у всіх колонках; доведене — `Roadmaps: Basic` на Free, «A timeline can only show work items
   from one space». `REM-4` не вжитий (REM зʼявляється лише після j09).
5. **j07 · JQL.** Дати в лапках: `updated >= "-7d"`. Поле спейсу — **`project`** (живий екран), докси вже пишуть
   `space` з банером «try using the old term instead». **`MARK-4` у картці «due this week» суперечить j01, де
   `MARK-4` у `Done`** — у W1 стоять `MARK-1`, `MARK-6`, `MARK-7`. W3 — панель `Details` фільтра, не діалог
   «Save filter» (у діалозі лише назва + `Submit`).
6. **j08 · Публічний доступ.** Не «вимкнено за замовчуванням», а **«Free Jira sites can't be opened to the
   public»** — на Free його немає. Вікно W2 картки (налаштування гаджета) замінене на діалог `Create dashboard`:
   назв полів панелей гаджетів у Cloud-доксах немає. Крок «зроби домашнім» → `Add to starred` (поля `Jira
   homepage` в доксах немає).
7. **j09 · Типи спейсів.** «Business-спейси — team-managed за природою» — **не так**: адмін створює спейс з
   будь-якого шаблону як company-managed; дві частини `Type` майже незалежні. «Company-managed на Free створити
   можна» — прямої цитати немає (лише «shared configuration… isn't available on the Free plan»); в урок не
   поставлено. Закривається майстром `Create space` на sandbox.
8. **j10 · Workflow.** Не «окремий workflow на кожен тип роботи», а один workflow на **комбінацію** типів (Jira
   питає при збереженні). `Resolution` у team-managed не заповнюється й не редагується — ознака завершеності
   `statusCategory = Done`. Шість статусів `HR` зібрані як «перейменувати три наявні + додати три нові».
9. **Усі · іконки без підпису.** Картки замовляють мітки на іконках (⤢, око watchers) — конвенція §4.3 після
   j01–j03 забороняє їх вигадувати; мітки переносяться на справжні написи, іконки називаються в підписі.

## Відкриті питання власнику

1. Назва фірми «Кориця» і склад восьми людей — затвердити або виправити (розділ 3, одна правка).
