## 4. Що описано словами замість вікна

1. **Екран OAuth-згоди Atlassian (W1 картки).** Не намальований. Причина: у доксах Atlassian
   немає **жодного напису з цього екрана дослівно** — `configure-oauth-2-1` описує його
   функціонально («The user is redirected to Atlassian to review and grant access on a consent
   screen», «Which scopes are available… on behalf of the user»), але не дає ні заголовка, ні
   назв кнопок, ні формату переліку дозволів. Знімка немає: конектор вмикає лише власник.
   В уроці — окремий підрозділ блоку 2 прозою, з ⚠ і поясненням, **чому** вікна немає.
2. **Панель `/mcp` і вивід `claude mcp list`.** Не показані виводом. У `term` стоїть лише те,
   що людина **вводить**; стани з'єднання названі в блоці 5 **цитатою з документації**
   (`✔ Connected`, `! Needs authentication`, `✘ Failed to connect`), а не намальованим екраном.
3. **Діалог «запит → виклик інструмента → підтвердження → результат».** Картка веліла зняти
   з реального запуску; запуску не було, тому діалог **не відтворений** — він розкладений
   на `sequenceDiagram` (блок 3) і на кроки 3–5 прозою. Сценарій живого прогону — §5 нижче.

## 6. Розбіжності

1. **Endpoint — ⚠ `facts-free-plan.md` №14 ЗАКРИТО.** Обидві адреси **живі** (перевірено
   2026-09-19, 06:14 UTC, `curl -s -D - -o /dev/null`):
   - `https://mcp.atlassian.com/v2/mcp` → **401**, `www-authenticate: Bearer
     resource_metadata="https://mcp.atlassian.com/.well-known/oauth-protected-resource/v2/mcp"`,
     `server: AtlassianEdge`;
   - `https://mcp.atlassian.com/v1/mcp/authv2` → **401**, `www-authenticate: Bearer
     resource_metadata=".../v1/mcp/authv2", error="invalid_token", error_description="Missing or
     invalid access token"`.

   Тобто це не «одна адреса правильна, друга ні»: живі обидві, і стара **не падає гучно**.
   В урок іде **v2** — вона стоїть у чинній сторінці підключення. v1 винесена в граблі з
   двома опорами: «The tools listed on this page are only available with Atlassian MCP v2»
   (`supported-tools`) і «On March 1, 2027 any existing utilization of v1 will automatically
   start to expose and utilize v2 tools» (сторінка підключення).
   **Джерело помилки знайдено:** маркетингова сторінка `atlassian.com/platform/remote-mcp-server`
   (редіректить на `/platform/rovo-mcp`) **досі містить `v1/mcp/authv2`** у кнопці встановлення —
   саме звідти взялась розбіжність у `facts`.

2. **Кредити — ⚠ `facts-free-plan.md` №14b ЗАКРИТО (суперечність несправжня).**
   `rovo-usage-limits` ділить звернення на два роди:
   - **безкоштовні:** «Free TWG API calls include installing the Teamwork Graph CLI and Rovo MCP
     or running commands to look up or update context in any single Atlassian product», приклади —
     «Write operations such as updating a Jira work item», «Requesting single product context,
     such as looking up a Jira work item»;
   - **за кредити:** крос-продуктові й пошукові («…recent work across Jira, Confluence, Bitbucket,
     and connected external tools»; `getTeamworkGraphContext`, `searchAtlassian`, `search`).

   Разом із «Rovo credits are included in all paid Jira, Confluence, Service Collection and
   Teamwork Collection cloud subscriptions» це дає робочу картину: **звичайна робота з Jira через
   MCP на Free кредитів не потребує**, а крос-продуктові запити — інший рід звернення. Урок
   побудований саме так («тримай прохання в межах Jira»), і він не розсиплеться, якщо політика
   зміниться. Що саме відповість Free-сайт на «збагачений» виклик — лишилось ⚠ №3.

3. **Докси MCP переїхали.** Були `support.atlassian.com/rovo/docs/…` (адреса в картці програми
   й у `facts-free-plan.md`), стали **`support.atlassian.com/atlassian-ai-gateway/docs/…`**;
   старі слаги редіректять. Заголовок сторінки тепер «Get started with the Atlassian MCP server»,
   а в тексті поруч живуть три назви: **Atlassian MCP**, **Atlassian Rovo MCP Server**,
   **Rovo MCP**. В уроці вжито «MCP-сервер Atlassian» і назву продукту Rovo MCP Server один раз.

4. **Картка програми проти продукту** (той самий клас, що й у хвилі 4):
   - картка: «`developer.atlassian.com/cloud/rovo-mcp/` (getting started, tools)» — **цей розділ
     не використовувався**: жива документація інструментів тепер у `support.atlassian.com`;
   - картка: «reporter — людина, а не Automation» — **дослівного джерела немає**; подано як

   - картка: «ризик: якщо MCP на Free упреться в ліміт кредитів Rovo — REST API як запасний шлях» —

## 7. Що в контракті виявилось незручним

1. **§4 не має стану для чужого екрана.** Усі шість станів — про Jira, а половина цього уроку
   відбувається **поза Jira**: термінал і сторінка згоди Atlassian. Якщо дизайн захоче колись
   показати екран згоди, знадобиться або сьомий стан, або дозвіл на `form` із написами чужого
   сервісу. Зараз обійшовся прозою.
2. **§4.4 «один запит = один блок»** для CLI розриває природну пару: «запусти `claude`» і
   «всередині набери `/mcp`» — це один крок людини, але два різні рядки. Вийшов текст + один
   блок; читається нормально, але правило під JQL, а не під термінал.
3. **Норма «2–4 граблі» (§3) не сходиться з широтою карток третій урок поспіль** (j15 — п'ять,
   j18 — найбільший блок 3, тут — **шість**). Скорочувати не став: кожна грабля має джерело й
   різну природу (акаунт · область · адреса · режим дозволів · формулювання · плутанина з Rovo).
4. **Заголовок вікна має лише два стани.** Моє вікно — гібрид трьох джерел (знімок + сюжет +
   докси). Узяв «за документацією» як строгіший і пояснив склад у підписі. Заявка на третій стан
   тепер від чотирьох уроків: j14, j15, j17, j22.
5. **Вимога «≥ 1 вікно» для уроку, де головний екран — термінал.** Тут виправдано (є картка в
   Jira), але сама вимога змушує шукати привід. Для j23 виняток уже є; варто памʼятати, що такий
   урок можливий і серед звичайних.
6. **Дрібне:** `.term__meta` з `$` без `aria-hidden` — конвенція курсу «AI Термінал» (22 з 23
   уроків) розходиться з духом контракту; зробив як у сусідньому курсі, бо `js/ui.js` копіює
   лише `.term__in`.

## 8. Знахідки для сусідніх уроків

### → j23 (іспит)
Безпечні теми для питання Ф5 по j22 (усі стоять на цитатах і не залежать від версії):
MCP — місток, а не AI всередині Jira · доступ мають усі сайти Cloud, різниця планів — **частота**
звернень · згода вирішує сайт і дозволи, права лишаються твої · читання спершу, запис — з
підтвердженням · `Ask AI` ≠ MCP. **Не питати** про номер покоління endpoint-а (змінюється
1 березня 2027) і про числа кредитів/лімітів.

### → довідник «Карта інтерфейсу, глосарій і ліміти Free» (числа, яких в уроці немає)
- **Ліміт звернень MCP** (`atlassian.com/platform/rovo-mcp`, 2026-09-19): «Free: 500 calls per
  hour · Standard: 1000 calls per hour · Premium/Enterprise: 1000 calls per hour (+ 20 additional
  calls per user with up to 10,000 calls per hour)»; там само «The MCP server does not currently
  support FedRAMP or HIPAA requirements».
- **Кредити Rovo** (`rovo-usage-limits`): Jira 25/70/150 на користувача на місяць
  (Standard/Premium/Enterprise), Confluence так само, Service Collection і Teamwork Collection
  250/700/1500; «$0.01 per Rovo credit, or $10 per 1,000 credits»; «Vast majority of enriched TWG
  API and tool calls are 1-10 Rovo credits per call»; перевитрата вмикається **2026-12-03** —
  **та сама дата, що для кроків автоматизації** (j15), тобто в довіднику це один рядок про дві речі.
- **Розділ «Що змінилось»:** докси MCP переїхали `rovo` → `atlassian-ai-gateway` · v1 → v2,
  автоперемикання **2027-03-01** · форуми спільноти перезапускаються **2026-09-22** ·
  канонічний хост доксів Claude Code — `code.claude.com` (`docs.claude.com` редіректить).

### → довідник «JQL: поля, оператори, функції»
JQL живе і в MCP: інструмент **`searchJiraIssuesUsingJql`** («Search Jira work items using JQL»).
Обіцянка картки довідника «JQL у flows, дашбордах, MCP» закривається цим рядком.

### → j20 «Люди і доступ»
- **Готові цитати:** «a user can revoke their app grants at any time using their own connected
  apps screen» · адмінський шлях — `Atlassian Administration → Site settings → Connected apps →
  Manage authorization for the app → Uninstall`, там само `Block user apps` («Organization and Site
  admins can also choose to restrict app installation to admin level») —
  `security-and-access-policies/docs/manage-your-users-third-party-apps/`.
- **Ще один випадок «адміністратор ≠ адміністратор»:** групи інструментів `delete_jira` і
  `manage_jira` вимкнені за замовчуванням, вмикає їх **адміністратор організації**
  («Organization admins grant or revoke access at the permission-group level»).

### → j17 «Marketplace обережно»
Та сама сторінка `manage-your-users-third-party-apps` дає цитати про `Connected apps`,
статус `UPDATE` і `Block user apps` — перетин із темою уроку 17; якщо рецензент шукатиме
джерело для «хто ставить застосунки», воно тут.

### → j18 / j19 (JSM)
На сторінці `configure-oauth-2-1` серед застосунків, які перелічені на екрані згоди, прямо
названо **Jira Service Management** — тобто підключення MCP стосується й службових спейсів.
Інструментів саме JSM у переліку `supported-tools` я не звіряв.

### → дизайну
- Нових класів **не бракувало**: вікно `item` зібралось з наявних (`win__item`, `win__fields`,
  `win__desc`, `win__comments`).
- **Новий випадок для `term` (390 px):** три блоки містять **довгий український запит одним
  рядком** (до 210 знаків) — перенесення всередині `.term__in` варто заміряти; це не команда,
  її не можна різати переносом навпіл без зміни змісту при копіюванні.
- `win__topbar` — **0 вживань і в цьому уроці** (19 з 19).

### → усім (метод, дешевий і повторюваний)
**Живість MCP-endpoint перевіряється без підключення:**
`curl -s -D - -o /dev/null <url>` → **401 + заголовок `www-authenticate: Bearer resource_metadata=…`**
означає «адреса жива й захищена», а 404 — «такого шляху немає». Це відрізняє «стаття застаріла»
від «адреса застаріла» за одну секунду й без жодного акаунта.
**Друге:** індекс живих слагів розділу Atlassian тепер треба шукати й поза `jira-*`:
`support.atlassian.com/atlassian-ai-gateway/resources/` — той самий прийом хаба працює
для нових продуктових розділів.
