   значка немає.
6. **Розділ «фільтр» проти «фільтр вигляду».** Задача просила розвести одним рядком — зроблено
   в блоці 4 цитатами з `save-your-filters-in-business-projects` («are specific to the space you
   create them in», «you can only apply one at a time»).
7. **Три фільтри огляду.** Картка називає «прострочені · без виконавця · без дедлайну», а j07
   зберіг інші три («мої на цьому тижні», «прострочені», «без виконавця»). Взяв ті, що реально
   існують після j07, а «без дедлайну» подав як **четвертий** запит у `term`-блоці
   (`due IS EMPTY AND statusCategory != Done ORDER BY created ASC`; поля `due`, `created`,
   оператор `IS EMPTY` перевірені на `jql-fields`).

## 7. Що в контракті виявилось незручним

1. **Стан `form` не має контейнера для сторінки-не-діалогу.** `Import data into Jira` — це не
   діалог і не ланцюжок кроків, а сторінка налаштувань із плитками. Скористався дозволеним
   §4.3 «найближчим наявним»: `win__main` → `win__bar` (крихта + кнопка) → `win__page` (`h4` +
   `win__tiles`), без рейки (рейки налаштувань у знімку немає). Дизайну: або дозволити
   `win__page` у `form` офіційно, або завести стан «сторінка налаштувань без рейки».
2. **Бракує класу для інформаційної картки всередині вікна.** На екрані імпорту зверху стоїть
   помітна картка «You're in the new import experience» з абзацом тексту; класу під неї немає
   (`win__portal-intro` — семантично про портал). Текст винесений у підпис під вікном.
3. **`<h4>` у прозі заборонений, а третій рівень заголовків подекуди потрібен.** Блок «Зроби
   сам» має чотири частини (А–Г), і всередині Б — три кроки. Обійшовся префіксами
   «Б1 / Б2 / Б3» на `<h3>`; у 21 сусідньому уроці `<h4>` поза вікнами — 0, тож конвенцію не
   ламав. Якщо третій рівень буде потрібен частіше, це рішення для контракту, не для автора.
4. **Легенда «підписи, не речення» і мітка на рядку таблиці.** У `list`-вікні мітка природно
   лягає на клітинку (назва спейсу), а не на заголовок колонки; зробив так, бо інакше цифра
   вказувала б на колонку, а пояснення — на рядок. Варто зафіксувати конвенцію.
5. **Норма «2–4 граблі» знову тісна для практикуму** — у мене рівно 4, але граблі про імпорт
   довелось стиснути в один заголовок із двома підтемами (ключ і перенесення робіт). Те саме
   зауваження вже робили автори j07 і j11.

## 8. Знахідки для сусідніх уроків

- **j21 → довідник «Карта інтерфейсу, глосарій і ліміти Free»:** таблиця «Structure your
  hierarchy» (`jira-software-cloud/docs/map-column-data-to-issue-types/`) — що саме можна
  створювати при імпорті на кожному плані: Free/Standard у company-managed — рівні 0 і −1;
  у team-managed — «Can create any number of work types at level 0 during import», «Can't create
  new work types at level 1 and above», «Can't create new work types at level −1»; більше 150
  унікальних значень у колонці типу — попередження. Також: «Recommended number of work items per
  file — 1500» і «Estimated time to import — Approximately 1 hour»
  (`jira-cloud-administration/docs/import-data-from-a-csv-file/`); кошик і строки — уже в j12/j20.
- **j21 → довідник «Що змінилось»:** **сезонні релізи задокументовані** —
  «Jira changes will now be available in seasonal release cycles»
  (`organization-administration/docs/what-are-release-tracks/`); там само три треки
  (continuous / bundled / preview) і те, що вибір треку — **Premium або Enterprise**, а сторінка
  `App updates` (`…/view-all-changes-to-an-atlassian-app/`) доступна **на всіх планах**
  адміністраторові організації. Це найкраща опора для розділу «Що звіряти після релізу».
- **j21 → j20:** у моєму уроці крок 16 чеклиста — «доступ до фільтрів і дашборда» з цитатами
  `manage-filters` («Private… only… the owner and Jira admins», «My organization… all users on
  the Jira instance»); якщо j20 говорить про доступи інакше, варто вирівняти формулювання.
  Там само: **обрати одну форму запису мітки в JQL** (з лапками чи без) — див. §6, п. 4.
- **j21 → j19, j22, іспит:** шлях до імпорту **подвійний** і обидва документовані:
  `Create space` → «Scroll to the bottom of the sidebar then select Import data» і
  `Settings → System → External System Import`. Перший створює **новий** спейс, другий —
  єдиний шлях дописати роботи в **наявний** (лише site/org admin).
- **j21 → усі:** **`Set to recur`** — готовий механізм повторюваної роботи без ручного flow:
  «Select Automation via the lightning bolt icon, or select the Due date field» → «Select Set to
  recur»; створений flow зветься `Clone on a schedule`, мітка `Recurring`; копія бере ті самі
  поля, крім дат початку й завершення, і дочірні роботи, **не бере** вкладення, веб-посилання й
  звʼязки; запуски рахуються в межі автоматизації. Корисно для j05 (повторювані справи) і j14/j15.
