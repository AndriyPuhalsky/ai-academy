## Канон хвилі (рішення власника, не переоткривати)
- **Верхній рівень ієрархії — назва з екрана:** `Workstream` у `REM` і `HR` (шаблон Project management), `Campaign` у `MARK`
  (Campaign management), `Epic` — **лише** у `WEB` (Kanban, шаблон розробки). У прозі — «етап (Workstream)» / «кампанія
  (Campaign)» / «епік (Epic)» при першій згадці на сторінці, далі можна українським словом. Урок j04 один раз пояснює
  механіку: довідка Atlassian зве цей рівень Epic («level 1, by default called Epic»), а діловий шаблон дає йому свою
  назву. Шаблон Task tracking (`MY`) верхнього рівня не має (Task · Sub-task).
- **Цитати доксів з «Epic» лишаються дослівними** (цитата — це цитата). Перефраз поруч пояснює, як цей рівень зветься в
  спейсі сюжету. Не «виправляй» докси.
- **Підзадача:** тип `Sub-task` (з дефісом) у ділових спейсах, `Subtask` — у спейсі розробки. Українське «підзадача» лишається.

  Project management і Campaign management; правдиве лише для Task tracking) і рядок доксів «Task and subtask» для Project
  management як опис того, що дасть шаблон (жива Jira дала Workstream · Task · Sub-task).

## Квіз
Якщо питання, правильна відповідь чи дистрактор стоять на спростованому (Epic у діловому спейсі, `+ Add work type` для епіка,
`Use template`/`Create` у діловому майстрі, `Any` у нового статусу тощо) — виправ. У цій хвилі тобі дозволено змінити й
текст правильної відповіді та `explain`, якщо вони фактично хибні зараз; кожну зміну квізу — окремим рядком у звіті. Правильна
відповідь не стоїть на твердженні під ⚠. Не маркуй правильну пунктуацією чи словом («…, бо …» лише в правильній).
