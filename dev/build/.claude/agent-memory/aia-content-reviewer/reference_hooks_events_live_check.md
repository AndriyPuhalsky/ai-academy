Найдешевший спосіб дізнатись, які hook-події знає **встановлена** збірка (не докси):
покласти в `.claude/settings.json` неіснуючу назву події й запустити `claude doctor`.
Він друкує блок `Invalid settings` з рядком
`Unknown hook event "X" was ignored. Valid events: PreToolUse, PostToolUse, …` —
**усі валідні назви через кому, ОДНИМ рядком**, не списком. Тому «N рядків» у тексті
курсу — хибна одиниця виміру; правильно «N назв».

- Перевірено 2026-09-06 на **2.1.263**: у переліку рівно **33** назви (розрив 33/31 із
  збірки 2.1.236 закрито — `PreModelSwitch`/`PostModelSwitch` доїхали).
- `claude doctor` **виходить із кодом 0** навіть коли знайшов зламані налаштування —
  як гейт у конвеєрі не годиться. Перевірено тим самим запуском.
- **Регістр назви події важливий**: `sessionstart` теж дає `Unknown hook event`.
- Експеримент безпечний, якщо робити його так: своя тека в `/private/tmp`,
  `CLAUDE_CONFIG_DIR=<своя тека>`, `"command": "true"` — і прибрати за собою.
- Другий шлях (`strings "$(which claude)" | grep`) доводить лише **відсутність** назви;
  контроль — вигадана назва, вона мусить дати «немає». Див. [[reference-lesson-verification]].

Markdown, **немає в `llms.txt`**, тягнути прямо по URL). Там же таблиця
«Exit code 2 behavior per event» — готова відповідь на питання «хто блокує»:
станом на 2026-09-06 це 15 подій із 33.
