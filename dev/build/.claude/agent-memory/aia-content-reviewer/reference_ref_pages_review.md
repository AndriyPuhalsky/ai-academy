Три довідники (`claude-code-ref-commands.html`, `-hooks`, `-settings`) лежать **у корені
сайту**, поза `modules/`, поза прогресом і сертифікатом, **без квіза**.

- Контракт уроку (вісім блоків, `data-module`, `#quizData`, Mermaid) до них **не
  застосовується** — не «виправляти» під структуру уроку.
- `check-lessons.py` і `check-quiz.py` їх **не бачать взагалі** — механічної страховки нема.
- Що перевіряти механічно: `data-config` на `<html>`, `.skip-link`, `id="main"`, viewport без
  `user-scalable`, обгортка `overflow-x-auto` + `aria-label` **на кожну** таблицю, нижній
  регістр шляхів, відсутність `term--enter`/`term--hero`. У `-ref-commands` на 2026-09-06 усе
  це стояло: 30 таблиць = 30 обгорток з `aria-label`.

**Повнота — головна цінність довідника, і вона перевіряється діфом множин, а не читанням.**
Робочий рецепт (`-ref-commands`, 111 команд, зайняв хвилини):

1. `curl -sL https://code.claude.com/docs/en/commands.md` → витягнути перший стовпчик
   регуляркою `^\| \`(/[^\`]+)\`` → множина «наживо».
2. З HTML витягнути перший `<td><code>/…</code></td>` кожного рядка між `id="g1"` і
   `id="dead"` → множина «в довіднику».
3. `comm` обох. Так знайшлась єдина нова команда `/skill-doctor` (v2.1.252+), а решта
   111 із 111 збіглась із датованим знімком `screens/b-slash-commands-full.txt` **точно**.
4. Окремо звірити **сигнатури** (`[arg]` / `<arg>`) — вони теж діфаться автоматично.

Далі описи вже читаються очима, але швидко: живі рядки доксів дампляться у файл
`### <ім'я>\n<опис>` і дивляться пачками по 12–16.

**Що ловиться саме тут, а не в уроці:** дрібна неточність у клавіші, якої в жодному уроці
немає. Приклад: `Ctrl+W` було описано як «видаляє попереднє слово», а докси
(`interactive-mode`) прямо протиставляють: `Ctrl+W` іде **до найближчого пробілу** (цілий шлях
або `--flag=value`), а «лише слово» — це `Option+Delete` / `Ctrl+Backspace`.

Див. також [[course-numbers-drift]], [[lesson-fact-sources]], [[lesson-verification]].

## `-ref-settings`: діф трійками, а не парами (2026-09-06)

Таблиця «All settings» у `settings-reference.md` має **чотири** колонки, тож звіряти можна
не тільки назви, а й **тему** та **область** — одним прогоном:

```python
# 1. докси: рядки між '## All settings' і '## Model and responses'
#    regex ^\| \[`(key)`\] ... | Topic | Scope |   → 225 трійок (2026-09-06)
# 2. HTML: секції <section id="..."> крім службових (files/scopes/traps/examples/toc/
#    notinlist/sources); у кожній <tr><td><code>K</code></td><td>опис</td><td>область</td>
#    прибрати <wbr>, зіставити «будь-який»→Any file, «свій або керований»→User or managed,
#    «свій, локальний, керований»→User, local, or managed, «лише керований»→Managed,
#    «~/.claude.json»→Global config
# 3. діф множин + порівняння теми й області для спільних ключів
```

Результат: **223 із 223 рядків збіглися з доксами і назвою теми, і областю — нуль
розбіжностей**; бракувало рівно двох нових ключів. Тобто на такій сторінці читати описи
очима треба **вибірково** (там, де є сильне твердження), а таблицю — машиною.

Версійні позначки теж діфаються машиною: `Requires Claude Code v(X) or later` з тіла запису
проти `потрібна X+` у HTML. 39 із 40 збіглися точно; єдиний виняток — ключ, який **після
знімка встиг стати deprecated** (`keybindingFlavor`, див. [[course-numbers-drift]]).

**Два змістові капкани саме цієї сторінки:**

1. **«Чотири ключі-моделі беруться цілком з одного джерела» — неправда для двох із чотирьох.**
   `settings.md` («Lists merge instead of overriding»): цілком беруться лише `fallbackModel`
   і `modelPicker`; `availableModels` між **не**керованими областями **зливається як завжди**
   (як є застосовується тільки керований список), а `modelSettings` розвʼязується **по одній
   моделі за раз** разом із `effortLevel`. Ця сама помилка була і в `c13`, і в довіднику.
2. **`cleanupPeriodDays: 0` — це `Settings Error`, а не `Settings Warning`.** Перевірено
   живцем на 2.1.263 у `CLAUDE_CONFIG_DIR=/private/tmp/…`: `claude doctor` кладе ключ у
   розділ `Invalid settings` з `Suggested fix: cleanupPeriodDays must be at least 1`, а
   `settings.md` відносить «значення, яке схема відхиляє» саме до `Settings Error`
   («Settings Warning» — це про **окремі записи** всередині ключа: криве правило дозволу,
   неіснуюча назва події). `c13` каже інакше — урок помиляється, довідник правий.

**Ще один задокументований виняток, який легко проґавити:** блаженна формула «область не
«будь-який» → з проєктного файла ключ просто не діє» має рівно один контрприклад у доксах —
`autoContinueAtUsageLimit`: «When none of those sets the key, a project or local settings file
that sets it **turns the feature off** rather than being ignored». Тобто наслідок
протилежний обіцяному. Шукати такі місця: `grep "rather than being ignored" settings-reference.md`.
