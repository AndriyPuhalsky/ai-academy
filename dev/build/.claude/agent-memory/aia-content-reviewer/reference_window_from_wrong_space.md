Вікно уроку може бути зняте з реального екрана — і все одно брехати, бо знімок узятий **з іншого
спейсу**. У 012 так сталось двічі з одного кореня: `screens/03-board.md` і `screens/10-space-settings.md`
зняті зі спейсу **розробки** `KAN`, а вікна, підписані як ділові (`MY`, `REM`), намальовані з них.

Два конкретні сліди (звірені з `screens/27-sandbox-2026-09-28.md` §4–§5):
- **рейка `Space settings`**: у діловому спейсі немає `Features` і `Custom filters`, зате є `Approvals`
  (j06 тричі веде читача в `Features`; вікна j11, j15, j20 малюють ділову рейку з `KAN`);
- **порядок вкладок спейсу**: вікна пишуть `Summary · List · Board` (це `KAN`, 17.09), живий діловий —
  `Summary · Board · List · Calendar …`, живий `WEB` (теж Kanban!) — `Summary · Timeline · Board ·
  Calendar · List …`. Три різні порядки, тож «виправити за аналогією» не можна.

**Як перевіряти:** у заголовку вікна дата каже *коли*, але не каже *де*. Для кожного вікна ділового
спейсу спитати: який файл `screens/*` дав ці написи і якого спейсу він стосується. Якщо джерело —
знімок спейсу розробки, це дефект, навіть коли всі написи дослівні.

**Що робити:** не правити в одному файлі. Це наскрізний клас (j04, j06, j11, j15, j16, j20, j21) —
у звіт одним рядком плюс запит на дозйомку рейки/навігації ділового спейсу; фікс іде одним проходом
кореневої сесії. Пов'язане: [[claims-about-the-docs]], [[unsourced-claims-registry]].
