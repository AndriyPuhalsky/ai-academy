**На сторінці буває рівно ОДИН вхід.** 65 публічних сторінок мають M1 (`data-page-in` на
`<main>`); `roadmap.html` — ні, і це свідомо: його вхід — власний таймлайн 003
(`js/roadmap-motion.js`, рядки заголовка з-за маски + лічильники). Рішення 011 №2 від
2026-09-10, файл `dev/build/011-open-tails/05-decisions/decision-2-roadmap-page-in.md`.

**Why:** M1 = `gsap.fromTo(main, {opacity:0, y:8}, …520 мс)`. Заміряно A/B: `rm:rendered`
приходить через **1–4 мс** після `DOMContentLoaded`, тобто `<main>` має `opacity: 0` рівно
в мить, коли будується вхідний таймлайн 003 — накладання стовідсоткове, ~360 мс притемнення
поверх авторського жесту.
⚠ **Технічної шкоди від додавання НЕМАЄ** — це головне, що варто памʼятати, бо звіт
спочатку стверджував протилежне: ScrollTrigger Δ ≤ 3 px (геометрія змійки рахується
різницями rect, до transform байдужа), LCP Δ ≤ 12 мс, під `prefers-reduced-motion` M1 не
грає взагалі. Відмова — за дизайн-наміром, не за ризиком.
`claude-code.html` — не контрприклад: у нього `<main>` теж порожній і `data-page-in` є, але
власного **входу** немає (лише M10 друк від IO і M9 скрол-вісь), тож M1 і є його входом.

**How to apply:** нова сторінка за замовчуванням отримує `data-page-in` на `<main>`. Виняток
робиться **тільки** якщо в неї є власний вхідний таймлайн; сама наявність GSAP,
ScrollTrigger чи асинхронного рендера підставою не є. Не переносити атрибут на шапку/футер/
hero — це гірший виняток, ніж відсутність: grep показує парність, а семантика інша. Не
правити `js/motion.js` заради винятку — спільний файл 66 сторінок.
