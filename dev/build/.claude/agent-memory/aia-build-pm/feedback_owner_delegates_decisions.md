Коли власник каже «вирішуй сам» — вихід PM це **одне рішення** з розділами «Чому ·
Наслідки · Специфікація для виконавця · Що НЕ робити», а не перелік варіантів із
рекомендацією в кінці.

**Why:** варіанти повертають рішення власнику, тобто делегування не спрацювало;
а виконавець без точного CSS/JS і без «що НЕ робити» дописує рішення сам, мовчки.

**How to apply:** у спеку класти дослівний код і точні якорі (`файл:рядок`), у критерії
приймання — числа, за якими два різні агенти дійдуть одного висновку. Тверда рамка
хвилі 011, яку власник повторив двічі: **не погіршувати наявний UI/UX і функціонал**,
зміни — з урахуванням наслідків. Тому в кожному рішенні має бути окремий список «кого
зміна НЕ торкається» з доказом, а не самі лише плюси.
