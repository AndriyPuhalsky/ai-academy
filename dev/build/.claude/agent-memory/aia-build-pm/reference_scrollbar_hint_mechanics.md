**Три речі про смуги прокрутки AIA, кожна вже один раз ввела в оману (рішення №1 задачі 011,
заміри 2026-09-10, Chrome 152 по CDP).**

**1 · `scrollbar-color` УСПАДКОВУЄТЬСЯ і вимикає `::-webkit-scrollbar`.**
`css/components.css` §38.8 ставить `html { scrollbar-width: thin; scrollbar-color: var(--c-line) transparent }`.
`scrollbar-width` не успадковується (computed на скролері — `auto`), а **`scrollbar-color` —
так**, і Chrome ≥ 121 ігнорує вендорні псевдоелементи скрола на елементі, у якого задані
стандартні властивості. Наслідок: будь-яке правило `::-webkit-scrollbar` на цьому сайті —
**мовчазний нуль**, поки поруч не стоїть `scrollbar-color: auto`. A/B: 0 px → 12 px.

**2 · На macOS усі шість скролерів системи накладні.** `offsetHeight − бордери − clientHeight
= 0` на всіх типах (таблиця, діаграма, термінал, код). Смуга, видима на знімках
`011-open-tails/stand/shots/t8-*`, — накладна, що спалахнула від `scrollIntoView()` у самому
скрипті заміру й гасне за 1–2 с. **Знімок після програмної прокрутки не доводить, що підказка
видима у спокої** — доводить лише товщина в пікселях.

**3 · Метод «чи є що гасити».** Маска згасання краю (§41) працює тільки там, де в краю є
вміст. Рахувати так: для кожного прокручуваного блока зібрати прямокутники текстових вузлів
(`TreeWalker` + `Range.getClientRects`) і графіки SVG, порізати блок по 200 px висоти й
перевірити, чи хоч один прямокутник заходить у `--fade-w` від правого краю. База 2026-09-10:
**50 блоків, 211 зрізів, 11,4 % без чорнила, 0 блоків порожніх повністю, 32 % блоків вищі за
вʼюпорт** (там смуга знизу на екран не потрапляє). Ширина маски — не важіль: 40 → 96 px дає
лише 2,8 п.п.

**How to apply:** перш ніж обіцяти видиму смугу чи «підсилити гасіння» — заміряти обидва
числа. Повний розбір і готова спека — `dev/build/011-open-tails/05-decisions/decision-1-scroll-hint.md`.
Повзунок фарбувати `--c-line-strong` (3,34–3,78 до `--c-surface` / `--c-bg` / `--c-sunken`),
не `--c-line` (1,59–1,80 — провал SC 1.4.11). Споріднене: [[cls-opacity-masking-and-attr-injection]].
