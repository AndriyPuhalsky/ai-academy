Частина клієнтського коду AIA виконується **лише для залогіненого користувача**
(`renderEmpty()` / `renderCerts()` у `js/certificate.js` — після успішної відповіді
`certificates`). Агент не має права реєструвати акаунт, а база одна й вона продова.

**Робочий обхід:** пробна HTML-сторінка в межах своєї папки задачі
(`dev/build/NNN-slug/02-backend/`), яка перед `<script src="/js/....js">` кладе
`window.AIA_USER = {id:"probe"}` і заглушку `window.sb` з ланцюжком
`from().select().order()` → `Promise.resolve({data: [], error: null})`, а потім
диспатчить подію `aia:auth`. Мережі не торкається взагалі, у базу не пише.
Сторінка в `dev/` не роздається з сайту (`.assetsignore`), тому в прод не поїде.
Приклад: `dev/build/011-open-tails/02-backend/probe-cert-empty.html`.

Той самий прийом дає перевіряти екранування: підставити в поле контракту
ворожий рядок (`" onmouseover="alert(1)`) і подивитись, чи не зʼявився зайвий
атрибут у результаті.

**Чому це важливо:** без нього єдиний спосіб побачити ці стани — справжній акаунт
із записом у `profiles`/`certificates`, а в `certificates` немає політики DELETE,
тобто слід прибирає власник вручну (так було в 005-4).
