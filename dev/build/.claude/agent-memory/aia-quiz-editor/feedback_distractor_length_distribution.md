У кожному файлі свідомо цілитись у ~1/3 питань, де правильна найдовша, ~1/3 де найкоротша,
решта — посередині (на 6 питань: 2 / 2 / 2; на 7: 2 / 2 / 3). Нічиїх за довжиною уникати.

**Why:** ціль задачі 007 сформульована як «найдовша ≤ 35 % і найкоротша ≤ 35 %», і її легко
виконати механічно — зробивши правильну **завжди** середньою за довжиною. Це дає 0 %/0 % у
таблиці, але створює нову підказку: «викинь найдовше й найкоротше — лишиться два варіанти».
Розподіл 1/3–1/3–1/3 закриває і метрику, і евристику.

**How to apply:** перед правкою питання вирішити, яку роль воно грає (найдовша / найкоротша /
середина), і під цю роль підбирати довжини дистракторів: для «найкоротшої» всі три мусять
бути довші за правильну, і саме там дистрактор має описувати механізм так само розгорнуто,
як правильна, але хибно. Тримати різницю в межах ±20 % від правильної й не допускати
однакових довжин. Практично зручно: чернетки міряти `len()` окремим прогоном до правки,
а не переписувати текст у файлі по колу. Контекст — [[project-007-quiz-distractors]].
