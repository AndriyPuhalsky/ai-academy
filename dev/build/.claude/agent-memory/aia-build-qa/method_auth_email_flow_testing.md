# Відновлення пароля: усе, крім самого листа, перевіряється без жодного запису

Перевірено 2026-10-02 (задача 015, коло 1, гілка `password-reset`).

**Why:** база одна й продова, а ліміт відправок — 30 листів/год на весь проєкт. Тест, який
«просто спробував», зʼїдає чужі листи. При цьому **жоден** стан UI насправді не вимагає листа.

**How to apply:**

## 1. Два URL замінюють лист (і працюють для гостя, без акаунта)

- `?error=access_denied&error_code=otp_expired&error_description=Email+link+is+invalid+or+has+expired`
- `?token_hash=bad&type=recovery` — і те саме на сторінці уроку (`/modules/module-01?…`),
  бо там інший шлях: шлагбаум `#aiaGate` знімається **пізніше** за `load`.

Обидва дають панель «Посилання вже не діє» + чистий URL. Хеш-форма (`/#token_hash=…`) теж
обробляється — але див. пастку в [[method-hidden-window-traps]] про навігацію лише фрагментом.

## 2. Стани форми й діалогу — підміною `handlers`, без мережі

```js
let calls = 0;
AIAAuthUI.init({ handlers: { requestPasswordReset: () => { calls++; return Promise.resolve({ok:true}); } },
                 certUrl: '/certificate' });
AIAAuthUI.openAuthModal({ view: 'reset' });
AIAAuthUI.openPasswordDialog({ onSave: () => Promise.resolve({ok:false, message:'…'}) });
```

- `init` замінює **весь** обʼєкт `handlers` → справжній вхід на цій вкладці вмирає;
  робити це **в `<iframe>`** потрібної ширини або перезавантажувати сторінку після.
- Лічильник викликів — єдиний чесний доказ guard-а подвійного кліку (клік+клік → `calls === 1`).
- Гілку «Enter у полі» перевіряти **з позитивним контролем**: підмінити ОБИДВА обробники
  (`requestPasswordReset` і `signInWithPassword`) і впевнитись, що у вигляді `reset` спрацював
  перший, а у вигляді `auth` — другий. Інакше доведено нічого.

## 3. Стан «немає мережі» — блокуванням хоста, а не відправкою

Власний Chrome по CDP ([[method-cdp-own-chrome]]) + `Network.setBlockedURLs` на хост Supabase:
запит фізично не покидає машину, листа немає, а код проходить **справжню** гілку помилки.
Так знайдено, що `translateError` віддає користувачеві англійське `Failed to fetch`.

## 4. ⛔ 429 «Забагато спроб» дозволеними засобами НЕДОСЯЖНЕ

`POST /auth/v1/recover` на неіснуючу адресу (`…@example.com`) повертає **200 і нічого не шле**:
вікно 60 с рахується «for the same user», а користувача немає. Дві відправки поспіль — обидві
200, UI показує «Перевір пошту» двічі. Дістати 429 можна лише живим акаунтом, тобто зачепивши
спільний ліміт прода. **Писати «не перевірено» з цим доказом, а не «пройдено».** Показ
`{ok:false, message}` у формі доводити окремо — підміною обробника (п. 2).

## 5. Що рахувати мережею

`performance.getEntriesByType('resource')` по хосту Supabase до і після дії — надійніше за
панель мережі розширення (вона починає стежити лише з першого виклику інструмента). Але
список «без змін» — доказ **лише** тоді, коли в тому ж колі є прогін, де запит зʼявився.

Межа «акаунтів не створюю, паролів не вводжу» — [[feedback-account-creation-boundary]].
