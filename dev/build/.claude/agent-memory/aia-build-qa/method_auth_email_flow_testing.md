# Відновлення пароля: усе, крім самого листа, перевіряється без жодного запису

Перевірено 2026-10-02 (задача 015, коло 1, гілка `password-reset`).

**Why:** база одна й продова, а ліміт відправок — 30 листів/год на весь проєкт. Тест, який
«просто спробував», зʼїдає чужі листи. При цьому **жоден** стан UI насправді не вимагає листа.

**How to apply:**

## 1. Два URL замінюють лист (і працюють для гостя, без акаунта)

- `?error=access_denied&error_code=otp_expired&error_description=Email+link+is+invalid+or+has+expired`
- `?token_hash=bad&type=recovery` — і те саме на сторінці уроку (`/modules/module-01?…`),
  бо там інший шлях: шлагбаум `#aiaGate` знімається **пізніше** за `load`.

Обидва дають панель «Посилання вже не діє» + чистий URL. Хеш-форма (`/#token_hash=…`) теж
обробляється — але див. пастку в [[method-hidden-window-traps]] про навігацію лише фрагментом.

## 2. Стани форми й діалогу — підміною `handlers`, без мережі

```js
let calls = 0;
AIAAuthUI.init({ handlers: { requestPasswordReset: () => { calls++; return Promise.resolve({ok:true}); } },
                 certUrl: '/certificate' });
AIAAuthUI.openAuthModal({ view: 'reset' });
AIAAuthUI.openPasswordDialog({ onSave: () => Promise.resolve({ok:false, message:'…'}) });
```

- `init` замінює **весь** обʼєкт `handlers` → справжній вхід на цій вкладці вмирає;
  робити це **в `<iframe>`** потрібної ширини або перезавантажувати сторінку після.
- Лічильник викликів — єдиний чесний доказ guard-а подвійного кліку (клік+клік → `calls === 1`).
- Гілку «Enter у полі» перевіряти **з позитивним контролем**: підмінити ОБИДВА обробники
  (`requestPasswordReset` і `signInWithPassword`) і впевнитись, що у вигляді `reset` спрацював
  перший, а у вигляді `auth` — другий. Інакше доведено нічого.

## 3. Стан «немає мережі» — блокуванням хоста, а не відправкою

Власний Chrome по CDP ([[method-cdp-own-chrome]]) + `Network.setBlockedURLs` на хост Supabase:
запит фізично не покидає машину, листа немає, а код проходить **справжню** гілку помилки.
Так знайдено, що `translateError` віддає користувачеві англійське `Failed to fetch`.

**Легша заміна, якої вистачає (коло 2, 2026-10-02):** перехопити `window.fetch` **у самій
сторінці** й відхиляти **лише** URL із `supabase.co`, решту пропускати. CDP не потрібен,
працює у звичайній вкладці розширення й у `<iframe>`; доказ, що нічого не пішло, — власний
лічильник перехоплень + порожній `performance` по `/auth/v1/`.

## 3а. Підміна `fetch` відповіддю покриває ВСІ гілки `translateError` — і стан «успіх» теж

Один і той самий прийом, чотири різні відповіді — і жодної витраченої відправки:

| Підміна | Що доводить |
| --- | --- |
| `Promise.reject(new TypeError('Failed to fetch'))` | гілка «немає звʼязку» (`AuthRetryableFetchError`, `status === 0`) |
| `new Response('{"message":"Service Unavailable"}', {status:503})` | що гілка мережі **не** перехоплює серверний збій: має бути загальний текст, бо інтернет у людини є |
| `new Response('{"error_code":"invalid_credentials","msg":"Invalid login credentials"}', {status:400})` | що наявні гілки не зламані новим кодом |
| `new Response('{}', {status:200})` | **стан «успіх»** («Перевір пошту») на будь-якій ширині — без справжнього листа й без витрати ліміту кола |

Остання рядок — найцінніша: заміри геометрії успіху на 1280 / 390 більше не вимагають
другої відправки. Ліміт «одна відправка за коло» перестає бути вузьким місцем.

**Рахунок рядків у консолі — це теж критерій.** Якщо гілку впізнано, «не впізнали» писатись
не має: два рядки замість одного = гілка не спрацювала. Рахувати надійніше перехопленням
`console.warn` у сторінці (`window.__c.push(...)`), ніж інструментом розширення (п. 5).

## 3б. Живий негативний контроль, який нічого не коштує

`?token_hash=bad&type=recovery` — це **справжній** запит `verifyOtp` у живий GoTrue і
**справжня** 403. Тобто безкоштовний доказ, що нова гілка «немає звʼязку» не ковтає
серверні помилки: має зʼявитись панель «Посилання вже не діє», а не «немає звʼязку».

## 4. ⛔ 429 «Забагато спроб» дозволеними засобами НЕДОСЯЖНЕ

`POST /auth/v1/recover` на неіснуючу адресу (`…@example.com`) повертає **200 і нічого не шле**:
вікно 60 с рахується «for the same user», а користувача немає. Дві відправки поспіль — обидві
200, UI показує «Перевір пошту» двічі. Дістати 429 можна лише живим акаунтом, тобто зачепивши
спільний ліміт прода. **Писати «не перевірено» з цим доказом, а не «пройдено».** Показ
`{ok:false, message}` у формі доводити окремо — підміною обробника (п. 2).

## 4а. Шлях, якому потрібне значення в полі пароля, — на localhost

Форма входу не дійде до `translateError` без пароля (`submitForm` рубає на
`!pass` і `pass.length < MIN_PASS`). Такий сценарій ганяти на `python3 -m http.server`
із кореня worktree, **спершу довівши рівність коду**: `curl -s http://127.0.0.1:<порт>/js/auth.js
| shasum -a 256` = хеш файла в worktree = хеш із превʼю. Вихід у мережу все одно заблокувати
підміною `fetch`. Деталі межі — [[method-guest-tests-on-localhost]],
[[feedback-account-creation-boundary]].

## 5. Що рахувати мережею

`performance.getEntriesByType('resource')` по хосту Supabase до і після дії — надійніше за
панель мережі розширення (вона починає стежити лише з першого виклику інструмента). Але
список «без змін» — доказ **лише** тоді, коли в тому ж колі є прогін, де запит зʼявився.

**Статус відповіді теж є в `performance`:** `entry.responseStatus` (Chrome) дає справжні
`200` — не треба вмикати панель мережі заздалегідь, щоб довести код відповіді.

**Три пастки харнеса, кожна вже давала хибний висновок (2026-10-02):**
- `read_console_messages` стежить **з першого свого виклику**, а `clear: true` вичищає буфер
  назавжди — усе, що було до виклику, втрачено. Для рахунку рядків перехоплювати `console`
  у сторінці або ставити слухачі через CDP `Page.addScriptToEvaluateOnNewDocument`.
- `javascript_tool` іноді віддає `[BLOCKED: Cookie/query string data]` замість результату,
  **хоч код виконався**. Не вважати збоєм: перевірити наслідок окремим коротким запитом.
- `<iframe width=390>` із `border: 1px` дає `innerWidth` **388**. Рамку робити `outline`,
  `border` — `0`, і завжди звіряти `innerWidth` ([[method-viewport-widths]]).

Межа «акаунтів не створюю, паролів не вводжу» — [[feedback-account-creation-boundary]].
