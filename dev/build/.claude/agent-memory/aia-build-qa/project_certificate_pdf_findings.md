Видача сертифіката в AIA перевірялась уперше **2026-09-05** (до того `certificates` мала
0 рядків за всю історію). Той прогін дав два дефекти в `js/certificate.js`, обидва
**платформні** — файл підключений рівно з одного місця (`certificate.html`) і спільний для
трьох курсів. Плюс третій, знайдений бекендером: **QR не працював ніколи**.

**Why:** сертифікат — єдиний артефакт, який учень виносить за межі сайту, тому ці дефекти
видно не в QA, а в реального роботодавця, який перевіряє документ.

| | Було (коло 2) | Стало (коло 3, звірено на живому файлі) |
| --- | --- | --- |
| Розмір | **28 537 699 Б** (PNG ×2) | **419 713 Б** — у 68 разів менше |
| `/DCTDecode` | 0 | **2** (обидві сторінки JPEG 0.9) |
| `/Subtype /Link` | **0** | **2** |
| `/URI` | 0 | 4 (це 2 посилання: `/S /URI` + `/URI (…)`) |
| QR | порожній квадрат 92×92 (`qrcode@1.5.3` → 404 на CDN) | є, читається jsQR |

**Клік по посиланню в PDF доведено 2026-09-05** — перший раз за історію проєкту. Обидві
області (`КОД ПЕРЕВІРКИ` + QR, і рядок надрукованого URL) ведуть на `/verify?code=…`, який
відповідає «Сертифікат дійсний». Метод — [[method-pdf-link-click-testing]].
Вміст QR = надрукований URL = обидва `/URI` = код у базі, звірено побайтово.
Колір модулів QR `#2b2620` на `#f8f4ec` — контраст **13,67:1** (чистий білий дав би 14,99).

**How to apply:** перевіряючи будь-яку майбутню правку сертифіката — дивитись **сам файл**
(`/Annots`, `/URI`, `/DCTDecode`, розмір), а не шаблон у коді. Найкрихкіше місце фіксу:
області рахуються з DOM за атрибутом `data-verify-link` у `buildCertNode()` — якщо його
приберуть при переверстці низу аркуша, посилання зникне **тихо**, без помилки в консолі.

⚠️ Сертифікат **неперевидаваний**: `maybe_issue_certificate` знімком вставляє
`profiles.full_name` через `on conflict do nothing`, політики DELETE немає. Перед прогоном,
що доходить до видачі, звіряти саме `profiles.full_name` — **не** `user_metadata.full_name`:
2026-09-05 вони розійшлися (в метаданих лежало старе імʼя), бо `auth.js` оновлює метадані
best-effort. У сертифікат іде `profiles`.
Шлях повторної видачі, коли прогрес уже 23/23: на сторінці останнього модуля кнопка стоїть
у стані «✓ Завершено» — **перший клік знімає** (`uncomplete_module`), другий видає новий
сертифікат з новим кодом. Сторінка `/certificate` видавати не вміє, тільки показує.
