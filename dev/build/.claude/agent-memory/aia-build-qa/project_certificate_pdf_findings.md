Видача сертифіката в AIA перевірялась уперше **2026-09-05** (до того `certificates` мала
0 рядків за всю історію). Той єдиний прогін дав два дефекти, обидва в
`js/certificate.js`, обидва **платформні** — код спільний для трьох курсів.

**Why:** сертифікат — єдиний артефакт, який учень виносить за межі сайту, тому ці два
дефекти видно не в QA, а в реального роботодавця, який перевіряє документ.

**Факти, зняті з реального файла (не з коду):**
- **27 МБ** на дві сторінки. Причина: `html2canvas({scale: 2})` → `toDataURL("image/png")`
  → `addImage(..., "PNG")` двічі. Поштові скриньки з лімітом 25 МБ такий файл відкинуть.
- **`/Annots` = 0, `/Link` = 0, `/URI` = 0, рядок `verify` як текст — 0 входжень.**
  URL перевірки існує **лише як піксели**. Звідси ланцюжок: не клікнути → не скопіювати →
  переписати очима → латинські `a c e i o p x y` стають кириличними → `/verify` каже
  «не знайдено» → висновок «сертифікат підроблений». Саме так і сталося з власником.

**How to apply:** перевіряючи будь-яку майбутню правку сертифіката — дивитись **сам файл**
(`/Annots`, `/URI`, `Tj`, розмір), а не шаблон у коді: шаблон виглядає правильним, бо текст
у ньому є, і саме це вводить в оману. Рішення власника 2026-09-05 — класти в усі
сертифікати пряме клікабельне посилання; у jsPDF це `doc.link(x,y,w,h,{url})` поверх
наявного зображення, без переробки рендеру.

⚠️ Сертифікат **неперевидаваний**: `maybe_issue_certificate` вставляє `full_name` знімком
через `on conflict do nothing`, політики DELETE на `certificates` немає. Тому перед будь-яким
прогоном, що доходить до видачі, — звіряти `profiles.full_name`.
