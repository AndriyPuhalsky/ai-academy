# Вікно під розширенням «сховане»: чотири прилади, що мовчки брешуть

Перевірено 2026-09-08 (задача 010, коло 2). `document.visibilityState === "hidden"` тут —
**нормальний стан**, а не помилка: після кліку в сторінку `document.hasFocus()` стає `true`,
а `visibilityState` лишається `hidden`. Вікно ще й не має реальних розмірів: `outerWidth === 0`.

**Why:** усі чотири наслідки нижче дають «дефект», якого немає, або ховають той, що є.
На кожному з них я цього дня втратив кілька викликів.

**How to apply:**

## 1. `resize_window` більше НЕ змінює вʼюпорт

`resize_window(768, 900)` повертає `Successfully resized`, але `innerWidth` лишається 1440.
`outerWidth === 0` — вікном керує не менеджер вікон. Запис у [[method-viewport-widths]] про
«працює, дно 500 px» на цю сесію **не поширюється** — перевіряти `innerWidth` після кожного
виклику, а не вірити відповіді інструмента.

**Заміна для сторінок дизайн-системи 009:** ширину контейнера задають два токени, і їх можна
підмінити прямо на живій сторінці:

```js
document.documentElement.style.setProperty('--w-prose','350px');
document.documentElement.style.setProperty('--w-narrow','316px');
window.dispatchEvent(new Event('resize'));
```

Дає `.ds-diag` clientWidth **348** — рівно як на 390 px. Без `--w-narrow` не працює:
колонка тексту `min(100%, var(--w-narrow))` тримає 672 px, і вужче 670 не стане.
Це чесніше за iframe (справжній top-level рендер), але медіа-запити лишаються десктопні —
писати це у звіті.

## 2. `setTimeout` дроселиться до 1 хв — цикли опитування голодують

Сторінка, схована > 5 хв, потрапляє під intensive throttling: `setTimeout(…,120)` спрацьовує
раз на хвилину. Цикл «чекай, поки намалюється» з бюджетом 9 с виходить **після одного сну**
і рапортує «не намалювалось» — я так отримав 97 хибних `NOSVG` зі 100.

**Заміна — сон на `MessageChannel`,** його не дроселять:

```js
const sleep = ms => { const t0 = performance.now(); return new Promise(res => {
  const step = () => { if (performance.now() - t0 >= ms) return res();
    const ch = new MessageChannel(); ch.port1.onmessage = step; ch.port2.postMessage(0); };
  step(); }); };
```

Ознака, що ти вже в цій пастці: `javascript_tool` починає падати на «CDP timed out after
45000ms» там, де щойно все встигало.

## 3. `ResizeObserver` не доставляється взагалі — і це НЕ дефект коду

RO спрацьовує наприкінці кроку рендеру, а схована вкладка рендер не виконує. Перевірено
контролем: **власний** RO на тому ж елементі дав **0 викликів за 4,5 с**, включно з
початковим. Тобто перевірити RO-гілку тут неможливо в принципі.

**Що робити замість:** перевіряти запасні шляхи, які код зобовʼязаний мати —
`window.dispatchEvent(new Event('resize'))` (спрацьовує) і `visibilitychange`. Другий у
010 захищений умовою `if (!document.hidden)`, тому в цьому оточенні **не спрацює ніколи** —
і це правильна поведінка коду, а не дефект. Так і писати.

## 4. Клавіатура: `Tab` не рухає фокус, стрілки не гортають

`computer.key` дає події, але **не типову дію**. Контроль, який це доводить: `ArrowDown`
з фокусом на `body` **не прокручує сторінку** (`scrollY` не змінився).

Але одна річ працює й дуже корисна: **програмний `el.focus()` + справжнє натискання `Tab`
вмикає `:focus-visible`** на вже сфокусованому елементі. Це єдиний спосіб зняти живе кільце
фокуса в цьому оточенні (перевірено на `.ds-diag` і на `pre.term__body`: обидва дали
`box-shadow: rgb(22,19,17) 0 0 0 2px, rgb(139,166,235) 0 0 0 4px`).
