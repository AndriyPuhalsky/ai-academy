# Накладання діаграм = колізія id за `Date.now()`

**Факт.** У `mermaid@10.9.1` (CDN, той самий файл у проді й на деві):

```js
class DRt{constructor(s=!1,u){...; this.next = s ? ()=>this.count++ : ()=>Date.now()}}
...
const _ = `mermaid-${v.next()}`;
```

`deterministicIds` у конфізі проєкту не заданий → `false` → **id = `mermaid-<Date.now()>`,
роздільна здатність 1 мс**. Генератор створюється **на кожен виклик `mermaid.run()`**.

**Why:** `js/mermaid-init.js` (з коміта `8535f0e`, 2026-09-07) викликає `mermaid.run()`
окремо на кожну діаграму й **не чекає** проміс:
`nodes.forEach(n => mermaid.run({nodes:[n]}).catch(...))`. Усі виклики доходять до рядка з id
майже одночасно. Заміряно у вкладці верхнього рівня: різниця id сусідніх діаграм
**12/2, 9/1, 14/1 мс** — тобто третя діаграма розминається з другою на 1–2 мс.
Достатньо трохи швидшої машини чи іншого планування — і id збігаються.

При збігу Mermaid малює другий граф у вже наявний `#mermaid-<ts>` → **вузли двох діаграм
лежать один на одному, решта коробок порожні**.

**How to apply:**
- Детермінований доказ без «ловіння» гонки: підмінити `Date.now` на константу й запустити
  діаграми. Відтворюється 100 %. Відновити `Date.now` одразу.
- `await` між викликами — **не виправлення кореня, а лише запас**: один рендер триває
  87–132 мс (заміряно), тож id гарантовано різні. З замороженим годинником послідовний
  прохід ламається так само.
- Справжній фікс — `deterministicIds: true` у конфізі теми, або один
  `mermaid.run({nodes: allNodes})` (як було до `8535f0e`), або власні унікальні id.
- Симптом власника «на «Вхідні токени» налазить коробка «промпт»» — це саме воно, а не
  проблема шрифтів. Пастку шрифта (`document.fonts.ready`) закрив той самий коміт, і вона
  дає лише 2–9 px обрізання, не накладання.
