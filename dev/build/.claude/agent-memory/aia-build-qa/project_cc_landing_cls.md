# Лендінг AI Термінала: CLS не лікується резервом плити

Заміряно 2026-09-08 (коло 2 QA задачі 010), власний Chrome по CDP, `layout-shift` з
`buffered: true`, по 2–3 прогони на ширину, значення відтворюються до 4-го знака.

| Ширина | ПРОД (`0.4.2`) | ДЕВ (010) | Зміна |
| ------ | -------------- | --------- | ----- |
| 320 | 0,4896 | **0,7767** | гірше |
| 390 | 0,4483 | **0,6201** | гірше |
| 768 | 0,4158 | 0,3305 | краще |
| 1024 | 0,7364 | 0,5330 | краще |
| 1440 | 0,2596 | **0,3258** | гірше |

**Why (механізм, а не симптом).** `claude-code.html:154` містить
`<h1 class="cc-hero__title" id="heroTitle"></h1>` — **порожній**, заповнює
`js/claude-code-render.js`. `min-height` = `0px`. У мить гідратації висота йде
0 → 116,6 px (1440) / 110,2 (390) / 146,9 (320), і все нижче лендінга їде вниз.

Ключове й неочевидне: **до 010 обгортка плити була НАДМІРУ висока** (`--cc-hero-reserve`
520 при фактичних 480), тож у той самий кадр вона **зменшувалась на −39,7 px і частково
гасила** стрибок заголовка. Правка Ф-Е зробила резерв правдивим (466 → 475, тобто +8,8),
і компенсація зникла. Сумарний хід вмісту: прод 116,6 − 39,7 = **76,9 px**,
дев 116,6 + 8,8 = **125,4 px**.

**How to apply:**
- Не приймати «резерв плити тепер правдивий» за закриття CLS — це різні величини.
  Міряти саме `layout-shift`, і на **всіх пʼяти ширинах**: 1024 і 768 поводяться
  інакше за 320/390/1440.
- Єдине справжнє джерело — заголовок. Фікс, який назвав Ф-Е: `min-height` у рядках на
  `.cc-hero__title:empty`, 2 рядки вище 640 px і 3 нижче; на 320 лишиться один рядок
  зсуву. Порогів у сторінки рівно пʼять, і 320 від 390 ними не відділити.
- Сторінки уроків до цього стосунку не мають: там сплеск на мобільній дає **пізня
  гідратація футера** (`FOOTER.ds-ftr`, t ≈ 1,5–4 с, ~0,20–0,25) — і в проді те саме
  (0,2963 з `FOOTER.mt-16`), тобто це не 010. Спрацьовує через раз, залежно від того,
  чи встиг футер до кінця вікна заміру.
