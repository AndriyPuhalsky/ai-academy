# Лендінг AI Термінала: CLS лікується резервом ПОРОЖНІХ елементів, і їх два

## Стан на 2026-09-08, коло 3 (коміт `298ef1f`) — ПЕРЕМІРЯНО, старі числа нижче застаріли

Прод міряний через **`ai-academy.andriy-puhalsky.workers.dev`**, не через домен —
інакше в порівняння втручається різне кешування двох хостів. По 3 прогони,
`Network.setCacheDisabled`, `PerformanceObserver` з `buffered:true`.

| Ширина | ПРОД `0.4.2` | ДЕВ `298ef1f` | CWV |
| ------ | ------------ | ------------- | --- |
| 320 | 0,0002 | 0,0003 | обидва «добре» |
| 390 | 0,0002 | 0,0003 | обидва «добре» |
| 768 | 0,4647 | **0,1194** | поганий → потребує покращення |
| 1024 | 0,7884 | **0,1832** | поганий → потребує покращення |
| 1440 | 0,2786 | **0,1135** | поганий → потребує покращення |

**Why.** У `claude-code.html` **ДВА** порожні елементи, які заповнює
`js/claude-code-render.js`: `<h1 id="heroTitle">` (рядок 154) і
`<p class="cc-hero__lead" id="heroLead">` (рядок 163). Фікс кола 2 закрив **тільки
заголовок** — `.cc-hero__title:empty { min-height: calc(2|3 * var(--cc-lh-h1) * 1em) }`.
Трасування кожного кадру на 1024 доводить, що заголовок більше не рухається взагалі
(105,9 → 105,9), а зсув дає лід: **0 → 287,2 px** (288 на 1440), плюс `.cc-hero__cta`
48 → 108. Джерела в записах `layout-shift`: `PRE.term__body` + `SECTION.cc-section`
+ `DIV.cc-hero__cta` — усе, що лежить ПІД лідом.

A/B через CSSOM (гіпотетичний `min-height` на `.cc-hero__lead:empty`, 4/6 рядків):
768/1024/1440 з 0,130 / 0,183 / 0,115 → **0,116 / 0,138 / 0,087**. Напрямок доведено,
точні рядки треба рахувати як для заголовка.

**How to apply:**
- Резерв заголовка **точний до 0,04 px** на 5 із 6 перевірених вікон (включно з
  низькими, де `max-height:700` міняє кегль). Виняток — 320: там заголовок займає
  4 рядки при резерві 3 (146,9 проти 110,16), брейкпоінта між 320 і 390 у системі немає.
  На CLS це не позначилось.
- `:empty` **діри не лишає** — після гідратації `min-height` повертається у `0px`.
  Перевірено на 9 розмірах вікна.
- ⚠ **CLS цієї сторінки бімодальний**: результат перекидається залежно від того, чи
  встигла гідратація до першого кадру. Без тротлінгу 320/390 дають ~0,000 в обох
  середовищах; під Fast-3G + CPU ×4 прод стрибає до 0,49, дев — до 0,23. Мірити
  **медіану 3–7 прогонів**, а не один прогін, і завжди обидва середовища тим самим
  інструментом в одному прогоні.
- Сторінки уроків до цього стосунку не мають — там сплеск дає пізня гідратація футера,
  і в проді те саме.
