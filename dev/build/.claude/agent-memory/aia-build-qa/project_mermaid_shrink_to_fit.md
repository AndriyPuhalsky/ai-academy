# Діаграми не скролять — вони зменшуються до нечитабельного

**Факт (заміряно 2026-09-08 на всіх 100 діаграмах, три ширини).**
`useMaxWidth: true` (у `js/mermaid-theme.js:57`, і це ще й **дефолт Mermaid** —
`flowchart:{useMaxWidth:!0}` у бандлі) робить SVG `width:100%` з `max-width`, тому широка
діаграма не викликає горизонтальний скрол, а **пропорційно зменшується**.
`.ds-diag { overflow-x: auto }` через це не спрацьовує ніколи: заміряно `scrollWidth -
clientWidth = 0` у 300 з 300 випадків.

Ширина контенту `.ds-diag`: **734 px** (вʼюпорт 1440) · 670 (768) · 316 (390).

| вʼюпорт | масштаб < 100 % | < 70 % | < 50 % | найгірша |
| ------- | --------------- | ------ | ------ | -------- |
| 1440    | 61 зі 100       | 38     | 9      | `claude-code-23#0` — 28,3 % → **4,0 px** тексту |
| 768     | 65              | —      | —      | 25,8 % → 3,6 px |
| 390     | 96              | —      | 70     | 12,2 % → **1,7 px** |

Найширші: `claude-code-23#0` (viewBox 2596 px), `claude-code-19#1` (2533),
`claude-code-21#1` (2181), `claude-code-10#0` (2050), `claude-code-15#2` (1832),
`module-12#1` (1770), `architect-08#0` (1544), `claude-code-03#0` (1532).

**Why:** це **не регресія 010**. У проді те саме: `.diagram { padding: 1.25rem; overflow-x:
auto }` усередині `.prose-aia.max-w-3xl` дає 726 px контенту (проти 734 у 010), а
`useMaxWidth` там теж чинний (дефолт). Тобто мобільні учні ніколи не бачили половини діаграм.

**How to apply:** заводити окремою задачею, не хвостом 010. Варіанти для власника:
`useMaxWidth:false` + реальний горизонтальний скрол (`.ds-diag` уже має `overflow-x:auto`
й `overscroll-behavior-x: contain`) · нижня межа масштабу · `flowchart LR→TD` для
найширших · розбити 8 найширших діаграм на дві.

Метод заміру — [[method-mermaid-mass-audit]].

## ЗАКРИТО 2026-09-08 (коло 2) — і що прийшло натомість

`useMaxWidth: false` (обидва типи) + `margin-inline: auto` на SVG. Переміряно 100 діаграм ×
320 / 390 / 768 / 1440 (400 замірів): `k = 1` скрізь, `k > 1` — **0 із 400**, накладань 0,
переливів 0, вертикального скролу в `.ds-diag` 0, розпирання документа 0 із 232 проходів.
Скролять 99 / 97 / 64 / 60; розбіжність «скролить ↔ має tabindex» — **0 на кожній ширині**.

**Три ціни, яких ніхто не міряв до мене — питати про них на наступних задачах:**

1. **Вертикальний слід виріс у 1/k разів.** Висота тепер натуральна на будь-якій ширині:
   `claude-code-10#0` — **2823 px** (було ~435 на 390). Одна діаграма = 4+ екрани.
2. **Вхідний вузол виїжджає за ліву межу.** SVG ширший за контейнер притискається вліво
   (`margin-inline: auto` → «переобмежений бокс» → авто-марджини = 0), а корінь `flowchart TD`
   стоїть посередині графа. `claude-code-23#0`: корінь на x = 1159 при видимих 734 — учень
   бачить 2 вузли з 7 і не бачить початку. Дешевий фікс — `scrollLeft` на середину при появі.
3. **Смуга діаграм у 1–16 px ширша за контент-бокс** стає ліворуч, але скрол не зʼявляється
   (правий падінг зʼїдає різницю): `architect-03#0` @768, `claude-code-08#0` @1440. Косметика.

## Ціна №2 («вхідний вузол за лівою межею») ЗАКРИТА 2026-09-08, коміт `298ef1f`

`showRoot()` у `js/mermaid-init.js`: показати верхній вузол, серед однаково верхніх —
найлівіший; рівно один раз, у мить переходу в прокрутний стан і лише поки
`scrollLeft === 0`. Переміряно **всі 100 діаграм × 1440 / 768 / 390**:

| Ширина | `.ds-diag` clientWidth | прокрутних | корінь видно |
| ------ | ---------------------- | ---------- | ------------ |
| 1440 | 766 | 57 | **100 зі 100** |
| 768 | 702 | 61 | **100 зі 100** |
| 390 | 348 | 96 | **94 зі 100** |

Шість винятків на 390 — **сам вузол ширший за колонку** (503, 538, 418, 383, 359,
357 px при 348). Код центрує його, тому обрізається **початок підпису**: на
`claude-code-06` учень читає «…ена інструментів MCP…» замість «Схема інструментів
MCP…». Заведено як D-26 (дрібний). Напрямок: не пускати `scrollLeft` далі лівої
межі кореневого вузла.

**Що ще перевірено й тримається:** позиція користувача переживає 4 послідовні resize
(1440→1200→900→390) · `scroll-behavior: auto` скрізь, `scrollLeft` змінюється за
**один кадр** із 342, `scrollY` не рухається — тобто `prefers-reduced-motion`
не порушено · після 4 resize `id` усіх SVG незмінні, тобто повторного рендеру
й нової [[mermaid-id-collision]] не виникає · `data-scrollable` ↔ `tabindex="0"`
розбіжність **0 на кожній із трьох ширин** · `role="region"` і непорожнє доступне
імʼя — **96 із 96** прокрутних на 390.
