Правило: **«я подивився, виглядає нормально» — не доказ регресії.** Коли фікс живе в
спільному CSS (у цьому проєкті `css/custom.css` — один на три курси), міряти треба A/B.

**Why:** у колі 2 задачі 005 треба було довести дві протилежні речі одночасно: що три
нові правила `overflow-wrap` **закривають** дефект на AI Терміналі і **не чіпають** AI
Академію та AI Architect. Огляд сторінок цього не доводить: якщо правило нейтральне через
збіг (у чужих курсах `.prose-aia pre` і так має `word-break: break-word`), огляд покаже те
саме, що й справжня регресія.

**How to apply:**

```js
// зняти конкретні властивості з живих правил і перезаміряти геометрію
for (const sh of d.styleSheets) { let rs; try{rs=sh.cssRules}catch(e){continue}
  for (const r of rs) if (r.selectorText === '.prose-aia code') r.style.removeProperty('overflow-wrap'); }
```

Далі порівняти `documentElement.scrollWidth` і масив висот блоків **до і після**.

- **Контроль обовʼязковий.** Той самий дослід треба прогнати на сторінці, де фікс мусить
  діяти: у 005 `c13` дав 390 → **612** без правил. Без контролю нульова різниця на чужих
  курсах читається як «інструмент нічого не міряє».
- Результат виходить числом, а не враженням: «0 блоків `pre`/`quiz-opt` зі зміненою
  висотою, `docW` без змін» — це можна покласти у звіт.
- Тим самим прийомом перевіряється hover/focus: **у фоновій вкладці CSS-переходи не
  тікають**, тому `getComputedStyle` після наведення показує старий колір. Вставити
  `*{transition:none !important}` — і цільовий стан читається одразу. Інакше пишеш хибний
  дефект «hover не працює».
