У `js/roadmap-render.js` (задача 003) лишились **дві** відомі пастки. Обидві **не
виправлені навмисно**, обидві зафіксовані у звіті фронтенду, QA попереджена не подавати їх
як дефект.

1. **Інверсія згортання квартальних груп.** `groups.forEach(function (g, gi) { … gi >= 2 … })`
   згортає групи за **індексом**. Це було правильно, поки дані йшли від найновішого; після
   реверсу порядку (рішення власника: час тече вниз) воно згортає **найсвіжіші** квартали.
   На затверджених даних у «Зроблено» рівно дві групи, тож `gi >= 2` не істинне ніколи і
   **нічого не видно**. Видно на `?data=max`: із семи груп згортаються групи 2–6, тобто й
   реальні `Q-2 2026` / `Q-3 2026`. Однорядковий фікс відомий:
   `gi < groups.length - 2`.
2. **Зворотне сортування при появі `dropped`.** Гілка, що домішує «Передумали» до
   «Зроблено», сортує обʼєднану групу за кварталом **у зворотному порядку**. Поки `dropped`
   у даних немає, сортування не викликається взагалі. Перевірено на `?data=dropped`:
   групи виходять `Q-3 2026` → `Q-2 2026`, тобто секція перевертається проти рішення власника.

**Why:** правило «латентні пастки документуємо, не виправляємо» задала коренева сесія на
етапі планування 003 — щоб перенесення макета лишалось перенесенням, а не рефакторингом.
Рішенням власника був лише реверс порядку; команди виправляти інверсію він не давав.

**How to apply:** перша ж задача, що додасть у «Зроблено» третій квартал **або** перший
реально скасований пункт, робить обидві пастки видимими — тоді це окрема задача з
рішенням власника, а не побічна правка. Не «полагодити по дорозі»: фікс змінює те, що
власник бачить, тобто вимагає його «так».
