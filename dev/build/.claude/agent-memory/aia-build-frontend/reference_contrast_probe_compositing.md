# Пробник контрасту: напівпрозорі фони компонуються від кореня вниз

**Why.** У 012 наївний пробник дав **5 «провалів»** у вікнах курсу — `win__stats li`
(ratio 1,0) і `win__btn--primary` (1,75). Жодного дефекту там не було: обидва вузли мають
**власний фон з альфою** (`rgba(240,233,223,0.05)` і `rgba(143,177,195,0.13)`). Помилка була
в пробнику: він брав фон елемента й «накладав» його на фон батька, а функція накладання
повертала альфу 1 — тож обхід уривався на першому ж предкові, і за фон вважався майже чорний
піксель. Після виправлення: **1 857 вузлів, 0 провалів, мінімум 4,78** — рівно те, що
заміряв валідатор дизайну незалежно.

**How to apply.** Правильний порядок рівно такий:

1. зібрати ланцюжок `backgroundColor` із альфою > 0 від елемента **вгору** до `<html>`;
2. узяти **непрозору** базу (фон `documentElement`; фолбек — фон сторінки з токенів);
3. фарбувати ланцюжок **у зворотному порядку** — від найдальшого предка до елемента:
   `base = f*fα + base*(1−fα)`, альфа результату завжди 1;
4. якщо `color` тексту теж має альфу — скомпонувати його **на вже отриманому** фоні;
5 WCAG-коефіцієнт рахувати на двох непрозорих кольорах.

⚠ Перевірка здоровості пробника: мінімум по курсу має зійтися з числом, яке назвав інший
інструмент. Якщо «провали» — рівно ті вузли, у яких є власна альфа, винен пробник, не код.
