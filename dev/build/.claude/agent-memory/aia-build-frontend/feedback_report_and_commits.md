**Звіт фронтендера ПИСАТИ файлом `03-frontend/report*.md` через `Write` і дублювати
повним текстом у фінальному повідомленні.** (Виправлено кореневою сесією 2026-09-10.)

**Why:** на хвилі 2 задачі 011 я не створив файл, вважаючи це забороною харнеса, — а
бекендер у тій самій хвилі записав свій `report-wave2.md` без проблем. Це була моя
обережність, не блок. Власник прямо вимагає файли-звіти від усіх агентів майстерні;
порада «не створювати документацію без прохання» не діє, бо прохання є у визначенні.

**How to apply:** структуру звіту тримати ту саму, що в описі ролі (що змінено ·
точність до макета/спеки · що вирішив сам · нові токени · нові ключі конфігів ·
що треба від бекендера · стани · що передати тестувальнику · знайдене поза
обсягом). Знімки при цьому **можна** класти файлами в `03-frontend/shots/` і
комітити — це не звіт.

**Коміт із pathspec: `git commit -F <файл> -- <шляхи>`, і `-m/-F` іде ПЕРЕД `--`.**

**Why:** усе після `--` git вважає шляхами, тож `git commit -- css/x.css -m "…"`
падає з `pathspec '-m' did not match any file(s)`. Довгі українські
повідомлення зручніше класти у файл у скретчпаді й давати `-F`.

**How to apply:** коли в дереві паралельно працює інший агент (у 011 — бекендер у
`js/module.js` і `js/certificate.js`), кожен коміт робити окремим викликом і
одразу після правки саме цих файлів: `git commit -- <шлях>` бере **робочий стан
шляху**, тож дві правки одного файла (у 011 це `css/components.css` §41.1 і §28)
не можна робити разом, якщо потрібні два коміти — спершу правка + коміт, потім
друга правка + коміт.
