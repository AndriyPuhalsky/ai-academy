# 011 · Рішення №2 — `data-page-in` на `roadmap.html`

- **Питання:** рядок 10 реєстру — `roadmap.html` єдина з 66 публічних сторінок без
  `data-page-in`. Додати чи лишити як є.
- **Джерело:** `dev/build/011-open-tails/report-2026-09-10.md`, розділ «Рішення власника,
  які потрібні», п. 2; реєстр — `task.md`, рядок 10.
- **Делеговано:** власник передав рішення PM (2026-09-10).
- **Статус:** ухвалено. **Закривається без коду** (за винятком двох рядків коментаря — див.
  «Специфікація»).
- **Метод:** не оцінка, а A/B-замір у власному Chrome 152 по CDP (рецепт стенда 011),
  локальний сервер 8311, кеш вимкнено, 3 прогони на варіант. Рецепт відтворення — у кінці.

---

## Рішення

**`data-page-in` на `roadmap.html` НЕ додається.** Рядок 10 закривається як **невірно
поставлене питання**, а не як відкладений хвіст.

Замість «одна сторінка без входу» в проєкті фіксується правило, під яке підпадають усі 66:

> **Кожна публічна сторінка має рівно ОДИН вхід.** На 65 сторінках це M1
> (`data-page-in` на `<main>`, `js/motion.js:362–363`). На `/roadmap` — власна хореографія
> задачі 003 (вхідний таймлайн у `js/roadmap-motion.js:674–712`). **Двох входів одночасно
> не буває.** `roadmap.html` — не виняток із правила, а його другий випадок.

За цим формулюванням «65 з 66» більше не існує: **входів 66 із 66**, просто на одній
сторінці він інший і кращий.

---

## Чому

### 1. Технічний аргумент початкової рекомендації — спростований заміром

Звіт 2026-09-10 радив не додавати через ризик для ScrollTrigger: «заміри геометрії змійки
відносні, але ScrollTrigger рахує від документа під час transform». **Це виявилось
неправдою.** Чесно фіксую, бо рішення не має спиратись на аргумент, який не витримав
перевірки:

| Тригер | A (як є) | B (з `data-page-in`) | Δ |
| ------ | -------- | -------------------- | - |
| №1 змійка (`js/roadmap-motion.js:714`), `trigger: #timeline` | start −8, end 3188 | start −8…−5, end 3189…3191 | **≤ 3 px** |
| №2 кінцівка (`:733`), `trigger: #outro` | start 3342, end 3612 | start 3342…3345, end 3612…3615 | **≤ 3 px** |

Причини, чому шкоди немає:
- зсув M1 — рівно **8 px** (`--p-move-card: 8`, `css/tokens.css:387`), і на момент
  створення тригерів твін уже частково відіграв, тож реальна похибка менша;
- `collectPoints()` (`js/roadmap-motion.js:191–228`) рахує **різниці** прямокутників
  (`r.left − box.left`, `r.top − box.top`), а рівномірний `translateY` предка в різниці
  скорочується — геометрія змійки до transform **байдужа за побудовою**;
- ScrollTrigger самолікується: `ScrollTrigger.refresh()` викликається на `rm:relayout`
  (`:634`) і на resize (`:643`), плюс власний автооновлювач на `load`.

**Висновок: додати було б БЕЗПЕЧНО.** Рішення «не додавати» ухвалене не через ризик.

### 2. Прецедент співіснування існує — і він працює НА це рішення, а не проти

`claude-code.html` має і `data-page-in` (`:135`), і власний рух
(`js/claude-code-motion.js`), і асинхронний `<main>`. Він у проді з 010, пройшов три кола
QA, дефекту не заводили. Заміряно: там M1 теж притемнює `<main>` на **27 кадрів ≈ 432 мс**.

Але це **не** контрприклад, бо в нього немає власного **входу**:
`build()` (`js/claude-code-motion.js:98–150`) робить рівно дві речі — M10 друк термінала
(стартує від IntersectionObserver, коли термінал видно) і M9 скрол-вісь. Жодного
вхідного таймлайна на hero там немає. **Тобто на `claude-code.html` M1 і Є входом
сторінки** — правило «один вхід» виконано.

На `/roadmap` вхід уже зайнятий:
```
js/roadmap-motion.js:674–712 — gsap.timeline():
  .rm-hl__in    yPercent 106 → 0   (рядки заголовка з-за маски, стагер 75 мс)
  .rm-eyebrow   autoAlpha 0 → 1
  .rm-hero__lead autoAlpha 0 → 1, y 18 → 0
  .rm-count__num 0 → N (M3, лічильники)
  .rm-updated   autoAlpha 0 → 1
```

### 3. Накладання — стовідсоткове, не «в гіршому випадку»

M1 не «може» накластись — він накладається **завжди**. Заміряно:

| Що | Значення (3 прогони) |
| -- | -------------------- |
| `rm:rendered` після `DOMContentLoaded` | **+1…+4 мс** |
| Прозорість `<main>` у мить, коли будується вхідний таймлайн 003 | **0** (`transform: matrix(1,0,0,1,0,8)`) |
| Скільки триває видиме притемнення | **24 кадри ≈ 360 мс** |
| Крива прозорості `<main>` після старту хореографії | +60 мс — 0 · +120 — 0,69…0,71 · +180 — 0,85…0,87 · +240 — 0,93…0,94 · +300 — 0,97 · +360 — 0,99 |

M1 триває 520 мс (`--p-dur-page-in: 520`, `css/tokens.css:372`), крива `--p-e-out`
front-loaded, тому 0,99 досягається на ~360 мс. Вхідний таймлайн 003 повністю вкладається
в це вікно.

Практичний наслідок: **найсильніший кадр сторінки грає крізь затемнення.** Фокус масок —
рядки заголовка виїжджають з-під краю **непрозорими**; помножені на батьківську прозорість
0,7 → 0,94 вони читаються як звичайний fade. Це не поламка — це заміна авторського жесту
на дефолтний. Правило власника цієї хвилі — «**не погіршувати наявний UI/UX**»; наявний
UI/UX тут — саме вхід 003.

### 4. Порожній `<main>` не є аргументом «за» — перевірено

Спокуса міркувати так: `<main>` роадмапа порожній при парсингу, значить M1 корисно
«прикриє» приїзд контенту. Точний вимір статичного тексту всередині `<main>`:

| Сторінка | Статичних символів у `<main>` |
| -------- | ----------------------------- |
| `roadmap.html` | **2** (`//`) |
| `claude-code.html` | 1 (`↻`) |
| `index.html` | 662 |
| `architect.html` | 745 |
| `verify.html` | 441 |
| `certificate.html` | 125 |

Прикриття вже є і без M1: скелет (`js/roadmap-render.js:97`, `--delay-skeleton` 150 мс)
плюс сам вхідний таймлайн. Друге прикриття зверху нічого не додає.

### 5. Єдина реальна втрата — CLS 0,0119 — це маскування, а не фікс

Заміряно на 1280×900:

| Варіант | CLS | Джерело зсуву |
| ------- | --- | ------------- |
| A · як є | **0,0119** (однаково в 3 із 3 прогонів) | один зсув на 338–509 мс, `svg#trail` |
| B · з `data-page-in` | **0 / 0 / 0,0007** | — |
| D · з `data-page-in` + `prefers-reduced-motion` | 0,0116 | той самий `svg#trail` |

Виграш **уявний**: зсув нікуди не дівається, він просто відбувається, поки шар має
`opacity: 0`, і браузер не зараховує його в метрику. Варіант D це доводить — щойно M1 не
грає (reduce), 0,0116 повертається. Ховати зсув прозорістю — прийом, який псує довіру до
власних замірів; у проєкті вже є прецедент цієї пастки (010: «правдивий резерв висоти
ПОГІРШИВ CLS», бо завищений резерв випадково гасив чужий стрибок).

0,0119 — це у **8,4 раза** нижче порога 0,1 і в **6,9 раза** менше за вже прийнятий
власником зсув 0,082 на заблокованому уроці (шосте рішення звіту).
**Окрема задача не заводиться**, число фіксується тут.

### 6. LCP не є аргументом ні за, ні проти

| Варіант | LCP-елемент | LCP після `DOMContentLoaded` |
| ------- | ----------- | ---------------------------- |
| A · як є | `P#heroLead` | +426 / +421 / +419 мс |
| B · з `data-page-in` | `P#heroLead` | +424 / +415 / +414 мс |

Різниця **≤ 12 мс, у межах розкиду між прогонами**. M1 не відкладає появу контенту, бо
`.rm-hero__lead` і так виходить власним `autoAlpha` хореографії 003 (`:685`). FCP теж не
змінюється: `.rm-head` стоїть **поза** `<main>` (`roadmap.html:74`), тому перший
контентний кадр M1 не чіпає.

### 7. Ціна «правильного» додавання — правка спільного файлу заради косметики

Щоб додати M1 і не накласти його на вхід 003, довелося б дати `js/motion.js` затримку,
виняток або подію «хореографія сторінки взяла вхід на себе». `js/motion.js` — спільний
файл **66 сторінок**; `dev/build/CLAUDE.md` прямо тримає такі файли в режимі «тільки
читання» для паралельної роботи, а зміни в них проводить коренева сесія. Платити правкою
в спільному рушії руху за косметичне вирівнювання на одній сторінці — невигідний обмін.

### 3. Критерії приймання

Перевіряються на dev-превʼю (`https://dev-ai-academy.andriy-puhalsky.workers.dev/roadmap`)
або локально. Кожен дає однозначне «так/ні»:

1. `grep -c '<main[^>]*data-page-in' roadmap.html` → **0**.
   ⚠ Шукати треба саме тег `<main>`, а не голий рядок: коментар із п. 2 сам містить слова
   `data-page-in`, тому `grep -c 'data-page-in' roadmap.html` дасть **1** і виглядатиме як
   провал там, де все правильно.
2. `grep -c '<main[^>]*data-page-in' *.html modules/*.html | grep -v ':0$' | wc -l` →
   рівно **65** (перевірено на поточному дереві), тобто рішення не зачепило жодної іншої
   сторінки.
3. `/roadmap` на 1280 px: заголовок зʼявляється **рядками, що виїжджають з-за краю маски**,
   кожен рядок непрозорий від першого кадру; сторінка **не** темніє цілком.
4. Лічильники в hero добігають від 0 до значень із `roadmap.json`; змійка заповнюється при
   прокрутці; консоль без необроблених винятків.
5. `prefers-reduced-motion: reduce` (DevTools → Rendering → Emulate CSS media feature):
   сторінка статична, **весь** текст видимий, лічильники одразу показують кінцеві числа,
   змійка намальована повністю (`staticState()`, `js/roadmap-motion.js:143`). Поведінка та
   сама, що й до рішення — M1 під reduce не грає взагалі (`js/motion.js:261`), тож ця
   перевірка ловить регресію, а не наслідок рішення.
6. `/roadmap?from=claude-code` і `/roadmap?from=architect` віддають свій бренд у `#backLabel`
   (регресійна перевірка рядка 14, який чіпав ті самі файли).

## Що НЕ робити

1. **Не додавати `data-page-in` на `<main>` `roadmap.html`** — причини вище. Якщо колись
   спробуєте «просто перевірити» — перевіряйте не скріншотом, а кривою прозорості: на
   статичному кадрі відмінності не видно взагалі, і саме тому цей хвіст прожив від 010.
2. **Не переносити атрибут на частину сторінки** (`.rm-head`, hero, футер). M1 бере
   **перший** `[data-page-in]` у документі (`js/motion.js:362`), тож технічно це працює,
   але:
   - `.rm-head` — липка шапка (`css/roadmap.css:231`); зсув 8 px на навігаційній рамці
     сайту — не той жест, який M1 описує;
   - hero — це рівно та зона, де грає вхід 003, тобто найгірший з можливих варіантів;
   - футер — нижче першого екрана, при завантаженні його ніхто не бачить;
   - і головне: на 65 сторінках атрибут стоїть на `<main>`. Атрибут на іншому елементі —
     **гірший виняток**, ніж його відсутність: `grep` показує парність, а семантика інша.
3. **Не правити `js/motion.js`** заради затримки, винятку чи події «сторінка має власний
   вхід». Спільний файл 66 сторінок, зміна руху заради косметики на одній.
4. **Не «лагодити» CLS 0,0119 прозорістю.** Якщо колись візьметесь за цей зсув — лікувати
   треба резерв висоти `svg#trail` до рендеру, а не приховування шару. Число нижче порога,
   задача не заводиться.
5. **Не поширювати виняток на нові сторінки.** Дефолт — `data-page-in` на `<main>`.
6. **Не переписувати `js/roadmap-motion.js` «по дорозі».** У файлі живуть пʼять регресійних
   фіксів, невидимих і в коді, і на скріншоті (перенесення прогресу змійки на нові вузли —
   `:460–475`; `rebindPulse` — `:477–491`). Повторний імпорт макетного `_base/motion.js`
   поверне дефект D-01 задачі 003.

## Рецепт відтворення заміру

Стенд і клієнт CDP — уже в репозиторії: `dev/build/011-open-tails/stand/cdp.mjs`,
запуск Chrome — `stand/README.md`. Варіант «B» отримується **без правки файла**:
ін'єкцією атрибута на `document_start`, до того як `js/motion.js` прочитає документ.

```js
// Page.addScriptToEvaluateOnNewDocument — ставить атрибут під час парсингу,
// тобто раніше за init() у js/motion.js (він чекає DOMContentLoaded).
const INJECT = `(function(){var t=setInterval(function(){
  var m=document.querySelector('main#main');
  if(m){m.setAttribute('data-page-in','');clearInterval(t);}},1);})();`;
```

Знімалось: прозорість `<main>` у слухачі `rm:rendered`, зареєстрованому на `document_start`
(він спрацьовує **раніше** за слухач `js/roadmap-motion.js:620`, бо реєструється першим —
для події на самому `document` порядок реєстрації важливіший за фазу); крива прозорості
через `requestAnimationFrame`; `ScrollTrigger.getAll()` після осідання; `layout-shift`,
