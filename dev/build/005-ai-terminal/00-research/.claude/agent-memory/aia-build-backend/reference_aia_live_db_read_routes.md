Тулсет підагента фіксується в момент запуску. Якщо власник автентифікував Supabase MCP
вже після старту сесії, підагент бачить лише `mcp__supabase__authenticate` — робочих
інструментів немає, і повторний виклик не допоможе. Порядок запасних шляхів:

1. **Dashboard через `mcp__claude-in-chrome`** — найкращий. Код функцій:
   Database → Functions → клік на імені (панель `Edit`, читати, виходити через **Cancel**).
   Монако віртуалізує рядки: колесо доскролює лише частину, далі клік у редактор і
   `PageDown` (навігація нічого не змінює). Унікальні обмеження всіх таблиць одним
   екраном — Database → **Indexes**. RLS — Database → Policies → Edit policy (там видно
   `using (...)`). Дефолти колонок — Database → Tables → `View columns` → `Edit`.
   `get_page_text` бачить лише `<main>`, тому бічні панелі треба знімати скріншотом.
2. **PostgREST з `anon`-ключем із `config.json`** — швидка звірка схеми без Dashboard:
   `?select=<колонка>&limit=0` дає 200/400 на існування колонки без жодного рядка даних;
   `?<колонка>=eq.__bogus__` показує в помилці ім'я типу (в т.ч. enum) і дозволяє
   перебором з'ясувати допустимі значення; `?select=inne_table(id)` підтверджує наявність
   FK через embedding. Корінь `/rest/v1/` (OpenAPI) закритий — потребує service_role.
3. **`javascript_tool` до api.supabase.com** — не працює: cookie-сесії Dashboard мало,
   потрібен bearer, а читання чужого токена — не наша справа.

**Чого не робити:** вхід у Dashboard я виконати не можу (введення пароля заборонене) —
якщо показало екран Sign in, це стоп і питання власнику. SQL Editor не відкривати:
навіть `SELECT` там за крок від «Run» на чомусь, що пише. `Save function` / `Save policy` /
`Save` у колонках — ніколи.
