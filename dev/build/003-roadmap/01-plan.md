## Відкриті питання до власника

1. **[неблокуюче] Реверс порядку перевернув логіку згортання квартальних груп.**
   `render.js:315` згортає групу за індексом: `quarterGroup(g, gi >= 2, …)`. Це було
   правильно, поки дані йшли від найновішого; тепер дані йдуть **від найстарішого**, тому
   `gi >= 2` згортає **найсвіжіші** групи, а найстаріші лишає розкритими. На затвердженому
   контенті в «Зроблено» рівно дві групи, тож **сьогодні це не видно взагалі**; побачиться
   в день, коли зʼявиться третій квартал.
   Однорядковий фікс (згортати за віком, а не за індексом):
   `groups.forEach(function (g, gi) { body.appendChild(quarterGroup(g, gi < groups.length - 2, c, gi)); });`
   — при двох групах `gi < 0` ніколи не істинне, тобто **фікс доказово нічого не змінює
   на поточних даних**.
   **Мій дефолт: не виправляти зараз** — так само, як власник вирішив щодо пастки
   `dropped`-сортування (див. ризик Р-2). Фронтендер фіксує це у звіті, QA не подає як
   дефект. Якщо власник скаже «так» — це буде **друга** правка проти макета, і її треба
   назвати у звіті окремо.

2. **[неблокуюче] Чи лишати на публічній сторінці сценарні перемикачі URL**
   (`?data=min|max|empty|empty-progress|dropped|nodate`, `?fail=1`, `?slow=1`, `?links=1`).
   `SUMMARY.md` §2.3 каже «параметри в код не їдуть, але код, який їх обслуговує, лишити».
   Практична вага: **критерії приймання 7, 14, 15, 18 і поведінка `copy.noDate`
   перевіряються тільки ними** — QA має єдиний інструмент (браузер на dev-превʼю) і не
   має права правити `roadmap.json`. Ризик: `inflate()` у макеті вигадує правдоподібні
   пункти («Темна й світла тема» як *зроблене*), і публічний URL показував би несправжні
   твердження про продукт.
   **Мій дефолт: лишити перемикачі, але вичистити вигадане** — `inflate()` клонує реальні
   пункти з префіксом `[тест]` (точний код у F5.4), `?data=dropped` показує нейтральний
   `[тест] Скасований пункт`, плюс новий `?data=nodate` (прибирає поле `date` з останнього
   пункту «Попереду» — нічого не вигадує). Тоді на публічній сторінці немає жодного
   несправжнього твердження, а QA має чим перевірити масштаб.

3. **[неблокуюче] `#footerMeta` (версія платформи + дата з `config.json`) на спільній
   сторінці.** Якщо лишити, на одному екрані буде дві різні дати «оновлено»: hero скаже
   `оновлено 26 серпня 2026` (з `roadmap.json`), футер — `v0.2.0 · оновлено 25 серпня 2026`
   (з `config.json`, версія саме Академії, хоч сторінка спільна).
   **Мій дефолт: на `roadmap.html` `#footerMeta` не виводити** — нижній рядок футера
   лишається «Зроблено спільнотою · Нагору ↑». Дата роадмапу вже є в hero. Наявні сторінки
   не чіпаємо.

4. **[неблокуюче] Слот авторизації в шапці роадмапу.** У проєкті вже є обидва прецеденти:
   `certificate.html:47` має `#aiaAuth` (сторінка персональна), `verify.html` не має нічого,
   крім логотипа й «До курсу →» (сторінка публічна).
   **Мій дефолт: слоту авторизації немає** — роадмап публічний і безособовий, шапка як у
   макеті: бренд «AIA · Роадмап» + «← До AI Академії / До AI Architect» за `?from=`.
   Наслідок: `js/auth-ui.js` і `js/auth.js` на цій сторінці **не підключаються взагалі**.

5. **[неблокуюче] Версії платформ і `site.updated` при мержі в `main`.**
   **Мій дефолт: фронтендер їх не чіпає.** Пропозиція власнику на момент мержу: `version`
   `0.2.0 → 0.3.0` (`config.json`) і `1.1.0 → 1.2.0` (`architect.config.json`), `updated` —
   дата релізу в обох, і синхронно `meta.updated` / `meta.updatedLabel` у `roadmap.json`.

6. **[неблокуюче] `text-faint` (#7A7164, 3.57:1) у футерах наявних сторінок.**
   У футері `index.html:210,218,227` і `architect.html:195,204,213` надзаголовки колонок і
   нижній рядок пофарбовані в `text-faint` — це той самий провал AA, який критерій приймання
   4 забороняє на роадмапі. На `roadmap.html` беремо `text-muted` (як у макеті), тобто
   футер роадмапу буде на 3 елементи контрастніший за футер головної.
   **Мій дефолт: наявні дві сторінки не чіпати** (це не наша задача і це видима зміна) —
   виносимо в борг доступності, поруч із задачею 004.

7. **[неблокуюче] Пʼять «мертвих» токенів руху.** У блоці 2 `tokens.css` є пʼять токенів із
   нульовим використанням у самому макеті: `--c-node-core`, `--dur-state` (M12),
   `--dur-expand`, `--dur-page-in` (M1 — `@view-transition` прибраний), `--delay-outro`.
   **Мій дефолт: перенести всі як є, з коментарем `/* оголошений, поки не використовується */`.**
   Причина: три з них перелічені в `reduced-motion`-блоці, а критерій 12 перевіряється
   механічно — «кожен новий токен присутній у блоці». Викидати їх = розсинхронити план,
   макет і критерій заради ~150 байтів.

## Контракт даних

Бекенду в задачі немає, тому контракт односторонній: **`roadmap.json` ↔ `js/roadmap-render.js`**.
Це закон для фронтендера і предмет перевірки для QA.

### 1. Файл `roadmap.json` (корінь сайту, віддається як статичний asset)

```
{
  "_note":  string   — службовий коментар для власника, НІКОЛИ не рендериться
  "meta":   { "updated": "YYYY-MM-DD", "updatedLabel": string }
  "copy":   { … 27 ключів, див. таблицю 3 }
  "links":  { "github": string, "telegram": string }   — порожній рядок = канал зникає
  "items":  [ { id, state, title, description?, date?, platform } ]
}
```

Тип запиту: `fetch("roadmap.json", { cache: "no-store" })`, `render.js:71–74`. Помилка HTTP
або невалідний JSON → екран помилки (див. таблицю 4).

### 2. Поля пункту `items[]`

| Поле | Тип | Обовʼязкове | Значення | Приклад |
| ---- | --- | ----------- | -------- | ------- |
| `id` | string | так | ASCII, нижній регістр, kebab-case. Стає `id` елемента `<li>` і фрагментом URL (`roadmap.html#google-auth`). Мусить бути унікальним і не збігатися з наявними id сторінки (`top`, `main`, `trail`, `timeline`, `sections`, `outro`, `axisProbe`, `heroTitle`, `heroLead`, `heroCounts`, `heroUpdated`, `heroEyebrow`, `backLink`, `backLabel`, `ariaLive`, `contactTrigger`, `outroContact`, `sec-done`, `sec-progress`, `sec-ahead`, `grp-0…`) | `google-auth` |
| `state` | enum | так | `done` \| `progress` \| `ahead` \| `dropped`. `dropped` у даних **не подавати** (рішення 7.3) | `done` |
| `title` | string | так | Назва пункту. Рендериться як `h3`/`h4` — рівень задає код, не дані | `Вхід через Google одним натисканням` |
| `description` | string | **ні** | Немає → рядок без опису (композиція це витримує, перевірено в макеті) | `Вхід без окремого пароля…` |
| `date` | string | **ні** | Рівно формат `Q-<1..4> <YYYY>`. Немає → рендериться `copy.noDate` («пізніше»). Регулярка коду: `/Q-(\d)\s+(\d{4})/` у `quarterKey()` і `isoFromQuarter()`; інший формат ламає групування (`quarterKey` → −1) і `datetime` | `Q-3 2026` |
| `platform` | enum | так | `academy` \| `architect` \| `both` → мітка форми з двох комірок + текст із `copy.platformLabels` | `both` |

**Порядок елементів у масиві — від найстарішого до найновішого** (рішення власника
2026-08-26): час на сторінці тече вниз. Порядок показу секцій задає код
(`VIEW_ORDER = ["done","progress","ahead"]`), порядок **усередині** секції — це порядок даних.

### 2.1 Ідентифікатори 18 пунктів — беруться звідси, не вигадуються

Тексти (`title`, `description`) — **побайтово з `content.md`** (апостроф там `U+0027` `'`,

### 4. Помилки й те, що бачить людина

| Ситуація | Умова в коді | Що на екрані | Що в консолі |
| -------- | ------------ | ------------ | ------------ |
| `roadmap.json` недоступний (404/500/невалідний JSON/офлайн) | `load()` reject | `.rm-panel[role=alert]`: «Не вдалося завантажити план розвитку» + текст + кнопки «До курсу» (`index.html`) і «Написати нам». `html.rm-error` → hero і кінцівка `display:none`, рух не запускається взагалі | `console.warn("[roadmap] дані не завантажились:", …)` |

### Дефолтний набір, який перевіряється завжди

- **Порожньо:** `?data=empty` → екран `copy.emptyTitle`; `?data=empty-progress` → секція
  «В роботі» не зникає, доказ життя переїжджає на `.rm-void`.
- **Завантаження:** `?slow=1` → скелетон hero і 6 рядків, футер за межами вікна, приход
  даних не смикає layout.
- **Помилка:** `?fail=1` → панель `role="alert"`, hero і кінцівка сховані, рух не грає,
  кнопки «До курсу» і «Написати нам» працюють.
- **Дуже довгий український текст:** найдовші реальні рядки — назва «Третя платформа:
  програмування з AI-ментором» і опис до неї (167 символів); перевірити
  `document.scrollWidth === innerWidth` на 390px і що мета-колонка не налазить на текст.
  `hyphens: auto` дає переноси на кирилиці («прив'я-зані») — **очікуваний вигляд**, рішення 7.2.
- **Один проти двадцяти:** `?data=min` (3 пункти) і `?data=max` (40) — рівно 2 ScrollTrigger
  в обох.
- **Мобілка ≤640 / планшет 768–834 / десктоп 1440:** липкий заголовок секції вимкнений
  ≤640 і при `max-height: 700px`; мета-колонка переїжджає під текст ≤1023; кнопка «#»
  завжди видима на дотикових (`@media (hover: none)`).
- **Низький вʼюпорт:** 1280×653 і 1366×653 — критерій 20; 1440×900 — критерій 21.
- **Залогінений vs незалогінений:** на роадмапі стану авторизації немає взагалі (питання 4),
  тобто сторінка виглядає однаково; перевірити, що вхід на `index.html` після переходу
  туди-назад не зламався.
- **Подвійний клік і повторна відправка:** двічі по «#» (двічі оголошення, без винятків);
  двічі по «Написати нам» (модалка одна, `buildModal()` має захист `if (modalEl) return`);
  двічі по кнопці згортання групи (`?data=max`).
- **Відсутня мережа:** офлайн → екран помилки даних; GSAP CDN заблокований (DevTools →
  block request URL) → сторінка читабельна, змійка підсвічена цілком, лічильники фінальні.
- **`prefers-reduced-motion`:** системне налаштування (не емуляція) → 0 ScrollTrigger,
  0 циклів, усі рядки видимі.
- **Клавіатура й фокус:** `Tab` від `.skip-link` до кінця сторінки; фокус на рядку робить

- **Специфічне для цієї задачі:** `?from=architect` (шапка, футер, посилання назад) ·
  перехід із футера `architect.html` без параметра (працює евристика по `document.referrer`) ·

## Критерії приймання

Нумерація 1–19 **збережена з §8 `SUMMARY.md`** — дизайн, план і QA говорять одними
номерами. 20–35 додає цей план.

### Доступність і контраст

1. Точка входу у футері обох платформ досяжна `Tab`, контур `2px #D97757` з offset 3px не
   обрізається предками, ціль дотику ≥44px по висоті.
2. Усі цілі дотику ≥24×24: `.rm-entry` (≈149×44), `.rm-cta` (≈143×44), `.rm-back` (≈133×44),
   `.rm-row__link` (32×32).
3. Три стани розрізняються ≥2 незалежними засобами, і жоден із них не колір. Перевірка —
   скріншот у градаціях сірого + сторінка з вимкненою анімацією. Очікувано чотири засоби:
   форма лінії · накреслення хайрлайну (суцільний / заливка / пунктир) · кегль і вага ·
   щільність.

   футер роадмапу: там `text-muted`, не `text-faint`).

9. **`#7A7164` (`text-faint`, `--c-faint`) у `color` — нуль елементів** на новій сторінці.

### Тестувальнику

**Де найімовірніше зламається** (у порядку спадання ймовірності):

1. **Регістр шляхів на Cloudflare.** Пʼять нових файлів; локально все працює завжди.
   Починати з `curl`-таблиці F11 — це дешевше за все інше й уже раз ламало прод.
2. **M7 після `resize`** (пастка 6.1). Особливо **на реальному телефоні**, де адресний
   рядок згортається при першому скролі — саме там єдиний доказ життя сторінки колись
   умирав назавжди. Не емуляція, а справжній пристрій.
3. **Кількість ScrollTrigger на масштабі.** `?data=max` (40 пунктів) + розгортання групи +
   `resize` → усе одно рівно 2. Якщо стане більше — це архітектурна регресія, не дрібниця.
4. **Регресія на `index.html` / `architect.html`** через правку двох спільних JS-файлів
   (критерій 28). Модалка «Написати нам», `<title>`, слот авторизації, футер.
5. **Стиснений hero** на 1280×653 і 1366×653 — критерій 20; і що на 1440×900 hero
   **не** змінився — критерій 21. Обидва скріншотами.
6. **`prefers-reduced-motion` системним налаштуванням**, не емуляцією: 0 тригерів,
   0 циклів, нуль прихованих рядків, довжина тексту та сама.
7. **Порядок і групи**: критерії 23–25. Два підзаголовки, «2 пункти» / «4 пункти», жодної
   кнопки згортання, лічильники 6/2/10.
8. **Lighthouse і axe у DevTools на готовій сторінці** (§9.6 `SUMMARY.md` — з пісочниці
   дизайну це було недоступно). Мінімум: Accessibility без помилок рівня A/AA, дерево
   заголовків без стрибків, контраст без зауважень. Числа — у звіт.

**Чого НЕ подавати як дефект** (усе це — рішення власника або відомі питання):
зростання футера на +64px (7.1) · переноси «прив'я-зані» (7.2) · формат `Q-3 2026`, не
`Q3 2026` (7.5) · відсутність кнопки «#» у «Зроблено» (7.4) · відсутність карток і рамок ·
інверсія сортування при `?data=dropped` (Р-2) · інверсія згортання груп на `?data=max`
(Р-3) · `copy.noDate`, `groupCount[0]`/`[2]`, стан `dropped` — неперевірені на живих даних
за конструкцією · відсутність слота авторизації в шапці (питання 4) · відсутність
`#footerMeta` у футері роадмапу (питання 3) · різний `viewport` роадмапу й решти сторінок
(Р-10, задача 004).

**Свобода, якої в цій задачі більше, ніж завжди:** сторінка **не пише в базу нічого** —
ні реєстрацій, ні квізів, ні сертифікатів. Єдина дія, що йде на сервер, — надсилання форми
«Написати нам» (як і на решті сайту): її можна перевірити один раз, із вигаданим текстом,
і зафіксувати, що повідомлення створене свідомо тестом.
