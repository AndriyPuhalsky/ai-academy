**Правило: будь-який клас, який код підставляє з JS, перевіряти ґрепом по всіх HTML.
Нуль входжень = Tailwind CDN згенерує правило вже ПІСЛЯ вставки, і це зсув.**

**Why:** проєкт тягне Tailwind з CDN (JIT у браузері). CDN генерує правила лише для класів,
які вже бачив у DOM. Клас, що зʼявляється тільки при рендері з JS, десятки мілісекунд не має
стилю. Тричі підтверджено вимірюванням 2026-09-06 (006):
· `sm:not-sr-only` у пілюлі прогресу — 53 мс без стилю, шапка зсунута на 64,8 px (дефект
D-02, полагоджено власним класом `.navprog-label` у `css/custom.css`);
· модалка `js/contact.js` у момент вставки — `position: static`, `z-index: auto`, без фону,
1440×394, `top: 4414,5` замість `fixed / z-60 / inset-0 / 1440×709 / top 0`. Тобто на перше
відкриття 394 px нестилізованої форми лягають у кінець потоку документа. Живе в проді з 003;
· `#syllabusList` на `/` — 2337 px у колбеку вставки проти 2009 px після генерації правил
(перша картка 377,5 → 321,5). Живе з початкового коміту.
Разом ~28 утиліт приходять у DOM тільки з JS.

**How to apply:**

1. Ґреп-скрипт (python, ~20 рядків): витягнути токени з `class="…"`, `className=`,
   `classList.add/toggle/remove` у `js/*.js`; порахувати кожен у конкатенації **всіх**
   HTML (корінь + `modules/`). Нуль = ризик. Кастомні класи (`cc-*`, `snav-*`, `aia-*`,
   `quiz-*`, `is-*`) відсіювати — вони мають правила у справжніх CSS-файлах і JIT їх не
   стосується; лишаються самі Tailwind-утиліти.
2. Підтвердити заміром, а не лише ґрепом: `MutationObserver` на контейнері, зняти геометрію
   **всередині колбека мутації** і ще раз через ~1 с. Різниця = зсув. Метод працює й у
   hidden-вкладці (див. [[method-hidden-tab-limits]]).
3. Ліки, які проєкт уже прийняв: власний клас у `css/custom.css` з дослівними деклараціями
   Tailwind (так зроблено для `.navprog-label`: база = `sr-only`, `@media (min-width:640px)`
   = `not-sr-only`). Брейкпоінт мусить збігатися з тим, на якому стоїть резерв ширини.

Див. [[project-recurring-defect-classes]], [[method-cls-measurement]].
