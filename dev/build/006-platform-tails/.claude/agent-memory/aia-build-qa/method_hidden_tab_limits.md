**Першим ділом у прогоні перевіряти `document.visibilityState`.** Якщо `"hidden"` — анімацію
й таймінги в цьому прогоні довести неможливо, і це треба писати у звіт одразу, а не після
години спроб.

**Why:** 2026-09-06 (006, коло 2) вкладка віддавала `hidden` при живому `document.hasFocus()`.
Наслідки, які виглядають як дефекти сайту, але ними не є: `requestAnimationFrame` не
спрацьовує взагалі (виклик `javascript_tool` відпадає по таймауту CDP на 45 с);
`setTimeout(fn, 30)` виконується через ~1000 мс (клемпінг); CSS-переходи не просуваються —
`getComputedStyle` показує стартове значення нескінченно, і **не спрацьовує жодна** подія
`transitionrun` / `transitionstart` / `transitionend`. Я витратив три виклики на «чому
шторка не їде», перш ніж зрозумів, що це середовище, а не CSS.

**How to apply:**

- Розпізнавання за один виклик: `{vis: document.visibilityState, hidden: document.hidden}`.
  Другий доказ, якщо треба в звіт: 10 разів `await new Promise(r=>setTimeout(r,30))` з
  замірами `performance.now()` — інтервали ~1000 мс замість ~30.
- **Що все одно доводиться в hidden-вкладці:** геометрія, computed styles, `elementFromPoint`
  (порядок накладання), дерево доступності, мережа, консоль, скріншоти, payload запитів.
  Тобто вся матриця, крім руху.
- **Справжній клік мишею короткочасно будить рендер.** Схема, яка дала кінцевий стан шторки:
  `computer.left_click` по кнопці → `computer.screenshot` (примушує малювання) → аж потім
  `javascript_tool` із замірами. Якщо міряти без кліку (програмний `.click()`), `transform`
  назавжди лишиться `-300` і виглядатиме як «шторка не відкривається».
- У звіті писати чесно: «кінцевий стан доведено, рух — ні, перевірити може лише людина у
  відкритому вікні». Не видавати кінцевий кадр за анімацію.
