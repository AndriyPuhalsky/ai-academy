## Чому саме так — числа, а не думки

A/B на стенді (Chrome, шрифти сайту, Mermaid 10.9.1). Стенд валідний: варіант D дав
рівно **2596 px** — те саме, що QA заміряв на живому `claude-code-23`.

| Варіант | Ширина | Підпис |
| ------- | ------ | ------ |
| A · як зараз (`architect-02`) | 195 px | злиплий, один рядок |
| B · `htmlLabels: false` | **195 px** | **два рядки, читається** |
| C · текст одним рядком (перша ідея власника) | **276 px** (+42 %) | читається, один рядок |
| D · `claude-code-23` як зараз | **2596 px** | один рядок |
| E · `claude-code-23` + переноси + `htmlLabels: false` | **1624 px** (−37 %) | два рядки |

**Висновок, що змінив рішення:** варіант «розтягнути одним рядком» лагодить читабельність,
але **розширює діаграму на 42 %** — тобто працює проти скролу, який ми щойно ввели.
`htmlLabels: false` дає те саме безкоштовно (195 → 195) і не чіпає жодного тексту.

**Друга знахідка, що спростувала звіт Ф-Е:** теза «злиття рядків роздуває найширші
діаграми» на фактах не підтвердилась. У восьми найширших `<br/>` майже немає — одна штука
на всі вісім (`architect-08`). Вони широкі тому, що підписи справді довгі: 63, 82, **97**
символів в один рядок. Отже, щоб їх звузити, потрібна дія **протилежна** до «одним рядком»:
розбити довгі підписи на рядки.

## Що робити

### 1. `htmlLabels: false` — один рядок конфігу

`js/mermaid-theme.js`, поруч із `useMaxWidth: false`. Лагодить **58 переносів у 19 файлах**
одразу; `securityLevel: "strict"` лишається — HTML у підписах як не використовувався, так і
не використовується.

⚠ **Ціна:** підписи почнуть малюватись SVG-текстом замість HTML. Треба переглянути очима
всі 100 діаграм — шрифт, вирівнювання, кольори, `class hl`.

### 2. Надійність рендера — `render()` замість `run({nodes})`

Симптом: `data-processed="true"`, `<svg>` немає, `.ds-diag__fallback` **мовчить** — учень
бачить порожнє місце. Частота: у Chrome ~1 на 20 завантажень (Ф-Е), у Safari 26.5.2 —
**100 %** (коренева сесія; прод у тому ж Safari малює все, тобто це регресія міграції 010).

Рішення назвав сам QA у звіті кола 1: `await mermaid.render("aia-diag-" + i, src)` із
власним лічильником. Воно прибирає колізії id **конструктивно**, а не запасом у часі
(зараз захист тримається на тому, що послідовні виклики дають Δ id 86–131 мс), і дає
контроль над випадком «svg порожній» — саме там, де зараз fallback не спрацьовує.

Гіпотезу «контейнер прихований у мить рендеру» перевірено й **відхилено**: на `module-01`
у Safari `main > [hidden]` = 0, контент був видимий, а `<svg>` усе одно не зʼявився.

### 3. Переноси у восьми найширших — 47 підписів

Зібрано з коду; довші за 40 символів, без наявного `<br/>`:

| Сторінка | Підписів > 40 | Найдовший |
| -------- | ------------- | --------- |
| `claude-code-19` | 13 | 82 симв |
| `claude-code-15` | 8 | 65 |
| `claude-code-21` | 7 | 67 |
| `claude-code-23` | 6 | 63 |
| `claude-code-10` | 5 | **97** |
| `claude-code-03` | 5 | 62 |
| `module-12` | 3 | 59 |
| `architect-08` | — | (єдиний `<br/>` з восьми) |

Робить коренева сесія: це не додавання змісту, а розстановка розривів у наявному тексті —
по природних точках (`·`, `—`, `:`, кома), рядки приблизно рівні за довжиною.

### 4. Підказка горизонтального скролу

**Рішення власника: робимо без макета**, попри правило «новий елемент — через бриф».
Обмеження, які я на себе беру: жодного нового кольору, тільки токени; один патерн на
**всі шість** скролерів системи (`.ds-diag`, `.ds-tbl__wrap` × 111, термінали × 101,
`components.css:611`, `:675`, `:1043`), а не окремий для діаграм.

Механізм — чистий CSS, без JS: чотири фонові шари, з яких «прикриття» стоїть на
`background-attachment: local`, а «тінь» — на `scroll`. Наслідок: тінь видно лише тоді,
коли є куди гортати, і вона зникає на кінці — сама, без жодного слухача подій. Тінь
будується `color-mix()` від `--c-bg`, тобто лишається похідною від токена.
