# Продуктовий відділ AIA — агенти й навички

Шість агентів-сеньйорів. Ви — Head of Product, вирішуєте ви. Агентів кличе продакт-лід
(сесія Claude Code, запущена **з `dev/product/`**) — достатньо сказати, наприклад:
«запусти `pm-researcher` на ідею X» або «нехай `pm-critic` подивиться задачу 013».
Список агентів у сесії — команда `/agents`. Правила відділу — `CLAUDE.md`, журнал —
`JOURNAL.md`.

Кожен агент пише **лише свій файл** у папці задачі `NNN-slug/` і повертає коротке
повідомлення з висновком і питаннями до вас. Модель — Opus, зусилля `xhigh`, памʼять
своя (`.claude/agent-memory/<агент>/`, приватна).

## Команда

| Агент | Роль | Коли кликати | Пише |
| ----- | ---- | ------------ | ---- |
| `pm-researcher` | Дослідник (discovery) | Перший крок нової ідеї чи курсу; конкуренти, персони, план інтервʼю | `01-discovery.md` |
| `pm-strategist` | Стратег | «Чи робити і скільки»; метрика успіху, пріоритет, роадмап, OKR | `02-strategy.md` |
| `pm-spec` | Специфікації | Після рішення: PRD, сценарії, критерії приймання, чернетка брифа | `03-prd.md`, `task.draft.md` |
| `pm-learning` | Методист | Будь-який курс до написання уроків: результати, програма, квізи | `04-program.md` |
| `pm-growth` | Ріст і запуск | Позиціонування, тексти лендінга, канали, онбординг, донати | `05-launch.md` |
| `pm-critic` | Незалежний критик | Перед **кожною** передачею в дизайн і перед великим рішенням | `06-review.md` |

Після `pm-learning` уроки пишуть агенти конвеєра контенту — `aia-content-author`,
`aia-content-reviewer`, `aia-quiz-editor`. Їхні визначення лежать у `dev/build/` і тут
не дублюються.

## Навички кожного агента

Усі скіли завантажуються агентові в контекст повністю на старті (`skills:` у його файлі).
Головна сесія відділу теж їх бачить і може використати напряму.

### `pm-researcher` — 7 скілів
| Скіл | Що дає |
| ---- | ------ |
| `continuous-discovery` | Метод Терези Торрес: дерево можливостей і рішень, мапа досвіду, короткі підсумки інтервʼю, матриця «важливість × докази» для припущень |
| `jobs-to-be-done` | Формула «роботи», функціональні, емоційні й соціальні виміри, сили, що штовхають до зміни, інтервʼю про перехід, «нічого не робити» як конкурент |
| `mom-test` | Правила інтервʼю, у яких люди не можуть вам збрехати: питання про минулий досвід, а не про «чи купили б ви» |
| `customer-research` | Пошук сигналів у спільнотах (Telegram, DOU, коментарі YouTube) з рівнями впевненості; персони з непрямих джерел; опитування на відповідність продукту ринку (PMF) |
| `synthesize-research` | Тематичний аналіз, групування спостережень за схожістю (affinity mapping), звіряння кількох джерел, пастки опитувань (зсув вибірки, середнє проти розподілу) |
| `survey-design` | Порядок і формулювання питань, шкали (Лайкерт, NPS, SUS), розмір вибірки, пілот |
| `competitive-brief` | Конкурентне поле (прямі, непрямі, замінники), матриця можливостей, прогалини в позиціонуванні |

## Як додати скіл

1. Знайти: `npx skills find <запит>` або skills.sh. Перевірити кількість встановлень, зірки,
   **ліцензію** (`gh api repos/<owner>/<repo> --jq .license.spdx_id`) і **прочитати
   `SKILL.md` повністю**. Скіл із `disable-model-invocation: true` агентові передати не
   можна.
2. Встановити **з `dev/product/`**: `npx skills add <owner>/<repo> -s <скіл> -a claude-code -y`.
   **Ніколи `-g`**, бо глобальний скіл зʼявиться в усіх сесіях.
3. Ліцензія: MIT / Apache-2.0 → текст у `.claude/skills/_licenses/` і рядок в
   `.claude/skills/ATTRIBUTION.md`. Без ліцензії чи некомерційна (CC BY-NC) → лише в
   `.gitignore`, бо репозиторій публічний.
4. Додати назву в `skills:` потрібного агента й рядок у таблицю вище.
5. Запис у `JOURNAL.md`, коміт у `dev`.

Оновлення (`npx skills update`) робимо лише свідомо: скіл — це інструкції, що діють від
імені агента, тож нову версію перечитуємо так само, як нову.

  (`mattpocock/grill-me`, `asmartbear/asb-*`), або самі запускають агентів (`council`,
  `roast`).
- **Порада для конвеєра контенту:** правила `hinge-question-designer` варто колись віддати
  й `aia-quiz-editor`. Він зараз вирівнює лише довжину варіантів, а цей скіл робить кожну
  хибну відповідь осмисленою.
