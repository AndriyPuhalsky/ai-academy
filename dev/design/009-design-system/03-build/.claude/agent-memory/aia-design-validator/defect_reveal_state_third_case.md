Клас дефектів «елемент лишається невидимим назавжди» зустрівся втретє поспіль
(003 D-01 → 005 Б-01 → 009), і щоразу з іншої причини. Причина 009 нова й найпідліша:
**свіжий `IntersectionObserver` може не доставити ЖОДНОГО колбека** на елемент, який
фізично видно на екрані. Chrome не доставляє IO у вкладку, яка не рендериться (фон,
оклюзія, headless без скрінкасту). Виміряно в живому Chrome: елемент на 315 px у вікні
709 px — нуль колбеків; 2 з 5 щойно створених карток лишились невидимими.

**Лікування, яке справді закриває клас (обидві половини потрібні):**
1. *Білдер:* стан спокою `[data-reveal]` — ВИДИМИЙ (`opacity: 1`). Ховає тільки JS і
   тільки після того, як спостерігач приєднано. `bind()` не ховає те, що вже у вʼюпорті.
   Наслідок: JS не завантажився, впав або стоїть `reduce` — контент видно.
2. *Валідатор (009):* `bind()` додатково ПІДМІТАЄ вузли, що застрягли в `armed` і вже
   у вʼюпорті, плюс один слухач `visibilitychange` → `bind(document)`. Без цього
   озброєний вузол, якому колбек не прийшов, не рятувався ніколи: повторний `bind()`
   виходив по перевірці «вже озброєний». Ціна — нуль роботи на кадр.

**Як перевіряти (порядок дій):**
`AIA.motion.ioWorks()` спершу — щоб відрізнити дефект системи від мертвого середовища.
Далі: полічити `[data-reveal="in"]` проти `armed` і проти реально невидимих; прокрутити
всю сторінку; **дати ≥1.5 с на осідання** — на 700 мс я отримав 4 «застряглі», яких
насправді не було (колбеки ще летіли). Той самий тест прогнати на оригіналі автора, щоб
не приписати собі чужий результат.
