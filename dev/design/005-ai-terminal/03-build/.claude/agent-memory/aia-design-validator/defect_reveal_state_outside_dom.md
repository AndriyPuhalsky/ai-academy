**Найчастіший дефект конвеєра AIA: анімаційний стан живе поза DOM і не застосовується до
вузлів, які народжуються після першого проходу.** Уже двічі поспіль.

- **003 (роадмап), дефект D-01:** прогрес змійки не переносився на щойно створені вузли
  після `render()` — голова лінії відривалась. Полагоджено в коді сайту, у макеті
  `dev/design/003-roadmap/04-variants/_base/motion.js` **лишився**.
- **005 (AI Термінал), блокер Б-01:** `IntersectionObserver` створювався один раз на
  `DOMContentLoaded` (208 мс), а `.cc-rows` народжувались у `renderMap()` після `fetch`
  конфіга. Клас `is-in` не з'являвся ніколи, `.js .cc-row { opacity: 0 }` тримав усі
  22 рядки карти невидимими **назавжди**. Головний артефакт сторінки був порожній.

**Why:** обидва рази білдер перевіряв у headless Chrome, де `IntersectionObserver` і
`requestAnimationFrame` не спрацьовують узагалі, а скріншоти всієї сторінки знімались із
`--force-prefers-reduced-motion` — тобто саме в режимі, де CSS примусово ставить
`opacity: 1` і баг невидимий. Дві сліпі зони накладаються й дають хибне «перевірено».

**How to apply:** у будь-якій задачі, де є асинхронний рендер із конфіга,
**першою дією** перевіряти в живому браузері:
`document.querySelectorAll('.<клас-з-анімацією>').length` проти
`document.querySelectorAll('.<той самий клас>.is-in').length`. Нуль у другому = блокер.
Правильна форма фікса: спостерігач один на весь час життя сторінки, функція реєстрації
ідемпотентна (позначати вузли `data-*`), виклик додається на подію `*:rendered`.
Дивись також [[method-live-browser-checks]].
