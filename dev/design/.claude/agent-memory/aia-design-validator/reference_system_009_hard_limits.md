Три межі, перевірені приладом на 012. Усі три зʼявляться знову в будь-якій задачі, що робить
«реалістичніший» компонент.

**1. Суцільна заливка статусним кольором не несе AA-напису взагалі.**
`--c-info-edge` = `#537383`. Контраст написів: `--c-text` (`#F0E9DF`) **4.20** ✗ ·
`--p-n-0` (`#0E0C0A`) 3.86 ✗ · `--p-n-100` 3.65 ✗ · чисте біле 5.06 ✓, але чистого білого в
системі немає свідомо («кістка, не білило», Д1 009). Те саме стосується `--c-ok-edge`.
**Наслідок:** наголос у компоненті робиться товщиною канта (`--bw-strong`) і вагою
(`--w-medium`), а не плямою. Залиту кнопку, як у справжньої Jira, система не дає зробити.

**2. Дві напівпрозорі плівки вбивають третинний текст.**
`--c-text-3` (`#ADA599`) на полотні — 7.59. Під двома тінтами (`--c-veil-hover` на контейнері +
`--c-info-quiet`/`--c-ok-quiet` на дочірньому) падає до **4.46** — нижче AA. У 012 це дало
30 провальних вузлів у варіанті 3, лікується підняттям на `--c-text-2`.
**Перевіряй кожен шар тінту окремо; `rgba()` рахує від того, що ПІД ним.**

**3. «Нуль правил на голий тег» має дзеркало: голий тег БЕЗ правила.**
Критерій «у компоненті нуль селекторів на `h4 {`, `th {`, `td {`» виконується — і тоді
розмітка без класу (`<ul><li>` всередині `.win__sub`, `<span>` без `.win__btn` всередині
`.win__actions`) не отримує **жодного** правила й малюється навколишнім кеглем прози (17 px
проти шкали компонента 14/12/11). На екрані це «просто гірше, ніж мало б».
**Тест:** обійти всі текстові вузли компонента й зібрати ті, у яких
`parseFloat(getComputedStyle(el).fontSize) > максимального кегля компонента`. У 012 знайшлось
12 вузлів у 69 вікнах.

**4. Довідкові числа драбини 009** (темна тема, перевірено з живого `css/tokens.css`):
`--c-bg` `#161311` · `--c-surface` `#1E1A17` · `--c-raised` `#26221D` · наступна сходинка
`--p-n-400` `#2F2A24` (у системі «поверхня hover», семантичного імені для поверхні компонента
не має — використання = `розширення системи`).
