Спроєктовано й **виміряно в Chrome 2026-09-07** (probe-сторінка, headless) під час
специфікації 009. Замінює поіменний список токенів, який у `css/custom.css` розрісся
до **57 рядків** трьох поколінь (001 → 003 → 005).

**Конструкція:** одні ворота `--motion` (1|0) × пресет `--motion-scale` / `--motion-travel`,
дві похідні одиниці `--dur-u: calc(var(--motion)*var(--motion-scale)*1ms + 0.001ms)` і
`--move-u: calc(var(--motion)*var(--motion-travel)*1px)`. Кожна тривалість —
`calc(<число> * var(--dur-u))`, зсув — `calc(<число> * var(--move-u))`, масштаб —
`calc(1 ± var(--motion) * <дельта>)`. Медіа-запит `reduce` містить рівно два рядки.

**Виміряні числа:** при `--motion:1` використана `transition-duration` = `0.18018s`
(токен 180); при `--motion:0` = `0.00018s`. Зсув 8px → 0px, масштаб 0.98 → 1.

**Чому `+0.001ms`, а не 0:** нульова тривалість не породжує `transitionend`/`animationend`,
і JS, який їх чекає, зависає назавжди. 0.18 мс — менше чверті кадру, але подія приходить.

**⚠ Головна пастка, виміряна:** `getComputedStyle().getPropertyValue()` для
**незареєстрованого** custom property повертає **невирахуваний рядок**
`calc(180 * calc(1 * 1 * 1ms + 0.001ms))`. `parseFloat` = `NaN`, тож типовий помічник
`ms(name, fallback)` тихо бере fallback — і GSAP продовжує рухатись при `reduce`, а
візуально це помітно тільки на живому екрані. Два виходи, треба обидва: (1) JS читає
`--motion` і **сирі беззмінні числа**, а не складені токени; (2) складені токени
реєструються через `@property { syntax: '<time>' }` — після реєстрації той самий виклик
повертає вже обчислені `0.18018s` / `0.00018s` (перевірено).

**Безкінечні цикли нулем не вимикаються** — гасяться окремим токеном
`animation-play-state: var(--loop-state)` (`running` → `paused`); перевірено, що пауза
зберігає поточний кадр, тому кадр `0%` мусить дорівнювати стану спокою.
Токен-швидкість, на який ділять (`--term-speed-cps`), не множиться на `--motion` —
нуль дав би `Infinity`; його гілку бере JS.
