Найдорожчий клас дефектів у цьому проєкті — **не зламана верстка, а мовчазна
розбіжність контракту**: CSS чекає одного, JS дає інше, помилки немає, сторінка
малюється, і дефект помічають місяцями пізніше. Знайдено чотири штуки за одну
годину читання коду під час специфікації 010 (2026-09-07) — тобто це не рідкість.

**Виміряні приклади:**
1. `_base/components.css:527` селектує `.ds-snav__item[aria-current="true"]`, а
   `js/module.js:165` ставить `aria-current="page"`. Поточний урок у сайдбарі просто
   не отримує акценту. Правильне значення для пункту навігації за WAI-ARIA — саме
   `page`, тож правити треба CSS, а не JS.
2. `_base/components.css:557` малює літеру варіанта через `content: attr(data-key)`,
   а `js/quiz.js:107` ставить лише `className = "quiz-opt"`. 57 сторінок без «А/Б/В/Г».
3. `js/quiz.js:126,131` дописує `✓ ` / `✗ ` **у сам текст** варіанта, а система
   малює ті самі гліфи псевдоелементом → подвоєння.
4. **Найгірший тип: тихий fallback.** `js/roadmap-motion.js` читає 36 імен токенів
   через `num(name, fallback)`. Перейменуєш токен у CSS — JS мовчки візьме зашите
   число, і роадмап продовжить анімуватись «майже правильно». Те саме в
   `js/claude-code-motion.js` (15 імен). Плюс `getComputedStyle` не обчислює `calc()`
   для незареєстрованих custom properties → `parseFloat` = `NaN` → той самий fallback,
   і рух лишається живим при `prefers-reduced-motion`.

**Ще три, виміряні під 012 (2026-10-01) — той самий клас, нові форми:**
5. **Слот акценту, якого немає.** `[data-course="jira"]` стоїть на `<html>` усіх 26
   сторінок курсу, а блока в `css/tokens.css` немає → `:root` → усі 26 носять **шафран
   AI Академії**. Атрибут-слот без блока не падає, він тихо успадковує дефолт.
   **Перевірка: `grep` значень `data-course` у HTML проти блоків у `tokens.css`.**
6. **Невідоме значення даних, яке два рендерери читають по-різному.** У
   `jira.config.json` усі 23 модулі мають `status: "draft"` — четверте значення
   (канон: `ready`/`soon`/`done`). `js/config.js:154` фільтрує `=== "ready"` → CTA
   лишається якорем, `badgeFor()` віддає «Скоро» пунктиром **усім 23**; а
   `js/claude-code-render.js:311/334` рахує `isSoon` як `=== "soon"` → рядки виходять
   звичайними, але маркер «почати звідси» не ставиться **ніде**. Два екрани того ж
   курсу показують два різні світи. **Перевірка: для кожного поля-енуму зібрати
   множину значень у конфігах і множину порівнянь у JS — вони мусять збігатись.**
7. **Поіменний список селекторів замість механізму — у шести місцях.** Підказка про
   горизонтальний скрол (§41) і видима смуга (§41.1) працюють від
   `FADE_SCROLLERS` у `js/ui.js:328` (6 селекторів) + **пʼяти** повторів того ж списку
   в `css/components.css`. Новий скролер там не зʼявляється сам: підказка мовчки не
   виникає. **Дешевий обхід, який варто пам'ятати: перевикористати наявний клас
   скролера (`.ds-tbl__wrap`) і знести різницю вигляду одним правилом** — тоді шість
   списків не чіпаються взагалі.

**Why:** у цьому проєкті розмітка й стилі народжуються в різних місцях — половина
класів приходить із рядків усередині `js/*.js`, а не з HTML. Тому «подивитись на
сторінку» дефект не ловить: сторінка виглядає нормально, просто гірше, ніж мала б.

**How to apply:** пишучи будь-яку спеку, що зводить новий CSS зі старим JS, окремо
перевіряти **шість** речей і називати їх у розділі пасток:
(а) кожен селектор з атрибутом — чи ставить JS **саме це значення**;
(б) кожен `content: attr(...)` — чи є той атрибут у розмітці, яку будує JS;
(в) кожне `getComputedStyle`-читання токена — чи є в нього fallback, і що станеться
при перейменуванні;
(г) кожен **слот-атрибут** (`data-course`, `data-density`, `data-motion`) — чи існує
блок під кожне значення, що реально стоїть у HTML;
(д) кожне **поле-енум у конфігах** — чи збігається множина значень із множиною
порівнянь у JS, і чи читають його два рендерери однаково;
(е) кожен **поіменний список селекторів** у CSS/JS — чи треба дописати туди новий
компонент і скільком копіям того списку це потрібно.
Перевірка — `grep` по JS і конфігах, не погляд на екран.
