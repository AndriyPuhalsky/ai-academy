Файл «AIA Design System v1» (`FktfudHg9ZuZ7bYJufGIk6`, Drafts власника) живе на плані
**Starter**. Три обмеження, знайдені **фактично**, а не з документації:

1. **Один режим змінних.** `addMode` → «Limited to 1 modes only». Наслідок для архітектури:
   теми/акценти реалізуються **окремими змінними** (`accent/academy|architect|terminal/*`
   плюс `accent/current/*`, до якого привʼязані компоненти), а не режимами. У CSS те саме
   робить `[data-course]` на `<html>`. Це не обхід ліміту — рішення Р15.
2. **Рівно три сторінки.** `createPage` → «The Starter plan only comes with 3 pages».
   У `00-review` цього не було: там перевірили, що `createPage` працює, але не скільки разів.
3. **Денна квота MCP-викликів, і вона мала.** «You've reached the Figma MCP tool call limit
   on the Starter plan» прийшла **на 14-му виклику** сесії. У самому Figma в правій панелі
   при цьому видно «**MCP · Out of calls**», а в діалозі апгрейду написано, що Professional
   дає «200 MCP tool calls per day for Full seats». Квота денна — оновлюється.

**Що з цього планувати наперед:** роботу з Figma розбивати так, щоб **найцінніше йшло
першими викликами** (змінні → стилі → сторінки → канва), бо квота може скінчитись посеред
задачі. Створення 300 змінних — це 5 викликів (цикли всередині одного скрипта дешеві);
компонент-сети — по виклику на компонент, тобто найдорожча частина. Робити їх останніми.

**Що працює й перевірено:** дві колекції змінних · `createVariableAlias` між колекціями ·
`scopes` · `setVariableCodeSyntax` · `createPage` (до 3) · `combineAsVariants` ·
`setBoundVariableForPaint` · кирилиця в тексті · `figma.root.name` **записується**
(хоч і читається старим у тому ж скрипті).

**Chrome як запасний шлях годиться для ПЕРЕВІРКИ, не для збірки:** відкрити файл, звірити
змінні/стилі/канву очима — швидко й надійно; складати компонент-сети кліками — сотні дій
без можливості перевірити привʼязку змінної до заливки інакше, ніж візуально.
