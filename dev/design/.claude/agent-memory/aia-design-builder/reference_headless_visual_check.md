**Оновлено 2026-09-07: у білдера ТЕПЕР Є живий браузер** — `mcp__claude-in-chrome`
(`navigate` / `computer` / `javascript_tool` / `read_console_messages` / `find`).
Запис попередньої редакції «браузерних MCP-інструментів у мене немає» **застарів**.
Робочий цикл: `python3 -m http.server` → `navigate` → `javascript_tool` для замірів →
`computer screenshot` для очей.

**Пастка, важливіша за всі попередні (виміряна 2026-09-07):**
**Chrome не доставляє колбеки `IntersectionObserver` вкладці, яка не рендериться** —
фон, оклюзія, а не лише headless. Виміряно прямо: **свіжий** IO не спрацював ЖОДНОГО разу
на елементі, що стояв на 315 px у вікні висотою 709 px. Через кілька хвилин у тій самій
вкладці той самий тест показав «доставка працює».
**Наслідок для архітектури, а не лише для тестів:** нічого видимого не можна ховати CSS-ом
із розрахунком, що IO його потім покаже. У 009 через це змінено конструкцію — `bind()`
**не ховає те, що вже у вʼюпорті**, озброюється лише те, що за згином.
Тест, який залежить від IO, мусить друкувати стан середовища окремим рядком, інакше
обмеження вкладки виглядає як дефект системи.

**Пастка масштабованого `<iframe>` (виміряна 2026-09-07, задача 010):**
Chrome **не тікає `rAF`** у кадрі, який зменшений `transform: scale()` і/або стоїть поза
екраном. Наслідок: `getComputedStyle` віддає **стартове** значення CSS-переходу назавжди,
хоча компонувальник уже намалював кінцеве — тобто шторка на скріншоті відкрита, а число
каже `translateX(-280px)`. Спроба дочекатись `requestAnimationFrame` **усередині** такого
кадру підвісила рендерер на 45 с (`CDP Runtime.evaluate timed out`).
Правило: у масштабованому кадрі міряти лише статику (ширини, кольори, специфічність);
усе, що анімується, перевіряти оком у повнорозмірному вікні.

**Друга половина тієї самої пастки (виміряно 2026-09-07 на задачі 010):**
у нерендереній вкладці **не викликається й `requestAnimationFrame`**, тож
GSAP-таймлайни стоять замороженими на кадрі, який встиг відмалюватись, а
CSS-переходи застрягають посеред (`opacity: 0.3458`). Виглядає як зламана
верстка, хоча класи виставлені правильно.
- **Ознака середовища, яку треба друкувати окремим рядком:**
  `document.visibilityState === "hidden"` і `AIA.motion.ioWorks()` → `false`.
- **Обхід для перевірки руху:** `gsap.updateRoot(gsap.globalTimeline.rawTime() + 6)`
  проганяє всі таймлайни вручну — кінцевий стан перевіряється чесно.
- **Обхід для перевірки CSS-переходів:** тимчасово вставити
  `<style>*{transition:none !important}</style>` і переміряти — тоді видно
  ЦІЛЬОВИЙ стан, а не завмерлий кадр.
- **Наслідок для КОДУ, а не лише для тестів:** будь-яке «відкриття» у формі
  `hidden = false` + `requestAnimationFrame` + перемикання атрибута мовчки
  деградує — елемент опиняється в DOM з `opacity: 0`. Замість rAF треба
  **примусовий reflow** (`void el.offsetWidth`): він синхронний і від рендера
  не залежить. Стосується `js/auth-ui.js` і `js/contact.js`.

**Інші пастки, які лишаються чинними:**
- `javascript_tool` іноді повертає **[BLOCKED: Cookie/query string data]**, якщо у
  результаті трапляється щось схоже на query string або URL. Обхід: віддавати короткі
  рядки без URL, або читати результат зі скріншота.
- **Десктопний Chrome не робить вікно вужче ~500px.** Мобілку міряти через `<iframe>`
  потрібної ширини (і показувати його `position:fixed` поверх, якщо треба скріншот).
- **iframe бере CSS із кешу.** Тест ширин міряв не той файл, що на диску, доки не додано
  кеш-бастер у `src` і `Cache-Control: no-store` на локальному сервері. Без цього
  «виправлений» дефект продовжує «падати», і час іде на пошук неіснуючої причини.
- У headless `rAF` викликається рівно один раз — анімацію в русі він не покаже взагалі.

**Що зручно робити тим самим прийомом:** побайтовий тест копіювання
(`Range` + `selection.toString() === pre.textContent`), пошук горизонтального скролу
(`scrollWidth` vs `clientWidth` на списку ширин у iframe), обхід усіх текстових вузлів для
реального контрасту, вимір ваги шрифтів через `performance.getEntriesByType('resource')`.

**Доповнення 2026-09-07 (задача 010, білдер Б1) — три пастки виміру, кожна коштувала кола:**
- **Кеш-бастер на HTML НЕ рятує від кешу CSS/JS.** `iframe.src = page.html?cb=…` віддає
  свіжий документ, але `<link>`/`<script>` усередині беруться з памʼяті. Виміряний
  наслідок: виправлений дефект «продовжував падати» (273 px скролу на 320), а через
  прогін зникав сам. Лікується ТІЛЬКИ сервером із `Cache-Control: no-store` на
  **кожну** відповідь (свій `SimpleHTTPRequestHandler.end_headers`), не параметром у URL.
- **`document.hasFocus()` часто `false`,** бо системний фокус у панелі розширення.
  Тоді `.focus()` мовчки не породжує `focusin`/`focusout`, і будь-який тест на «фокус
  пішов за межі» дає хибний «дефект». Перевіряти `document.hasFocus()` ПЕРЕД
  клавіатурним тестом і спершу клікнути в сторінку.
- **Синтетичний `Tab` розширення не робить послідовної навігації фокусом** (тричі
  поспіль лишав фокус на skip-link при `hasFocus: true`). Порядок табуляції треба
  перевіряти програмно — списком фокусованих елементів у порядку DOM, — а живий
  прохід Tab лишати людині й казати це в звіті.
- Асинхронний тест: `javascript_tool` серіалізує Promise у `{}`. Класти результат у
  `window.__x` і опитувати окремим викликом; довгі прогони (32 iframe × 3 с) — це
  ~2 хвилини, батч `computer wait` по 10 с.
