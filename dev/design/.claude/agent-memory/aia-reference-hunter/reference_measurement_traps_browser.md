Усі чотири зловлені на собі (задача 012, 2026-10-01). Кожен давав правдоподібне число,
яке я вже був записав у звіт.

**1. Зняття елемента з DOM виглядає як рух.** Семплер `getBoundingClientRect` читає
`w=0, h=0` як «елемент переїхав у нуль». Перший прохід дав «cursor.com рухає блок на
740 × 429 px» — насправді React розмонтував панель при перемиканні вкладки.
**Лікування:** відкидати кадри з `w === 0 || h === 0` і рахувати їх окремо як `unmount`.
Побічна вигода: `unmount` за 12 с — чудова метрика сама по собі (cursor.com **148**,
attio **97**) і прямий індикатор «рух зроблено підміною DOM».

**2. Номер, згенерований CSS, не існує в `textContent`.** Детектор нумерації через текст
дав «0 на 40 сайтах»; перевірка через `getComputedStyle(el, '::before').content` знайшла
**241** номер (Material 3 — 60). Зловив випадково: **знімок на 350 px показав те, чого
«не було»**. **Лікування:** будь-яку нумерацію, маркери списків, лічильники шукати лише
через псевдоелементи + `list-style-type` + `@counter-style` у `document.styleSheets`.
**Загальний урок: якщо прилад дає рівний нуль на великій вибірці — спершу підозрювати
прилад, і звіряти з власним знімком.**

**3. `display: block` + `overflow-x: auto` на самій `<table>` не створює скролпорта.**
Групи рядків (`table-header-group`, `table-row-group`) вилазять за межі блока; документ
розʼїжджається. У моїй же сторінці звіту це дало `docW` 648 при вʼюпорті 390.
**Лікування:** скролить **обгортка** (`<div style="overflow-x:auto">`), таблиця лишається
`display: table`.

**4. Мобільний вʼюпорт ≠ ширина пристрою.** При `viewport.width = 350` пʼять сайтів із 25
віддали `innerWidth` **372–378** (і 776–790 при 768): сторінка змушує браузер
відмасштабуватись, тож фактичний кегль дрібніший за заявлений у CSS.
**Лікування:** завжди логувати `innerWidth` поруч із заданою шириною і
`documentElement.scrollWidth`; не плутати «розширив вʼюпорт» із «горизонтальний скрол».

Супутнє: **свою ж сторінку звіту теж треба заміряти** — у 012 вона мала власне
переповнення на 390 px через `flex: none` на бейджі (`.feas`), успадкований із 010.
Збирач `build.js` + `data.json` лишається правильною схемою (див. [[feedback-reference-method]]).
