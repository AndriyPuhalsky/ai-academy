**Виконано 2026-09-07 сесією `design_1` у живому Chrome**, на справжніх файлах системи:
`009-design-system/04-variants/_base/tokens.css` + `variant-a/variant.css` + скорочена копія

Агент №1 позначив ці факти як «документовані, але не заміряні мною». **Тепер заміряні.**
Цей файл має перевагу над §4.4 спеки.

## Головне: центральне рішення 010 підтверджене

**Tailwind CDN приймає `var(--токен)` як значення кольору, розміру, радіуса, `z-index`
і `max-width`.** Заміна 66 інлайнових `tailwind.config` одним `js/tw-theme.js` **працює**.

| Що перевіряли | Клас | Обчислене значення | Вердикт |
| ------------- | ---- | ------------------ | ------- |
| Поверхня | `bg-surface` | `rgb(30, 26, 23)` = `#1E1A17` | ✅ |
| Кегль + інтерліньяж | `text-sm` | `14px` / `21px` | ✅ |
| Гарнітура | `font-mono` | `"JetBrains Mono", ui-monospace, …` | ✅ |
| Радіус | `rounded-control` | `8px` | ✅ |
| Шар | `z-header` | `100` | ✅ |
| Ширина | `max-w-prose` | `768px` | ✅ |
| Межа | `border-line` | `rgb(67, 60, 53)` | ✅ |
| Адаптив | `text-xs sm:text-sm` | `14px` на широкому вікні | ✅ |

## Слот акценту курсу працює — це і був сенс усієї конструкції

`[data-course]` на `<html>` перемикає `--c-accent`, і всі утиліти `*-accent` міняються разом:

| `data-course` | `text-accent` → колір |
| ------------- | --------------------- |
| `academy` | `rgb(191, 138, 58)` — шафран |
| `architect` | `rgb(31, 166, 142)` — патина |
| `terminal` | `rgb(118, 146, 220)` — лазур |

Саме це **неможливо** з копією теми з хардкод-значеннями: Tailwind фіксує колір під час
генерації, і три акценти 009 на сайті не зʼявились би взагалі.

## ⚠️ Поправка до спеки: альфа-модифікатор дає ПРОЗОРЕ, а не непрозоре

Спека §4.3 попереджала, що `bg-accent/50` «мовчки віддає непрозорий колір».
**Виміряно — наслідок гірший:**

```
bg-accent/50  →  background-color: rgba(0, 0, 0, 0)
```

Тобто елемент лишається **повністю прозорим**: колір зникає, а не втрачає альфу.
Помилки в консолі немає.

**Що це означало б у проді — 540 вживань у 72 файлах:**

| Клас | Разів | Що зламалося б |
| ---- | ----- | -------------- |
| `bg-clay/10` | 130 | тихі акцентні підкладки зникли б |
| `border-clay/40` | 127 | акцентні межі зникли б |
| `border-line/60` | 107 | межі карток зникли б |
| `border-line/70` | 67 | те саме |
| **`bg-ink/85`** | **65** | **липка шапка стала б повністю прозорою** — текст сторінки їхав би просто крізь неї |
| `text-muted/90` | 17 | текст став би невидимим |
| `border-clay/60` · `/30` · `bg-line/60` | 8 | межі зникли б |
| у `js/*.js` | 19 | те саме, але зʼявляється лише в рантаймі |

**Разом: 521 у HTML + 19 у JS = 540 вживань, 72 файли.**

Це не косметика і не «одноманітність заради одноманітності»: **кожен із цих 540 класів —
мовчазна поломка**, яку не видно ні в консолі, ні в збірці, і яка зʼявиться відразу на
живому сайті.

### Наслідок для карти міграції (П2)

Альфа-модифікатори переходять у **окремі токени**, як і передбачала спека — і це працює:
`bg-accent-quiet` дав `rgba(191, 138, 58, 0.14)` ✅.

**Кожен із 540 випадків має бути в карті міграції поіменно**, з новим токеном-заміною.
Механічна заміна тут **особливо небезпечна**: `bg-clay/10` і `border-clay/40` — це різні
ролі (підкладка й межа), які не можна замінити одним правилом.

## Що це змінює для наступних агентів

1. **Запасний план §4.4 не потрібен** — `var()` у темі працює. Секцію `components.css` §19
   з утилітами `ds-u-*` **не робити**, префікс `u` в реєстр §7.0 не додавати.
2. **Заборона альфа-модифікаторів — жорстка**, і причина сильніша за описану в спеці.
3. **540 вживань у 72 файлах** — це окремий рядок у порядку робіт (П3) і, найімовірніше,
   найтонше місце всієї міграції. Липка шапка (`bg-ink/85` ×65) — перше, що треба перевірити
   очима після заміни теми.
