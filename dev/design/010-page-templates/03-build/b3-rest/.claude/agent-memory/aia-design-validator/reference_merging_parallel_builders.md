Коли троє агентів пишуть дельти паралельно й **кожному заборонено правити спільну базу**,
вони неминуче пишуть **три різні обходи одного дефекту**. У 010 це були три різні
`@media (hover: none)`, три копії `scroll-padding-top`, три різні набори
`overscroll-behavior-x` і дві копії правила `visibility` для меню.

**Правило зведення: обхід замінюється справжньою правкою в місці оголошення.**
База копіюється у пакет і патчиться там; `_base/` оригіналу не чіпається. Після цього
всі нейтралізатори з дельт **видаляються**, а не «лишаються про всяк випадок» — інакше
наступний агент читатиме файл, у якому один дефект описаний тричі трьома різними мовами.

**Порядок роботи, який спрацював:**
1. Прочитати всі звіти **повністю** й виписати конфлікти в таблицю «хто що каже».
2. Переміряти самому те, від чого залежить рішення (див. [[validator-falsify-builder-numbers]]).
3. Патчити копію бази скриптом із `assert s.count(old) == 1` на кожній заміні — так
   мовчазний промах неможливий.
4. Склеїти дельти за явними діапазонами рядків, а не «скопіювати все й почистити».
5. **Прогнати CSSOM-аудит по зведеному файлу** — саме він ловить те, що склеїлось погано:
   дублі селекторів, сироти без батьківського правила, незахищені `:hover`.

**Що перевіряти після склейки, машинно:** баланс дужок · дублі селекторів верхнього рівня ·
хекси й `rgba()` · літерали в `@media` · числові `z-index` · чи не лишилось нейтралізаторів.

**Пастка, що трапилась:** дочірнє правило `.ds-prose[data-prose="wide"] > section` поїхало,
а батьківське — ні (білдер позначив його «тільки макет»). Сирота без батька не ламає нічого,
але й не робить нічого. **Після склейки шукати правила-сироти окремо.**
