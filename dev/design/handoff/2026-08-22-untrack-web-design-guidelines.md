## Чому

Скіл `web-design-guidelines` вендорено з `vercel-labs/agent-skills`. У цього репозиторію
**немає жодної ліцензії** — перевірено 2026-08-22:

- `GET https://api.github.com/repos/vercel-labs/agent-skills` → `"license": null`
- у листингу кореня немає ні `LICENSE`, ні `COPYING`

Без ліцензії права на розповсюдження копії немає. Локально користуватись — нормально,
але зараз ця копія лежить у **публічному** репозиторії, тобто ми її розповсюджуємо.

Решта 12 скілів — MIT (Addy Osmani, Emil Kowalski, Arvind, GreenSock). Вони лишаються
в гіті, а вимогу MIT про збереження копірайту закриває новий файл
`dev/design/.agents/skills/ATTRIBUTION.md` (уже створений, поїде наступним комітом).

## Що зробити

**1. Дописати в кореневий `.gitignore`** (в кінець, після блоку `dev/*` / `!dev/design/` —
важливо саме після, бо в git виграє останнє правило):

```gitignore
# Скіл vercel-labs/agent-skills не має ліцензії (перевірено 2026-08-22) — тримаємо
# локально, але не розповсюджуємо в публічному репозиторії. Ставиться командою:
# npx skills add vercel-labs/agent-skills@web-design-guidelines -y  (з dev/design/)
dev/design/.agents/skills/web-design-guidelines/
dev/design/.claude/skills/web-design-guidelines
```

**2. Зняти з відслідковування** (файли лишаються на диску — `--cached`):

```bash
git rm -r --cached dev/design/.agents/skills/web-design-guidelines
git rm --cached dev/design/.claude/skills/web-design-guidelines
```

**3. Перевірити, що вийшло як треба:**

```bash
# має бути порожньо:
git ls-files | grep web-design-guidelines
# має бути на місці (локально скіл далі працює):
ls -la dev/design/.claude/skills/web-design-guidelines
```

**4. Закомітити** разом з іншими змінами цієї сесії (див. нижче) у `dev`. У `main` —
тільки після окремого «так» власника, за правилом кореневого `CLAUDE.md`.

## Застереження на майбутнє

Історія гіта вже містить `web-design-guidelines/SKILL.md` (коміт `7fe2499`). Цей handoff
прибирає його з поточного стану, але **зі старих комітів він не зникає**. Переписувати
історію (`filter-repo`) під це не варто: ризик і шум більші за проблему — це сторінка
markdown-рекомендацій зі стилю, не пропрієтарний код. Якщо колись знадобиться повне
прибирання (напр. хтось поскаржиться) — це окрема свідома операція, і тоді репозиторій
краще спершу перевести в private.
