Фаза B · Будуємо з LLM

Tool use / function calling

Практика · 5 уроків · ≈ 65 хв

Досі модель лише говорила. Тепер навчимо її діяти: викликати твої функції, щоб дізнатися щось із зовнішнього світу чи виконати дію. Це називається tool use (інша назва — function calling), і саме воно перетворює балакучу модель на справжній інструмент. Це також фундамент агентів, до яких ми перейдемо в наступній фазі. Підемо повільно, з аналогією й розбором коду.

10.1Навіщо моделі інструменти

Сама собою модель багато чого не вміє: дізнатися сьогоднішню погоду, точно порахувати велике число, заглянути в твою базу даних, надіслати лист. Вона працює лише з текстом. Але вона вміє інше — зрозуміти, що для відповіді потрібен інструмент, і попросити його викликати.

Аналогія. Уяви тямущого помічника в кабінеті без телефону й комп'ютера. Сам він залишок товару на складі не дізнається. Зате пише тобі записку: «зателефонуй на склад і спитай, скільки одиниць товару №42». Ти телефонуєш (виконуєш дію), приносиш відповідь — і він формулює гарну відповідь клієнту. Модель — цей помічник: вона не діє сама, вона просить тебе виконати дію й повернути результат.

Що це відкриває. Через інструменти модель може: підтягувати свіжі дані (погода, курси, новини), звертатися до інших сервісів (API), рахувати точно (калькулятор), працювати з твоєю базою. Тобто переходить від «розумного співрозмовника» до «виконавця, що взаємодіє зі світом». Саме на цьому будуються AI-агенти.

10.2Цикл tool use: хто що робить

Перш ніж кодити, втримай у голові загальний рух. Ти описуєш моделі доступні інструменти. Якщо для відповіді потрібен один із них, модель не вигадує результат, а повертає запит «виклич ось цю функцію з такими аргументами». Твій код виконує — і повертає результат моделі, а та формулює фінальну відповідь: 

sequenceDiagram
  participant C as Твій код
  participant M as Модель
  C->>M: запит + список інструментів
  M-->>C: "виклич get_weather(city='Київ')"
  C->>C: виконує функцію get_weather
  C->>M: результат інструменту (tool_result)
  M-->>C: фінальна відповідь людською мовою

Модель вирішує ЩО викликати; виконує функцію завжди твій код

Ключова думка. Модель ніколи не виконує твій код сама — вона лише просить (пише записку). Виконання, перевірка прав і безпека — повністю на тобі. Це й робить tool use водночас потужним і керованим: модель отримує «руки», але кнопки натискаєш ти.

10.3Описуємо інструмент для моделі

Спершу треба пояснити моделі, які інструменти в неї є. Опис — це ніби анкета: як називається інструмент, навіщо він і які аргументи приймає. 

tools = [
    {
        "name": "get_weather",
        "description": "Повертає поточну погоду для вказаного міста",
        "input_schema": {
            "type": "object",
            "properties": {
                "city": {"type": "string", "description": "Назва міста"}
            },
            "required": ["city"]
        }
    }
]

Розбір опису. name — як називається інструмент. description — навіщо він; модель читає це й вирішує, чи він потрібен (тому пиши зрозуміло!). input_schema — опис аргументів мовою JSON Schema, тобто «анкета»: тут одне поле city типу «рядок» (string), і воно required — обов'язкове. За цим описом модель розуміє, що і в якому форматі їй передати.

Список tools — це просто перелік таких анкет. Можна описати кілька інструментів одразу, і модель сама обере потрібний (побачимо в уроці 10.5).

10.4Повний цикл у коді

Тепер зберемо все. Попроси Claude Code: «створи файл tool_demo.py з інструментом get_weather і повним циклом tool use». Вийде приблизно так (читай із коментарями): 

def get_weather(city):
    return f"{city}: +18°C, ясно"   # тут міг би бути реальний виклик API погоди

messages = [{"role": "user", "content": "Яка погода в Києві?"}]
resp = client.messages.create(model=MODEL, max_tokens=500, tools=tools, messages=messages)

# Якщо модель просить інструмент, stop_reason буде "tool_use"
if resp.stop_reason == "tool_use":
    tool = next(b for b in resp.content if b.type == "tool_use")   # знаходимо блок-запит
    result = get_weather(**tool.input)                             # виконуємо функцію

    # Повертаємо моделі її ж запит + наш результат (як у діалозі, Модуль 8)
    messages.append({"role": "assistant", "content": resp.content})
    messages.append({"role": "user", "content": [{
        "type": "tool_result",
        "tool_use_id": tool.id,        # прив'язка результату до конкретного запиту
        "content": result
    }]})

    final = client.messages.create(model=MODEL, max_tokens=500, tools=tools, messages=messages)
    print(final.content[0].text)   # "У Києві зараз +18°C, ясно."

Розбір найхитріших місць.

• next(b for b in resp.content if b.type == "tool_use") — пробігаємо блоки відповіді й беремо перший, що є запитом інструмента (resp.content — список блоків із Модуля 8; next(...) повертає перший відповідний).

• get_weather(**tool.input) — дві зірочки «розпаковують» словник у іменовані аргументи. Модель прислала tool.input = {"city": "Київ"}, а ** перетворює це на виклик get_weather(city="Київ").

• tool_use_id повертаємо, щоб модель зрозуміла, на який саме запит цей результат (вона може попросити кілька викликів одночасно — ID їх розрізняє).

Помітив? Це той самий цикл із діаграми, лише в коді: запит → модель просить → ти виконуєш → повертаєш результат → фінальна відповідь. Запусти python tool_demo.py — і побачиш, як модель «сходила по погоду» через твою функцію.

10.5Кілька інструментів, надійність і крок до агентів

У реальних застосунках інструментів кілька. Ти просто описуєш їх усі в списку tools, а модель сама обирає потрібний під запит: 

tools = [
    { "name": "get_weather", "description": "Погода в місті", "input_schema": {...} },
    { "name": "get_time",    "description": "Поточний час у місті", "input_schema": {...} },
]
# На "яка зараз погода?" модель попросить get_weather,
# на "котра година?" — get_time. Вибір робить вона сама.

Надійність інструментів. Твої функції теж можуть впасти (сервіс недоступний, кривий аргумент). Обгортай виконання в try/except (Модуль 6) і повертай моделі зрозумілий результат навіть при помилці — наприклад, "помилка: місто не знайдено". Тоді модель гідно це обробить у відповіді, а не зламається весь процес.

І найголовніше — куди це веде. Поки що ми робили один прохід циклу: модель попросила інструмент один раз. А що, якщо дозволити їй просити інструменти багато разів поспіль, поки задача не виконана — крок за кроком, самостійно вирішуючи, що робити далі? Це вже й буде AI-агент. Саме цей крок ми зробимо в наступній фазі.

Підсумок модуля. Ти вмієш описувати інструменти (анкета input_schema), проводити повний цикл tool use в коді (tool_use → виконати → tool_result → фінальна відповідь), давати моделі кілька інструментів і безпечно обробляти збої. Модель тепер не лише говорить, а й діє. Далі — Фаза C: перетворимо цей цикл на справжнього агента.
