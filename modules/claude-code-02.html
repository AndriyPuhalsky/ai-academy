Що таке Claude Code

Початковий · 8 блоків · ≈ 35 хв читання

Claude Code найчастіше описують як «чат у терміналі». Це найдорожча помилка на старті: людина пише одне речення, чекає відповіді текстом, вручну вставляє свій код у запит — і не розуміє, навіщо взагалі було ставити окрему програму. Цей модуль існує, щоб такої помилки не сталося: він пояснює, з чим саме ти маєш справу, ще до встановлення.

Тут не буде команд, які треба вивчити напам'ять. Буде одна ментальна модель — і саме вона визначає, чи будеш ти отримувати від інструмента користь, чи витрачати на нього час.

Що в цьому модулі є, а чого немає

Немає: встановлення — це модуль 3, а перша власна сесія — модуль 4. Тут ти нічого не ставиш і нічого не ламаєш.

Є: чим агент відрізняється від чату й від підказок у редакторі · агентний цикл, розібраний на справжньому запуску · де фізично виконується код · чесна розмова про «vibe coding» · перелік поверхонь Claude Code і причина, чому курс лише про термінал.

Про свіжість фактів у цьому курсі

Claude Code змінюється щотижня. Тому кожен екран у цьому уроці підписаний тим, де і коли його знято, а кожне твердження взяте або з офіційної документації code.claude.com/docs, прочитаної 4 вересня 2026 року, або з живого запуску команди на машині автора. Якщо в тебе на екрані буде трохи інакше — спершу подивись на версію: майже завжди різниця саме в ній.

1Навіщо це

Є три різні речі, які легко сплутати, бо всі три «розуміють текст» і всі три пов'язані зі штучним інтелектом:

  • Чат — вікно, де ти пишеш запитання й отримуєш відповідь текстом. Наприклад, claude.ai у браузері.
  • Підказки в редакторі коду — інструмент, який дописує рядок за тебе, поки ти друкуєш. Документація Claude Code називає такі інструменти inline code assistants.
  • Агент — програма, яка сама читає файли, сама запускає команди, сама вносить зміни й сама перевіряє, що вийшло. Claude Code — саме це.

Офіційне визначення з документації дослівно: Claude Code — це «агентний асистент, який працює у твоєму терміналі», і хоча він найсильніший у роботі з кодом, він «може допомогти з будь-чим, що ти можеш зробити з командного рядка: писати документацію, запускати збірки, шукати у файлах, досліджувати теми».

git — програма, яка веде історію змін проєкту: хто, що і коли змінив, і як повернутись назад. Якщо ти нею не користуєшся, цей рядок таблиці тебе не стосується; агент від цього не перестає працювати.

Документація робить це порівняння прямо у двох місцях. Перше: «На відміну від чат-бота, який відповідає на питання й чекає, Claude Code може читати твої файли, запускати команди, вносити зміни й самостійно доводити задачу до кінця, поки ти дивишся, скеровуєш або взагалі відходиш». Друге, про редактор: «Це відрізняється від вбудованих асистентів коду, які бачать лише поточний файл».

Чому це не термінологія, а гроші й час

Від того, за що ти вважаєш інструмент, залежить, як ти формулюєш задачу — а від формулювання залежить результат.

  • Вважаєш чатом → пишеш «як полагодити кнопку?» → отримуєш текст, який доводиться вручну переносити у файли. Робота лишається на тобі.
  • Вважаєш агентом → пишеш «на сайті не працює кнопка надсилання, код у папці src/, розберися й полагодь» → отримуєш змінені файли й пояснення, що саме змінено.

Документація називає цей підхід «делегуй, а не диктуй» і дає дослівний приклад: «Оформлення замовлення зламане для користувачів із простроченими картками. Відповідний код у src/payments/. Можеш розібратися й полагодити?» — і додає: «Тобі не потрібно вказувати, які файли читати й які команди запускати. Claude з'ясує це сам».

Одне слово, яке варто запам'ятати

Документація називає Claude Code agentic harness — «агентною обв'язкою» навколо моделі: «вона дає інструменти, керування контекстом і середовище виконання, які перетворюють мовну модель на дієздатного агента».

Звідси головний висновок модуля: модель у чаті й модель у Claude Code — та сама. Різна обв'язка. Тому не має сенсу питати «чи Claude Code розумніший за чат» — питання в тому, що йому дозволено робити руками.

2Як це виглядає на екрані

Claude Code — це одна програма з іменем claude. У модулі 1 ти вже бачив команду which, яка відповідає на питання «де саме лежить ця програма», і --version, яка друкує номер версії. Ось вони на машині, де знімався цей курс.

Живий запуск 4 вересня 2026 року: macOS 26.5.2, збірка Claude Code 2.1.236, поставлена через homebrew. Замінене рівно одне — ім'я користувача й комп'ютера в запрошенні: у справжньому виводі там дані автора курсу, тут скрізь anna і MacBook-Air. Решта дослівна. У тебе цієї відповіді ще не буде — встановлення в модулі 3.

Програма сама каже, що вона не чат

Якщо запустити claude --help, перші рядки описують призначення програми. Читаються вони так: за замовчуванням запускається інтерактивна сесія — тобто діалог, у якому ти сидиш і дивишся; а ключ -p (він же --print) дає неінтерактивний режим — коли команда відпрацювала й вийшла, як звичайна утиліта.

Перші чотири рядки з claude --help, знятого 3 вересня 2026 року на збірці 2.1.236. Повний вивід цієї команди — 243 рядки: 62 ключі й 13 підкоманд. Розбирати його весь тут не треба; мета цього екрана — показати, що це інструмент, а не одна кнопка. Навігацією по ньому займається модуль 5.

Найкоротший доказ, що це агент

Ось справжній запуск. У папці лежить один файл notes.txt на два рядки. Людина не відкривала його, не копіювала вміст у запит і взагалі не казала, як рахувати рядки — вона поставила питання й отримала відповідь.

Живий запуск 4 вересня 2026 року, macOS 26.5.2, Claude Code 2.1.236. Вивід дослівний: програма надрукувала рівно один символ 2 і завершилась. Порівняй із чатом: у чат довелось би вставити вміст файла, інакше відповіді не буде — чат до твого диска не має доступу взагалі.

Чому тут немає знімка «агент у роботі»

Інтерактивний екран Claude Code — рухома картинка: рядки з'являються, оновлюються й зникають, поки агент працює. Текстом такий екран не знімається, а домальовувати його з голови цей курс не буде: правило простих слів — жодного вигаданого виводу. Тому в модулі 2 показані ті екрани, які реально знімаються, а живий інтерактивний екран ти побачиш власними очима в модулі 4, коли запустиш claude у себе.

3Як це працює

Усередині Claude Code крутиться одна й та сама послідовність, і документація називає її агентним циклом (agentic loop). Фаз рівно три:

  1. зібрати контекст — подивитись, що взагалі є: які файли, що в них, що каже git, що відповіла попередня команда;
  2. діяти — прочитати файл, змінити його, запустити команду;
  3. перевірити результат — запустити тест, подивитись на вивід, переконатись, що вийшло те, що треба.

Документація одразу застерігає: фази «зливаються» одна з одною й повторюються. Питання про код може обмежитись першою фазою. Виправлення помилки прокрутить усі три кілька разів поспіль.

  G --> A["2. Діяти інструментом"]
  A --> V["3. Перевірити результат"]
  V -->|"ще не сходиться"| G
  V -->|"готово"| D["Відповідь тобі"]
  U["Ти будь-якої миті: Esc або нове речення"] -.-> A

Той самий цикл на живому запуску

Запит із блоку 2 запустили ще раз — цього разу з ключем --output-format stream-json, який замість короткої відповіді друкує службовий журнал: які інструменти агент викликав і що отримав у відповідь. Ось що там було, у порядку подій:

Крок Що зробив агент Що отримав
1 склав команду терміналу, щоб порахувати рядки й заразом зазирнути в останній байт файла відмову: одна частина команди потребувала окремого дозволу
2 переписав команду без забороненої частини й запустив знову розмір файла й число 2
3 прочитав сам файл цілком два рядки тексту
4 надрукував відповідь 2

Розшифровка службового журналу справжнього запуску 4 вересня 2026 року (macOS 26.5.2, Claude Code 2.1.236). Сам журнал — суцільний JSON, читати його людині незручно, тому тут переказ подій, а не знімок екрана. У підсумковому рядку журнал назвав це чотирма ходами і 12,6 секунди. Той самий запит іншого разу може дати іншу послідовність кроків — агент вирішує це на місці, а не виконує заготовлений сценарій.

У цих чотирьох рядках видно все, заради чого написаний модуль. Крок 1 — фаза «зібрати контекст»: агент не знав, скільки рядків, і пішов дивитись. Відмова на кроці 1 — це система дозволів: інструмент не отримав права на частину команди й чесно про це сказав (докладно — модуль 7). Крок 2 — агент не зупинився й не поскаржився, а переформулював дію. Крок 3 — перевірка того, що він порахував. Крок 4 — відповідь.

Ти теж усередині циклу

Документація формулює це дослівно: «Ти теж частина цього циклу». Скерувати агента можна двома різними діями, і новачки знають лише про першу:

  • Esc — зупиняє Claude негайно. Інструмент, який виконувався цієї миті, скасовується, і програма чекає на твою наступну вказівку.
  • набрати текст і натиснути Enter — надсилає виправлення, не зупиняючи поточну дію. Claude прочитає його, щойно завершить те, що зараз робить, і врахує, обираючи наступний крок.

Це не «аварійне гальмо», а звичайний режим роботи. Дивитись, як агент іде не туди, і мовчки чекати кінця — найпоширеніша помилка перших днів.

Дві частини, з яких складається агент

Цикл рухають два компоненти: моделі, які міркують, і інструменти, які діють. Документація каже про це різко й точно: «Без інструментів Claude може лише відповісти текстом».

Вбудовані інструменти документація ділить на п'ять категорій — кожна дає свій рівень самостійності:

Категорія Що дозволяє
Робота з файлами читати файли, редагувати код, створювати нові файли, перейменовувати
Пошук знаходити файли за шаблоном, шукати за вмістом, вивчати структуру проєкту
Виконання запускати команди терміналу, піднімати сервери, ганяти тести, працювати з git
Вебдоступ шукати в інтернеті, читати документацію, дивитись текст помилки
Розуміння коду бачити помилки типів після правок, переходити до визначень, шукати використання

Це основа, до якої пізніше додаються навички (skills), під'єднання зовнішніх сервісів через MCP, перехоплювачі подій (hooks) і субагенти — кожному з цих слів присвячений окремий модуль, з 14-го по 18-й. Зараз достатньо знати, що вони надбудовуються над тим самим циклом, а не замінюють його.

До чого агент має доступ, коли ти запускаєш його в папці

Перелік із документації, дослівно за змістом:

  • твій проєкт — файли в папці, з якої ти запустив, і в її підпапках; інші файли — лише з твого дозволу;
  • твій термінал — будь-яка команда, яку міг би виконати ти;
  • стан git — поточна гілка, незбережені зміни, історія комітів;
  • файл CLAUDE.md — твої постійні інструкції для проєкту (модуль 12);
  • автоматична пам'ять — те, що Claude сам занотував про твої звички під час роботи (модуль 12);
  • розширення, які ти налаштував — зовнішні сервіси, навички, субагенти, керування браузером.

Зверни увагу на перший пункт: доступ починається з тієї папки, у якій ти набрав claude, а не з усього комп'ютера. Це головна причина, чому модуль 1 стільки уваги приділив поточній папці.

Де фізично виконується код

Це питання здається технічним, а насправді воно про безпеку: від відповіді залежить, чиї файли зміняться. Документація називає три середовища виконання. 

flowchart TD
  M["Модель Claude — міркує"] --> H["Claude Code — інструменти, контекст, середовище виконання"]
  T["Інструменти — діють"] --> H
  H --> L["Local — код виконується на твоїй машині"]
  H --> C["Cloud — код виконується на віддалених машинах"]
  H --> R["Remote Control — код на твоїй машині, керування з браузера"]
  style H fill:#2A211C,stroke:#D97757,color:#F0EEE6

Обв'язка та сама, цикл той самий — змінюється лише те, де виконується код

Середовище Де виконується код Навіщо
Local твоя машина режим за замовчуванням: повний доступ до твоїх файлів та інструментів
Cloud віртуальні машини Anthropic або сервери твоєї організації віддати задачу й піти; працювати з репозиторієм, якого немає локально
Remote Control твоя машина, керована з браузера користуватись вебінтерфейсом, лишаючи файли й виконання в себе

Увесь цей курс — про Local. Хмарні й віддалені варіанти оглядово розібрані в модулі 20.

4Зроби сам

Claude Code ще не встановлений, тому вправа цього модуля — не про нього, а про тебе: навчитись формулювати задачу так, як її розуміє агент. Це вміння дає більше, ніж знання команд, і саме воно відрізняє людину, якій інструмент допомагає, від людини, яка з ним воює.

Крок 1. Зроби папку для вправ

Відкрий термінал (модуль 1) і набери три команди, натискаючи Enter після кожної. Перша створює папку, друга заходить у неї, третя друкує, де ти опинився.

Живий запуск 4 вересня 2026 року, macOS 26.5.2, оболонка zsh. Ім'я користувача в запрошенні й у шляху замінене на anna, решта дослівна. На Windows у PowerShell ті самі три команди працюють так само, тільки шлях виглядатиме як C:\Users\Anna\ait-practice.

Крок 2. Напиши одну задачу двома способами

Візьми будь-яку справу зі свого життя, у якій є комп'ютер: розібрати папку «Завантаження», зробити з фотографій альбом, полагодити щось на сайті, зібрати звіт із трьох файлів. Створи в папці ait-practice файл task.txt (найлегше — через будь-який текстовий редактор) і напиши в ньому дві версії однієї й тієї самої задачі.

  • Диктант. Ти вказуєш кожен крок: який файл відкрити, який рядок змінити, яку команду виконати.
  • Делегування. Ти описуєш, що не так і що вважатимеш зробленим, а спосіб лишаєш агентові. Зразок із документації: «Оформлення замовлення зламане для користувачів із простроченими картками. Відповідний код у src/payments/. Можеш розібратися й полагодити?»

Друге формулювання довше за перше на одне речення, і саме воно працює краще. Перевір свій варіант делегування за трьома питаннями: чи названо симптом · чи вказано, де приблизно шукати · чи сказано, за якою ознакою вважати задачу закритою.

Крок 3. Додай до задачі перевірку

Допиши в task.txt третій рядок: як ти сам зрозумієш, що задача зроблена. Не «має працювати», а щось таке, що можна побачити: сторінка відкривається без помилки, у папці лишились тільки файли за 2026 рік, тест дає «пройдено».

Це не формальність. Документація формулює причину так: «Claude зупиняється, коли робота виглядає зробленою. Без перевірки, яку він може запустити, "виглядає зробленою" — єдиний доступний сигнал, і роль перевіряльника лишається тобі: кожна помилка чекає, поки ти її помітиш». До цього ми повернемось у блоці 6.

Крок 4. Обери свою поверхню

Claude Code існує не лише в терміналі. Ось повний перелік із документації, станом на 4 вересня 2026 року:

Поверхня Для чого вона, за документацією

5Як перевірити, що вийшло

У цьому модулі перевіряти треба дві різні речі: чи зробилась вправа й чи склалась ментальна модель. Перше робить команда, друге — чотири питання.

Перевірка вправи

Перебуваючи в папці ait-practice, набери ls. Ця команда друкує перелік того, що лежить у поточній папці. Якщо файл створився — його ім'я з'явиться у відповіді.

Живий запуск 4 вересня 2026 року, macOS 26.5.2. Порожня відповідь означала б, що файл зберігся не туди — найчастіше в папку, яку редактор запропонував за замовчуванням.

Ще одна корисна перевірка — і її нормальний результат

Набери claude --version. Якщо Claude Code ще не встановлений, ти побачиш повідомлення виду zsh: command not found: claude. Це очікувана відповідь на цьому етапі курсу, а не поломка: у модулі 1 розібрано, що вона означає «оболонка перебрала папки зі списку PATH і не знайшла програми з таким іменем». Встановлення — наступний модуль.

Перевірка розуміння

Дай собі відповідь уголос або на папері. Якщо на якесь питання відповіді немає — повернись до названого блоку, це швидше, ніж наздоганяти пізніше.

  1. Чому чат не може порахувати рядки у твоєму файлі, а Claude Code може? (блок 1 і блок 2)
  2. Назви три фази агентного циклу й скажи, яка з них найчастіше пропускається без твоєї участі. (блок 3)
  3. Чим Esc відрізняється від «набрати виправлення й натиснути Enter»? (блок 3)
  4. Твій код виконується на твоїй машині чи на чужій, якщо ти працюєш у терміналі? А якщо у вебверсії? (блок 3)

6Типові граблі

1. Ставитись до агента як до чату

Найпоширеніше. Виглядає так: людина пише одне коротке речення на кшталт «як виправити цю помилку?», отримує пораду текстом і йде робити руками. Інструмент при цьому не зробив нічого з того, заради чого існує.

Ознака: ти читаєш відповідь і сам переносиш її у файли. Виправлення: формулюй задачу, а не питання. «Полагодь» замість «як полагодити».

2. Вручну вставляти код у запит

Звичка з інструментів, які бачать лише відкритий файл. Людина копіює три екрани коду в запит, боячись, що інакше агент не зрозуміє. Документація каже прямо: «Claude Code читає файли твого проєкту за потреби. Тобі не треба додавати контекст вручну».

Шкода від цієї звички не лише в часі: усе вставлене займає місце в контекстному вікні, а воно скінченне й коштує грошей. Про це — модулі 6 і 11.

3. Боятись перервати

Людина бачить, що агент іде не туди, і сидить, чекаючи, поки він закінчить. Утрачений час плюс зіпсований контекст. Esc — штатний спосіб керування, а не аварійна кнопка; про це прямо написано в документації, і саме тому переривання розібране в блоці 3, а не в кінці курсу.

4. Плутати Claude Code з Claude у браузері

Назви схожі, суть різна. У терміналі код виконується на твоїй машині, і зміни відбуваються у твоїх файлах. У вебверсії claude.ai/code сесія працює в хмарі, на віддаленій машині. Наслідки різні буквально в усьому: що зміниться, що видно, що лишиться після від'єднання.

5. Vibe coding: де він працює, а де ні

Vibe coding («кодинг на відчуттях») — вислів спільноти для способу роботи, у якому людина описує бажаний результат словами й приймає те, що вийшло, не читаючи код.

Чесно про джерело терміна

Слова vibe немає в документації Claude Code взагалі. Перевірено двічі: дослідники курсу пройшли 13 сторінок документації та її повний покажчик 3 вересня 2026 року, і ще раз — 4 вересня, пошуком по завантажених сторінках overview, quickstart, how-claude-code-works, best-practices, common-workflows і покажчику llms.txt. Нуль збігів. Тобто це термін спільноти, а не назва режиму в продукті: шукати кнопку «vibe» немає сенсу.

Де такий спосіб роботи справді працює. Сама документація описує саме його як нормальний: «Замість того щоб писати код самому й просити Claude його переглянути, ти описуєш, чого хочеш, і Claude сам з'ясовує, як це зробити». Тобто описувати результат словами — не помилка, а задум інструмента. Це добре працює там, де ціна помилки низька й видима одразу: чернетки, разові скрипти, обробка своїх файлів, навчальні проєкти, прототип, який ти сам і подивишся.

Де він ламається. Документація називає цю пастку окремим іменем — the trust-then-verify gap, «розрив між довірою і перевіркою»: «Claude видає реалізацію, яка виглядає переконливо, але не враховує граничних випадків». І дає рецепт одним реченням: «Завжди забезпечуй перевірку — тести, скрипти, знімки екрана. Якщо ти не можеш це перевірити, не випускай це».

Звідси чесна межа, і вона проходить не там, де здається. Не «маленький проєкт можна, великий не можна», а:

  • є перевірка, яку можна запустити й отримати «пройшло / не пройшло» → працювати словами можна, і це нормальний режим;
  • перевірки немає, а результат бачать інші люди, гроші чи чужі дані → перевіряльником стаєш ти, і кожна пропущена помилка чекає, поки ти її помітиш.

Третя фаза циклу — «перевірити результат» — не випадково стоїть у самій основі інструмента. Vibe coding не поганий і не хороший; він рівно настільки надійний, наскільки надійна перевірка, яку ти йому дав.

6. Чекати, що агент прочитає думки

Протилежна крайність до диктанту. «Зроби мені гарно» не працює з тієї ж причини, з якої не спрацювало б із людиною: немає ані симптому, ані ознаки готовності. Документація радить думати про це «як про делегування здібному колезі»: контекст і напрямок — від тебе, деталі — від нього.

7Часті питання

Чи треба вміти програмувати?

Щоб пройти цей курс — ні. Документація описує Claude Code ширше за код: він «допоможе з будь-чим, що ти можеш зробити з командного рядка: писати документацію, запускати збірки, шукати у файлах, досліджувати теми». Але є чесна поправка з блоку 6: чим менше ти розумієш у предметі, тим важливіше мати перевірку, яку можна запустити. Без розуміння й без перевірки лишається тільки віра, що вийшло.

Чому курс лише про термінал, якщо є застосунок і розширення?

Дві причини, обидві з документації. Перша: «CLI — найповніша поверхня для роботи в терміналі», і частина можливостей існує лише там. Друга, важливіша: «Інтерфейс визначає, як ти бачиш Claude і взаємодієш із ним, але агентний цикл під ним ідентичний». Тобто вивчене в терміналі переноситься на застосунок, розширення й вебверсію. У зворотний бік це працює гірше: у застосунку багато механізмів заховано, і коли щось піде не так, дивитись буде нікуди.

А зовсім без термінала можна?

Можна. Документація каже дослівно: «Якщо ти волієш не користуватися терміналом, Desktop дає той самий рушій із графічним інтерфейсом». Порада курсу все одно лишається: пройди хоча б перші модулі в терміналі, а потім обирай. Рішення, ухвалене після того, як ти побачив обидва варіанти, коштує дешевше.

Чи бачить Claude Code увесь мій комп'ютер?

Ні. Доступ починається з папки, у якій ти запустив claude, і поширюється на її підпапки; інші місця — «лише з твого дозволу». Плюс термінал і стан git у цій папці. Як саме влаштовані дозволи, що таке захищені шляхи й чому в блоці 3 агент отримав відмову — модуль 7, один із найважливіших у курсі.

Це те саме, що Claude у браузері, тільки в іншому вікні?

Ні, і різниця не косметична. Модель та сама, обв'язка різна: у чаті немає доступу до твоїх файлів і терміналу. Плюс різне середовище виконання — термінал працює на твоїй машині, claude.ai/code у хмарі. Це різні наслідки для файлів, для приватності й для того, що станеться, коли ти закриєш ноутбук.

Скільки це коштує?

У курсі під це є окремий модуль 11 — там і про підписки, і про те, як не спалити ліміт за годину. Тут одна деталь, яку варто знати вже зараз: різні плани відкривають різні можливості на різних поверхнях, і документація позначає це прямо в таблиці платформ. Конкретних лімітів цей курс не наводить свідомо — і не тому, що ми їх не знайшли: їх немає в самій документації. Скільки встигнеш до межі, залежить від довжини й складності розмов, моделі та задіяних можливостей, тому фіксованої кількості повідомлень не існує. Ціни за токен у модулі 11 є — але завжди з датою звірки, бо вони змінюються швидше, ніж встигає оновитись навчальний матеріал.

Версія на екранах у мене інша. Це проблема?

Ні, і цього варто чекати. Документація випереджає будь-яку встановлену збірку: на 3 вересня 2026 року розрив між документацією та збіркою, на якій знімався цей курс, складав близько двадцяти версій. Тому в курсі біля кожного екрана стоїть версія, а головна навичка, яку він дає, — звіряти факт живою командою, а не статтею. Окремий модуль 17 присвячений саме цьому.

8Підсумок і наступний крок

Якщо після цього модуля ти можеш пояснити знайомому, чому Claude Code не чат, і чому задачу для нього формулюють інакше, ніж питання для пошуковика, — модуль зробив свою роботу.

Підсумок модуля
  • Claude Code — агент: він сам читає файли, запускає команди, вносить зміни й перевіряє результат. Чат друкує текст, підказки в редакторі бачать лише відкритий файл.
  • Модель та сама, що в чаті. Різниця — в обв'язці: інструменти, керування контекстом, середовище виконання. Документація називає це agentic harness.
  • Агентний цикл — три фази: зібрати контекст → діяти → перевірити результат, і по колу, доки не зійдеться.
  • Ти всередині циклу: Esc зупиняє негайно, набраний текст із Enter скеровує, не зупиняючи поточної дії. Обидва способи — штатні.
  • Без інструментів модель уміє лише відповідати текстом. Інструментів п'ять категорій: файли, пошук, виконання, веб, розуміння коду.
  • Доступ агента починається з папки, у якій ти його запустив.
  • Середовищ виконання три: Local, Cloud, Remote Control. Курс — про Local.
  • Поверхонь шість: CLI, Desktop, VS Code, JetBrains, Web, Mobile. Цикл під ними однаковий, тому вивчене в терміналі переноситься на решту.
  • Vibe coding — термін спільноти, у документації його немає. Працює там, де є перевірка; ламається там, де її немає. Правило з документації: не можеш перевірити — не випускай.

Наступний крок

Далі — модуль 3 «Встановлення й перший вхід»: чотири операційні системи, різниця між каналами оновлення (і чому вона важливіша, ніж здається), підписка проти ключа доступу, команда claude doctor для перевірки встановлення й окрема історія про те, чому одна з поширених установок не оновлюється сама.

Файл task.txt, який ти написав у блоці 4, не видаляй. У модулі 4 ти даси цю саму задачу агентові й побачиш різницю між двома формулюваннями на власному прикладі.

Квіз: перевір себе

Шість питань без оцінок і дедлайнів. Вони перевіряють розуміння, а не пам'ять на назви: до кожної відповіді одразу з'являється пояснення, чому решта варіантів хибні.

Модуль позаду?

Познач його завершеним — позначка збережеться в цьому браузері й з'явиться на головній сторінці.
