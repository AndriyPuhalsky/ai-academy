Встановлення й перший вхід

Початковий · 8 блоків · ≈ 45 хв читання

Встановити Claude Code — це одна команда. Проблема в тому, що команд таких шість, вони дають різні результати, і вибір, зроблений тут за десять секунд, визначає, яку версію програми ти бачитимеш наступні місяці. Половина питань на кшталт «у мене немає фічі, про яку пише документація» народжується саме в цьому модулі — і закривається теж тут.

Другий крок — вхід. Claude Code не працює без облікового запису, і безкоштовний план claude.ai доступу до нього не дає. Тут розберемо, які акаунти підходять, чим підписка відрізняється від ключа API і чому один забутий рядок у налаштуваннях оболонки може мовчки перебити активну підписку.

Що знадобиться до початку

Термінал — вікно, у яке набирають команди. Якщо слова «поточна папка», PATH і command not found ще нічого не означають, спершу модуль 1: там усе це пояснено з нуля, і далі я на нього посилаюсь без повторів.

Платний обліковий запис. Документація каже дослівно: «Claude Code requires a Pro, Max, Team, Enterprise, or Console account. The free Claude.ai plan does not include Claude Code access» — «потрібен акаунт Pro, Max, Team, Enterprise або Console; безкоштовний план claude.ai доступу до Claude Code не дає». Це перше, що варто перевірити, і про це — блок 3.

Комп'ютер, який тягне. Мінімум — 4 ГБ оперативної пам'яті й одна з систем зі списку в блоці 4. Інтернет потрібен постійно: модель, яка відповідає, працює на серверах Anthropic, а не на твоєму комп'ютері.

1Навіщо це

Claude Code — це програма, яку треба покласти на свій комп'ютер. Не сайт, не вкладка браузера: файл, який запускається командою claude у терміналі. Тому встановлення тут не формальність перед «справжнім» матеріалом, а перше місце, де курс може зламатись мовчки.

Чому вибір способу встановлення — це не дрібниця

Anthropic — компанія, яка робить Claude, — випускає нові версії Claude Code майже щодня. І роздає їх двома потоками, які в документації називають каналами релізів (release channels):

  • latest — «receive new features as soon as they're released», тобто нові версії приїжджають одразу, щойно вийшли;
  • stable — «use a version that is typically about one week old, skipping releases with major regressions»: версія приблизно тижневої давнини, з якої викинуті випуски з великими поломками.

Різниця звучить нешкідливо, доки не побачиш її в числах. Ось два пакети Claude Code для менеджера пакетів Homebrew на macOS, перевірені 4 вересня 2026 року: у стабільному каналі — версія 2.1.236, у свіжому — 2.1.251. Між ними п'ятнадцять випусків. Кожен із них міг додати команду або налаштування, про які документація вже пише як про наявні.

Головна пастка всього курсу

Людина ставить Claude Code найпростішим способом, через тиждень читає документацію про якусь можливість, набирає команду — і бачить, що її немає. Вона починає шукати помилку в собі: не так набрала, не туди встановила, зламала налаштування.

Насправді не сталося нічого поганого: у неї інший канал релізів, і все. Цей модуль існує здебільшого заради того, щоб ти впізнав цю ситуацію за хвилину, а не за вечір.

Друга половина модуля — вхід

Після встановлення Claude Code не працює, доки ти в нього не зайдеш. Способів входу більше, ніж здається: підписка Claude (Pro, Max, Team, Enterprise), обліковий запис Claude Console з оплатою за використання, корпоративні хмарні провайдери й довгоживучий токен для автоматичних запусків. Вони не лише співіснують — вони вишикувані в жорсткий порядок пріоритету, і той, що вище, мовчки перебиває той, що нижче. Це один із найчастіших сюжетів «усе працювало, а тепер помилка авторизації», і в блоці 3 буде видно, чому.

Що ти вмітимеш після цього модуля

  • встановити Claude Code на своїй системі свідомо обраним способом;
  • сказати, у якому ти каналі й чому в тебе саме ця версія;
  • оновити програму руками, коли вона не оновлюється сама;
  • увійти в обліковий запис і перевірити, під ким саме ти зайшов;
  • прочитати вивід claude doctor — короткої діагностики, яка відповідає на більшість питань про встановлення.

2Як це виглядає на екрані

Дві команди відповідають майже на все, що стосується встановлення. claude --version друкує номер версії. claude doctor друкує діагностику: як програма встановлена, де лежить, хто керує її оновленнями і чим закінчилась остання спроба оновитись. Документація описує її так: «prints read-only installation and settings diagnostics without starting a session» — тобто це перевірка тільки на читання, сесія з Claude при цьому не запускається й нічого не витрачається.

Нижче — справжній вивід обох команд, знятий на робочій машині автора курсу.

Знято 4 вересня 2026 року: macOS 26.5.2 на процесорі Apple Silicon, Claude Code 2.1.236, встановлений через Homebrew. Вивід дослівний, нічого не прибрано й не підправлено. На твоєму комп'ютері рядки Path, Package manager і Platform будуть іншими — вони й описують саме твою установку.

Як прочитати цей вивід рядок за рядком

Рядок Що він каже
Running: package-manager (2.1.236) тип установки, яка зараз запущена, і номер версії. Тут — установка, якою керує менеджер пакетів

Рядки Commit і Config install method службові: документація їх окремо не описує, і для роботи вони не потрібні. Блок Remote Control — про керування сесією з телефона; це тема модуля 20.

Один рядок у цьому виводі оманливий

Auto-update channel: latest виглядає як відповідь на питання «у якому я каналі». Але встановлено тут пакет claude-code, а це, за документацією, канал stable. Суперечності немає: цей рядок показує значення налаштування autoUpdatesChannel, у якого канал latest — значення за замовчуванням. А для установок через Homebrew документація каже дослівно: «Homebrew installations choose a channel by cask name instead of this setting» — канал вирішує назва пакета, а не це налаштування.

Практичний висновок: якщо ти ставив через Homebrew, у питанні каналу вір назві пакета, а не рядку Auto-update channel. Як подивитись назву — нижче.

Два пакети Homebrew — і різниця між ними в числах

Homebrew — популярний менеджер пакетів для macOS: програма, яка встановлює інші програми однією командою. Claude Code роздається в ньому двома пакетами (у Homebrew їх називають casks). Команда brew info показує, яка версія зараз у кожного, нічого не встановлюючи. Приписка | head -1 означає «покажи тільки перший рядок відповіді».

Знято 4 вересня 2026 року на macOS 26.5.2. Два пакети з тим самим Claude Code відрізняються на п'ятнадцять версій: 2.1.236 проти 2.1.251. Ці числа застаріють — важлива не їхня величина, а сам факт розриву. Повтори ці дві команди в себе, і побачиш свою пару чисел.

Тепер той самий сюжет словами. Дослідники цього курсу 3 вересня 2026 року звірили документацію з локальною збіркою 2.1.236 і нарахували розрив приблизно у двадцять випусків, а в ньому — десяток можливостей, які документація вже описує, а в цій версії їх ще немає: серед них окремий рядок про кеш у команді /usage (потрібна 2.1.251) і налаштування часу життя кешу (потрібна 2.1.242). Тобто розрив між каналами — не теоретичний: він рівно про ті команди, які ти читатимеш у наступних модулях.

3Як це працює

Тут два незалежні механізми: як програма потрапляє на комп'ютер і оновлюється — і як вона розуміє, хто ти. Розберемо по черзі.

Спосіб встановлення вирішує все інше

Способів шість, і вони діляться на дві групи. Перша — рідний інсталятор (native installer): скрипт, який Anthropic роздає за адресою claude.ai/install.sh. Він кладе програму в твою домашню папку й далі стежить за нею сам. Документація про нього: «Native installations automatically update in the background to keep you on the latest version» — оновлюється у фоні без твоєї участі.

Друга група — менеджери пакетів: Homebrew на macOS, WinGet на Windows, apt, dnf, apk на Linux, а також npm. Це програми, які встановлюють і оновлюють увесь софт на машині централізовано. Claude Code у них теж є — але оновлює його вже не Claude Code, а вони. Документація: «Homebrew, WinGet, apt, dnf, and apk installations do not auto-update by default».

Автооновлення у фоні є рівно в однієї гілки — рідного інсталятора. Усі решта оновлюються тільки рукою

Звідси відповідь на питання з назви модуля — чому Homebrew не оновлюється сам. Не тому, що щось зламано, і не тому, що ти щось пропустив: так влаштовано. Менеджер пакетів вважає себе єдиним господарем встановленого софту, і програма, яка сама себе перезаписує в його папці, для нього ненормальна ситуація. Саме це видно в живому виводі з блоку 2: Auto-updates: Managed by package manager, а нижче — невдала спроба оновитись, failed (install_failed).

Виняток, про який варто знати

Документація описує спосіб попросити Claude Code самому виконувати команду оновлення менеджера пакетів: змінна оточення CLAUDE_CODE_PACKAGE_MANAGER_AUTO_UPDATE зі значенням 1. Працює для Homebrew і WinGet: «Claude Code then runs the upgrade in the background when a new version is available and shows a restart prompt on success». Для apt, dnf і apk так не можна — їхні команди потребують прав адміністратора.

Тобто точне формулювання таке: жоден пакет Homebrew не оновлюється сам, але Claude Code можна попросити натиснути цю кнопку за тебе. Змінні оточення — тема модуля 13; поки що достатньо знати, що така можливість існує.

Канал можна змінити, версію — зафіксувати

  • Налаштування autoUpdatesChannel має два значення: "latest" (за замовчуванням) і "stable". Змінюється в сесії через /config → Auto-update channel або в файлі settings.json — це модуль 13. Для установок через Homebrew воно не діє: там канал вирішує назва пакета.
  • Команда claude install ставить рідну збірку й приймає або канал, або конкретний номер версії. Документація: «The channel you choose at install time becomes your default for auto-updates».
  • Налаштування minimumVersion задає нижню межу: фонове оновлення й claude update відмовляться поставити версію нижчу за вказану. Це рятує від несподіваного відкату назад під час переходу з latest на stable.

Вхід: сім джерел одного дозволу

Claude Code має розуміти, від чийого імені звертатись до сервера. Джерел, з яких він може взяти цей дозвіл, сім, і вони не рівноправні: програма перебирає їх згори вниз і бере перше, що знайшла. Документація називає цей порядок «authentication precedence».

Для звичайного користувача важливі рівно два з семи — нижній і третій.

Підписка Claude Ключ API з Claude Console

Третій рядок цієї таблиці — джерело найпоширенішої плутанини. Документація описує наслідок дослівно: «If you have an active Claude subscription but also have ANTHROPIC_API_KEY set in your environment, the API key takes precedence once approved. This can cause authentication failures if the key belongs to a disabled or expired organization». Тобто активна підписка є, помилка авторизації теж є, і причина — старий ключ, який хтось прописав у налаштуваннях оболонки пів року тому. Ліки в блоці 6.

Де зберігається вхід

Після успішного входу Claude Code запам'ятовує тебе, і повторювати вхід не треба. Місце залежить від системи:

  • macOS — у зашифрованому сховищі системи (Keychain). Якщо записати туди не вдалось, наприклад, коли сховище заблоковане у віддаленому сеансі, Claude Code кладе вхід у файл ~/.claude/.credentials.json з правами 0600 — «читати й писати може тільки власник»;
  • Linux — файл ~/.claude/.credentials.json, права 0600;
  • Windows — файл %USERPROFILE%\.claude\.credentials.json, захищений правами твого профілю користувача.

Практичний висновок один: цей файл — такий самий секрет, як пароль. Його не викладають у репозиторій, не пересилають і не копіюють на чужу машину.

Далі — встановлення на твоєму комп'ютері. Це перша дія курсу, яка справді щось змінює в системі, тому кроки розписані дрібно.

Крок 2. Обери спосіб

Рекомендація документації — рідний інсталятор, він позначений як «Native Install (Recommended)». Для цього курсу вона теж найкраща, і причина проста: це єдиний спосіб, який оновлюється сам, тобто твоя версія не відстане від того, що описано в наступних модулях.

npm · будь-де, потрібен Node.js 22+ npm install -g @anthropic-ai/claude-code ні
apt, dnf, apk · Linux окремі підписані репозиторії, команди — у документації ні

Команди дослівно з офіційної документації Claude Code, сторінка «Advanced setup», прочитана 4 вересня 2026 року. Стовпчик «оновлюється сам» — переказ фрази «do not auto-update by default» з тієї самої сторінки.

Крок 3. Виконай команду для своєї системи

На macOS, Linux і WSL це один рядок. Знак % на початку набирати не потрібно — це запрошення, яке термінал друкує сам (модуль 1).

Вивід цієї команди в курсі не показаний свідомо. Автор працює на macOS зі збіркою з Homebrew, тобто зняти справжній екран рідного встановлення не може, а домальовувати вивід правилами курсу заборонено. Що станеться насправді: інсталятор завантажить програму й надрукує кілька рядків про хід роботи, після чого поверне запрошення.

На Windows команда залежить від того, яке вікно ти відкрив. Ознака з модуля 1: PowerShell показує на початку рядка PS C:\Users\YourName>, CMD — той самий рядок без PS. Помилишся вікном — побачиш одну з двох фраз, які документація наводить дослівно:

  • The token '&&' is not a valid statement separator — це означає «ти в PowerShell, а набрав команду для CMD»;
  • 'irm' is not recognized as an internal or external command — навпаки, «ти в CMD, а набрав команду для PowerShell».

Прав адміністратора для встановлення на Windows не потрібно — документація зазначає це окремо: «You do not need to run as Administrator».

Крок 4. Відкрий новий термінал і перевір

Це не зайвий крок. Інсталятор кладе програму в папку ~/.local/bin на macOS і Linux, а на Windows — у %USERPROFILE%\.local\bin. Щоб оболонка знаходила її за одним іменем claude, ця папка має бути у списку PATH з модуля 1, а вже відкрите вікно термінала про зміни в PATH не дізнається. Документація радить у цьому місці рівно те саме: «Alternatively, close and reopen your terminal». Тож закрий вікно, відкрий нове й набери:

claude --version

Якщо надрукувався номер із приміткою (Claude Code) — програма стоїть і запускається. Якщо натомість command not found: claude — це не поломка установки, а PATH; лікується в блоці 6.

Крок 5. Зайди в папку проєкту й запусти

Claude Code працює з тією папкою, у якій його запустили. Тому спершу cd, і тільки потім claude:

  1. cd ~/my-site — заміни на свою папку. Немає жодної — створи порожню командою mkdir ~/claude-test і зайди в неї;
  2. claude — запускає програму.

Крок 6. Увійди в обліковий запис

Під час першого запуску Claude Code відкриє браузер. Далі дослівно за документацією, бо цей екран інтерактивний і зняти його текстом неможливо:

  • браузер відкривається сам. Якщо не відкрився — натисни клавішу c, і адреса для входу скопіюється в буфер обміну; встав її в браузер руками;
  • увійди у свій акаунт Claude у вікні браузера;
  • якщо браузер показав код замість того, щоб повернути тебе назад — скопіюй цей код і встав у термінал на запит Paste code here if prompted. Документація зазначає, що так буває у WSL2, у сеансах через SSH і в контейнерах;
  • коли вхід завершився, термінал друкує Login successful і просить натиснути Enter.

Далі перепроходити вхід не треба: облікові дані зберігаються на комп'ютері (де саме — у блоці 3). Змінити акаунт можна командою /login усередині сесії, вийти — /logout.

Той самий вхід є і окремою командою термінала — claude auth login, а поруч із нею claude auth logout і claude auth status. У login є чотири прапорці, і саме тут проходить межа «підписка проти ключа API»: --claudeai — вхід підпискою Claude, це поведінка за замовчуванням; --console — вхід через Claude Console, тобто з оплатою за використання; --sso — корпоративний вхід; --email — підставити адресу на сторінці входу. Перевірено на живій збірці 2.1.236 (macOS, 2026-09-04) і звірено з довідником команд документації того самого дня.

Три деталі про перший запуск

Безкоштовний план не підходить. Якщо в тебе звичайний безкоштовний акаунт claude.ai, вхід відбудеться, а робота — ні. Потрібен Pro, Max, Team, Enterprise або Console.

Якщо в оточенні є ANTHROPIC_API_KEY, браузер не відкриється взагалі: замість входу Claude Code один раз спитає, чи використовувати цей ключ.

Перша сесія відрізняється від наступних. Документація зазначає, що в найпершій сесії після встановлення частина можливостей ще не підтягнулась, і сесія може стартувати в ручному режимі дозволів навіть на тих планах, де зазвичай стартує автоматичний. Це не поломка й не твоя помилка — у наступній сесії все на місці. Що таке режими дозволів і чому починати варто саме з ручного — модуль 4.

5Як перевірити, що вийшло

Три команди дають три різні відповіді, і жодна з них не здогадка. Нижче — справжній вивід усіх трьох підряд на машині автора.

Знято 4 вересня 2026 року, macOS 26.5.2, Claude Code 2.1.236 з Homebrew. Замінена рівно одна річ: справжня адреса пошти автора скрізь замінена на anna@example.com. Решта дослівна, включно з рядком Organization, який Claude Code складає з тієї самої адреси.

Що саме перевіряє кожна команда

Питання Команда Як прочитати відповідь
Програма встановлена й запускається? claude --version надрукований номер із приміткою (Claude Code) — так; command not found — ні
Скільки в мене установок і де вони? which -a claude один рядок — одна установка, і це нормально. Два і більше — конфлікт версій, див. блок 6
Під ким я зайшов і що в мене за план? claude auth status --text рядок Login method називає тип акаунта
Як воно встановлене й чи є проблеми? claude doctor останній рядок: No installation issues found. або перелік проблем
Команда, яка відповідає «так» або «ні» без слів

Документація про claude auth status: «Exits with code 0 if logged in, 1 if not» — команда повертає нуль, якщо ти залогінений, і одиницю, якщо ні. Це так званий код завершення (exit code): число, яке кожна програма віддає оболонці, коли закінчила роботу; нуль означає «все добре».

Подивитись його можна командою echo $? одразу після перевірки — у блоці вище вона надрукувала 0. Само собою це дрібниця, але саме на кодах завершення тримаються автоматичні запуски з модуля 19: скрипт не читає текст, він читає число.

Перевірку доречно повторити ще раз через тиждень — і подивитись, чи змінився номер версії. Якщо в тебе рідна установка, він має зрости сам. Якщо не зріс жодного разу за місяць, ти або в каналі stable, або взагалі не в тій гілці, про яку думаєш — і тоді claude doctor покаже, у якій саме.

6Типові граблі

1. command not found: claude одразу після встановлення

Найчастіша ситуація в цьому модулі. Установка пройшла, а оболонка програму не бачить. Документація формулює причину прямо: папка, у яку інсталятор поклав claude, не входить у PATH. Ця папка — ~/.local/bin/claude на macOS і Linux, %USERPROFILE%\.local\bin\claude.exe на Windows.

Порядок дій:

  1. Закрий термінал і відкрий новий. Половина випадків лікується цим: вже відкрите вікно не бачить змін у PATH.
  2. Перевір, чи папка в списку. На macOS і Linux команда з документації: echo $PATH | tr ':' '\n' | grep -Fx "$HOME/.local/bin". Надрукувався шлях — папка в списку; порожньо — ні.
  3. Додай її. Для zsh (за замовчуванням на macOS): echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.zshrc, потім source ~/.zshrc. Для bash (більшість Linux) те саме з ~/.bashrc. Обидва рядки — дослівно з документації.
  4. Перевір: claude --version.

На Windows у PowerShell документація радить спершу подивитись $env:PATH -split ';' | Select-String '\.local\\bin', а потім, якщо порожньо, додати папку в PATH користувача й перезапустити термінал.

2. Дві установки одночасно

Ставив через Homebrew, потім спробував рідний інсталятор — і тепер на комп'ютері дві програми claude. Документація попереджає: «Multiple Claude Code installations can cause version mismatches or unexpected behavior». Симптом характерний: claude --version показує не ту версію, яку ти щойно поставив.

Діагностика — which -a claude (усі знайдені в PATH) і claude doctor (яка саме зараз запущена). Далі зайву прибирають так, як велить її спосіб установки: brew uninstall --cask claude-code, npm uninstall -g @anthropic-ai/claude-code, winget uninstall Anthropic.ClaudeCode або видалення файлів рідної установки — rm -f ~/.local/bin/claude і rm -rf ~/.local/share/claude.

3. Активна підписка, а Claude Code лається на авторизацію

Симптом із документації: API Error: 400 ... "This organization has been disabled" попри живу підписку. Причина — змінна ANTHROPIC_API_KEY в оточенні, найчастіше «стара, з попередньої роботи чи попереднього проєкту». За порядком пріоритету з блоку 3 ключ стоїть вище за підписку, тому підписка не використовується взагалі.

Що робити, дослівно за документацією:

  • на macOS і Linux — unset ANTHROPIC_API_KEY, потім запустити claude;
  • на Windows у PowerShell — Remove-Item Env:ANTHROPIC_API_KEY;
  • щоб не повернулось після перезапуску — знайти й прибрати рядок export ANTHROPIC_API_KEY=… у файлах ~/.zshrc, ~/.bashrc або ~/.profile;
  • перевірити результат командою /status усередині сесії.

4. «У мене немає команди, про яку пише документація»

Не поломка, а канал релізів — той самий сюжет із блоків 1 і 2. Порядок дій:

  1. claude doctor — подивитись рядки Package manager і версію;
  2. якщо там homebrew — brew upgrade claude-code або brew upgrade claude-code@latest, залежно від того, який пакет встановлений;
  3. якщо потрібен свіжий канал — перейти на пакет claude-code@latest або на рідну установку;
  4. для WinGet — winget upgrade Anthropic.ClaudeCode.

Окрема пастка Homebrew з документації: Cask 'claude-code' is unavailable: No Cask with this name exists означає, що застарів локальний перелік пакетів Homebrew. Ліки з документації — brew update, а потім повторити встановлення; шукати проблему в Claude Code тут немає сенсу.

5. Помилки, які варто впізнавати з першого погляду

Нижче — рядки дослівно з таблиці помилок офіційної документації, прочитаної 4 вересня 2026 року. Екранів тут немає навмисно: більшість цих помилок трапляється на Windows і Linux, а автор працює на macOS — вигадувати чужі екрани правилами курсу заборонено.

6. Дрібні, але дорогі помилки

  • sudo npm install -g — документація забороняє прямо: «Do NOT use sudo npm install -g as this can lead to permission issues and security risks». Якщо npm лається на права, лікувати треба права, а не тиснути sudo.
  • Alpine Linux без підготовки. Там немає навіть bash і curl, тому команда встановлення падає з not found. Спершу apk add bash curl libgcc libstdc++ ripgrep, потім змінна USE_BUILTIN_RIPGREP у значенні 0.
  • Windows без Git for Windows. Ставити його необов'язково, але без нього Claude Code виконує команди через PowerShell, а не через Bash. Якщо Git встановлений, а Claude Code його не знаходить, документація радить прописати шлях у налаштуванні CLAUDE_CODE_GIT_BASH_PATH.
  • Розширення для VS Code — не те саме, що встановлення. Документація зазначає окремо: розширення тримає власну копію Claude Code всередині себе й не кладе claude у PATH. Тобто після нього команда в терміналі не з'явиться.

7Часті питання

Чи безпечно запускати команду, яка тягне скрипт з інтернету й одразу його виконує?

Питання доречне: curl … | bash означає «завантаж і виконай не читаючи». Anthropic відповідає на нього криптографічно. Кожен випуск публікує файл manifest.json із контрольними сумами всіх збірок, підписаний ключем компанії; перевірка підпису підтверджує весь список одразу. Відбиток ключа — 31DD DE24 DDFA B679 F42D 7BD2 BAA9 29FF 1A7E CACE, перевірка — gpg --verify manifest.json.sig manifest.json, правильна відповідь містить Good signature. Підписи маніфестів існують для версій від 2.1.89 і новіших. Плюс сама програма підписана засобами системи: на macOS «signed by "Anthropic PBC" and notarized by Apple», перевірка — codesign --verify --verbose ./claude; на Windows — підпис «Anthropic, PBC». На Linux окремих підписів у файлів немає, але репозиторії apt, dnf і apk підписані, і менеджер пакетів перевіряє їх сам.

Скільки це коштує і який план потрібен?

Потрібен Pro, Max, Team, Enterprise або обліковий запис Claude Console з оплатою за використання. Безкоштовний план claude.ai Claude Code не дає. Детально про ліміти, вартість запитів і про те, коли ключ API дешевший за підписку, — модуль 11: там ця тема зібрана в одному місці, щоб не розмазуватись по всьому курсу.

Що обрати: Homebrew чи рідний інсталятор?

Для цього курсу — рідний інсталятор: він оновлюється сам, і твоя версія не відстане від матеріалу. Homebrew має сенс, коли ти вже тримаєш увесь софт на машині в ньому й хочеш оновлювати все однією командою; тоді свідомо обирай пакет claude-code@latest, якщо тобі потрібні свіжі можливості, і не забувай brew upgrade. Homebrew зберігає старі версії на диску — час від часу варто виконати brew cleanup.

Як перейти на інший канал або відкотитись на конкретну версію?

Рідна установка приймає ціль прямо в команді: claude install stable, claude install latest або конкретний номер, наприклад claude install 2.1.89. Обраний канал стає типовим для подальших автооновлень. Той самий вибір є в інсталяторі: curl -fsSL https://claude.ai/install.sh | bash -s stable. Перевірити результат — claude --version: команда друкує саме ту версію, яку ти назвав. Одне застереження: якщо в тебе вже є установка з менеджера пакетів, claude install додасть до неї другу, рідну — і вийде ситуація з пункту 2 блоку 6.

Чи потрібен Node.js?

Ні, якщо ти не ставиш через npm. Claude Code — самостійна програма; навіть при встановленні через npm вона тягне ту саму рідну збірку, а Node.js під час роботи не використовується. Але сама установка через npm від версії 2.1.198 потребує Node.js 22 або новішого.

Як повністю прибрати Claude Code з комп'ютера?

Спершу прибрати програму способом, яким ставив: rm -f ~/.local/bin/claude і rm -rf ~/.local/share/claude для рідної установки, brew uninstall --cask claude-code, winget uninstall Anthropic.ClaudeCode, npm uninstall -g @anthropic-ai/claude-code. Окремо — налаштування й історія: rm -rf ~/.claude і rm ~/.claude.json. Друга частина незворотна: разом з нею зникнуть усі налаштування, дозволи й історія сесій. І ще одне з документації: якщо на машині лишились розширення для VS Code чи JetBrains або застосунок для комп'ютера, папка ~/.claude з'явиться знову — вони теж у неї пишуть.

А що таке claude setup-token, який видно в довідці?

Це спосіб увійти там, де немає браузера: на сервері збірки, у скрипті, в автоматичному запуску. Команда відкриває той самий вхід через браузер і друкує в термінал токен строком на рік. Найважливіше про неї: вона нікуди його не зберігає — токен треба скопіювати самому й покласти у змінну оточення CLAUDE_CODE_OAUTH_TOKEN. Потребує підписки. Поводитись із ним треба як з паролем; докладно про автоматичні запуски — модуль 19.

Чи можна працювати взагалі без термінала?

Можна: є застосунок для комп'ютера під macOS, Windows і Linux, розширення для VS Code і JetBrains, вебверсія. Курс лишається про термінал з причини, названої в модулі 1: у ньому видно всі механізми, які в застосунку сховані. Але пам'ятай пастку з блоку 6: встановлення розширення для VS Code не робить команду claude доступною в терміналі.

Чому claude doctor, а не /doctor?

Це дві різні речі. claude doctor запускається з термінала, нічого не змінює й не відкриває сесію. /doctor набирається вже всередині сесії Claude Code — документація описує його як повнішу перевірку, яка вміє й лагодити знайдене. Обидва інструменти детально розібрані в модулі 17, присвяченому діагностиці.

8Підсумок і наступний крок

Якщо claude --version друкує номер, claude auth status --text називає твій акаунт, а claude doctor закінчується рядком No installation issues found. — модуль зробив свою роботу. Усе інше в курсі відбуватиметься вже всередині запущеної програми.

Підсумок модуля
  • Способів встановлення шість. Автооновлення у фоні є лише в рідної установки через claude.ai/install.sh. Homebrew, WinGet, apt, dnf, apk і npm самі не оновлюються — це задокументована поведінка, а не поломка.
  • Канали релізів два: latest — одразу після виходу, stable — приблизно тиждень пізніше, без випусків із великими поломками. Різниця буває в десятки версій: 4 вересня 2026 року пакети Homebrew показували 2.1.236 проти 2.1.251.
  • У Homebrew канал вирішує назва пакета: claude-code — stable, claude-code@latest — latest. Рядок Auto-update channel у виводі claude doctor для такої установки не показує реального каналу.
  • Claude Code потребує платного акаунта: Pro, Max, Team, Enterprise або Console. Безкоштовний план claude.ai доступу не дає.
  • Джерел входу сім, і вони мають жорсткий порядок. ANTHROPIC_API_KEY стоїть вище за підписку, тому забутий ключ у налаштуваннях оболонки мовчки перебиває її. Ліки — unset ANTHROPIC_API_KEY.
  • claude doctor — коротка діагностика без запуску сесії. Вона відповідає на «як я це встановив», «яка в мене версія», «хто керує оновленнями» і «чим закінчилась остання спроба оновитись».
  • Найчастіша проблема етапу — command not found: claude при успішній установці. Це PATH, і половина випадків лікується новим вікном термінала.

Наступний крок

Далі — модуль 4 «Перша сесія: проси, дивись, дозволяй»: як сформулювати задачу, як читати кроки, які Claude показує на екрані, що таке діалог дозволу й чому найпершу сесію варто провести в ручному режимі. Саме там стане в пригоді зауваження з кроку 6 цього модуля — про те, що перший запуск після встановлення поводиться інакше, ніж усі наступні.

До того часу — одна корисна звичка: перш ніж шукати причину дивної поведінки в собі, набери claude doctor і подивись на версію. Дуже часто відповідь саме там.

Квіз: перевір себе

Шість питань без оцінок і дедлайнів. Вони перевіряють розуміння, а не пам'ять на назви команд: до кожної відповіді одразу з'являється пояснення, чому решта варіантів хибні.
