Трек III · Розробка з Claude

Claude API: перші кроки

Середній · 6 уроків · ≈ 75 хв читання

Починається Трек III. Усе, що ти вмієш робити в чаті, тепер стане кодом: промпти — шаблонами, відповіді — даними, параметри — ручками керування. Модуль суто практичний: наприкінці в тебе буде скрипт, який спілкується з Claude, тримає багатокрокову розмову, стрімить відповіді й аналізує зображення. Основні приклади — Python, ключові — продубльовано TypeScript.

5.1Старт: ключ, SDK, перший запит

Знадобляться три речі: акаунт на платформі Anthropic (Console), API-ключ, створений там само, та офіційний SDK. Але перш ніж писати перший рядок коду — розмова про безпеку, бо ключ — це водночас твої гроші і твій доступ.

Правила поводження з ключем

Зберігай у змінних середовища (.env у .gitignore), ніколи не вшивай у код і не коміть у репозиторій. Ніколи не клади ключ у фронтенд: усе, що бачить браузер, бачить і чужинець — браузерні застосунки ходять до API лише через твій бекенд. Підозрюєш витік — негайно відклич ключ у Console і створи новий.

Встановлення SDK і ключ у середовищі:

Термінал
pip install anthropic            # Python
npm install @anthropic-ai/sdk    # TypeScript / Node.js

export ANTHROPIC_API_KEY="sk-ant-..."   # Linux / macOS

Перший запит — мінімум коду:

Python
from anthropic import Anthropic

client = Anthropic()  # ключ читається з ANTHROPIC_API_KEY

message = client.messages.create(
    model="claude-sonnet-5",  # актуальні назви моделей: docs.claude.com
    max_tokens=1024,
    messages=[
        {"role": "user", "content": "Привіт! Поясни одним абзацом, що таке токен."}
    ],
)

print(message.content[0].text)
TypeScript
import Anthropic from "@anthropic-ai/sdk";

const client = new Anthropic(); // ключ — зі змінної ANTHROPIC_API_KEY

const message = await client.messages.create({
  model: "claude-sonnet-5",
  max_tokens: 1024,
  messages: [
    { role: "user", content: "Привіт! Поясни одним абзацом, що таке токен." },
  ],
});

console.log(message.content[0].text);

Який рядок моделі писати? Правило з Модуля 1: найлегша модель, що стабільно тягне задачу, — Haiku для масових простих запитів, Sonnet для повсякденної роботи, Opus для найскладніших міркувань. Конкретні назви версій регулярно оновлюються, тож винось модель у константу чи конфіг і звіряйся з документацією.

5.2Messages API: анатомія запиту й відповіді

Уся робота з Claude крутиться навколо одного ендпойнта — Messages API. Запит складається з чотирьох головних частин:

  • model — яка модель відповідає;
  • max_tokens — обов'язкова стеля довжини відповіді;
  • system — системний промпт: роль і правила з Модуля 3;
  • messages — масив реплік user та assistant, що чергуються.
Класична помилка

Системний промпт — це окремий параметр system на верхньому рівні запиту, а не повідомлення з роллю «system» у масиві messages. У масиві живуть лише user та assistant.

Python · запит із системним промптом
message = client.messages.create(
    model="claude-sonnet-5",
    max_tokens=500,
    system="Ти — лаконічний асистент кейтерингової компанії. "
           "Відповідай українською, тепло і по суті.",
    messages=[
        {"role": "user",
         "content": "Сформулюй ввічливу відмову: на цю дату ми вже заброньовані."}
    ],
)

print(message.content[0].text)   # текст відповіді
print(message.stop_reason)       # чому генерація зупинилась
print(message.usage)             # input_tokens / output_tokens

У відповіді найважливіші три поля. content — масив блоків (текст лежить у content[0].text; чому масив — стане ясно в Модулі 6, коли з'являться блоки викликів інструментів). usage — скільки токенів з'їли вхід і вихід: це твої гроші, і згадай Модуль 1 — українська «коштує» більше токенів за англійську. І stop_reason — чому модель зупинилась:

stop_reason Що означає Що робити
end_turn Модель природно завершила думку Нічого — нормальний випадок
max_tokens Відповідь обірвано стелею довжини Збільш max_tokens або попроси продовжити
stop_sequence Зустрівся заданий тобою маркер зупинки Очікувана поведінка — див. урок 5.3
tool_use Модель хоче викликати інструмент Тема Модуля 6

  REQ --> API["Claude API"]
  API --> RES["JSON-відповідь: content, stop_reason, usage"]
  RES --> CODE2["Твій код: парсинг і використання"]

5.3Параметри генерації

Три ручки, які варто знати з першого дня: max_tokens, temperature і stop_sequences.

max_tokens — стеля, а не ціль: модель може завершити раніше, але ніколи не перевищить ліміт. Якщо stop_reason повернувся як max_tokens — відповідь обірвано на півслові: збільшуй стелю або проси продовження.

temperature (від 0 до 1) — та сама «дрібка керованої випадковості» з Модуля 1. Близько нуля вибір токенів максимально передбачуваний — те, що треба для фактів, екстракції та JSON. Ближче до одиниці — різноманітніше і живіше: брейншторм, креатив, варіанти.

Задача temperature
Екстракція даних, JSON, класифікація 0 – 0.2
Робочі тексти, відповіді на основі документів 0.3 – 0.7
Брейншторм, креатив, генерація варіантів 0.8 – 1.0

stop_sequences — список рядків, на яких генерація жорстко зупиняється. Ідеальна пара до тегів із Модуля 4: задай стоп-маркером закривний тег відповіді — і модель фізично не зможе «договорити зайвого».

Python · температура і стоп-маркер
message = client.messages.create(
    model="claude-sonnet-5",
    max_tokens=400,
    temperature=0,                    # фактична задача — мінімум випадковості
    stop_sequences=["</answer>"],   # крапка після закривного тега
    messages=[
        {"role": "user",
         "content": "Дай відповідь у тегах: спершу міркування у <thinking>, "
                    "потім висновок у <answer>. Питання: ..."}
    ],
)

Є й інші регулятори різноманіття — наприклад, top_p. Робоче правило: обирай один основний регулятор (зазвичай temperature) і не крути кілька одночасно без чіткої причини — інакше ефекти переплутаються і налагодити поведінку буде важко.

5.4Багатокрокові розмови

Перший сюрприз новачка: API нічого не пам'ятає. Кожен запит — з чистого аркуша. «Пам'ять» розмови — це масив messages, який ти сам надсилаєш щоразу повністю: усі попередні репліки користувача й асистента плюс нову. Це прямий наслідок того, що ми розібрали в Модулях 1 і 3: модель бачить лише контекст поточного запиту.

Python · мінімальний чат у терміналі
history = []

while True:
    user_text = input("Ти: ")
    history.append({"role": "user", "content": user_text})

    reply = client.messages.create(
        model="claude-sonnet-5",
        max_tokens=1024,
        system="Ти — дружній помічник. Відповідай українською.",
        messages=history,            # уся розмова — щоразу
    )

    answer = reply.content[0].text
    history.append({"role": "assistant", "content": answer})
    print("Claude:", answer)

Наслідок, про який варто думати одразу: історія росте, а з нею — вхідні токени кожного запиту, тобто час і гроші. Базові стратегії: обрізати найстаріші репліки, періодично замінювати їх стислим підсумком розмови, а великі довідкові матеріали підвантажувати вибірково — до цього підходу ми серйозно повернемося в Модулі 7.

І обіцяний у Модулі 3 трюк: префіл через API — це просто повідомлення асистента, додане останнім:

Python · префіл відповіді
reply = client.messages.create(
    model="claude-sonnet-5",
    max_tokens=300,
    temperature=0,
    messages=[
        {"role": "user",
         "content": "Витягни з відгуку sentiment та issues у JSON."},
        {"role": "assistant", "content": "{"},   # початок відповіді — наш
    ],
)

raw_json = "{" + reply.content[0].text   # модель продовжує ПІСЛЯ префіла

Зверни увагу на останній рядок: відповідь містить лише продовження, тож префікс приклеюєш сам перед парсингом. Дрібниця, яка ламає перший пайплайн кожному другому розробнику.

5.5Streaming: відповідь у реальному часі

Звичайний запит мовчить, доки модель не догенерує все, — на довгих відповідях це десятки секунд порожнього екрана. Streaming віддає текст у міру народження токенів: сумарний час майже той самий, але перші слова з'являються за мить — і користувач бачить життя. Саме так працює чат claude.ai, і саме цей ефект імітує заголовок головної сторінки нашого курсу. 

flowchart TD
  Q["Запит до API"] --> A["Без streaming"]
  Q --> B["Зі streaming"]
  A --> A2["Тиша... потім уся відповідь одним шматком"]
  B --> B2["Токени прилітають подіями в міру генерації"]
  B2 --> B3["Текст друкується на очах — кращий UX"]
  style B fill:#2A211C,stroke:#D97757,color:#F0EEE6

Під капотом — server-sent events; SDK ховає всю механіку

Python
with client.messages.stream(
    model="claude-sonnet-5",
    max_tokens=1024,
    messages=[{"role": "user",
               "content": "Розкажи коротку історію про каву в Чернівцях."}],
) as stream:
    for text in stream.text_stream:
        print(text, end="", flush=True)
TypeScript
const stream = client.messages.stream({
  model: "claude-sonnet-5",
  max_tokens: 1024,
  messages: [{ role: "user", content: "Розкажи коротку історію про каву." }],
});

stream.on("text", (text) => process.stdout.write(text));

const finalMessage = await stream.finalMessage(); // повна відповідь і usage

Коли streaming не потрібен: фонові пайплайни, де відповідь споживає код, а не людина, — класифікація, екстракція, batch-обробка. Там простіше дочекатися повного результату й розпарсити його одним шматком.

5.6Vision: робота із зображеннями

Claude бачить зображення: скріншоти інтерфейсів, фото документів, графіки, меню, схеми. Технічно це той самий Messages API — просто content повідомлення стає масивом блоків: спершу зображення, потім текстове питання.

Python · аналіз фото меню
import base64

with open("menu.jpg", "rb") as f:
    image_data = base64.standard_b64encode(f.read()).decode("utf-8")

message = client.messages.create(
    model="claude-sonnet-5",
    max_tokens=1024,
    messages=[{
        "role": "user",
        "content": [
            {
                "type": "image",
                "source": {
                    "type": "base64",
                    "media_type": "image/jpeg",
                    "data": image_data,
                },
            },
            {"type": "text",
             "text": "Перелічи всі позиції меню з цінами у валідному JSON: "
                     "масив об'єктів з полями name та price."},
        ],
    }],
)

print(message.content[0].text)
  • Формати: JPEG, PNG, GIF, WebP; в одному повідомленні може бути кілька зображень — зручно для порівнянь.
  • Джерело-URL: якщо файл уже в інтернеті, замість base64 можна передати блок source із type: "url" і посиланням.
  • Порядок: зображення перед питанням — модель спершу «дивиться», потім читає задачу.
  • Токени: зображення теж коштують токенів пропорційно розміру — не годуй API фотографіями на 12 мегапікселів, якщо досить 1024px.
Чесне застереження

Vision — не ідеальний OCR: дрібний текст, рукопис і щільні таблиці можуть розпізнаватися з помилками. Критичні цифри з фото документів перевіряй руками — розпізнавання з Модуля 2 працює і тут.

Підіб'ємо: твій код тепер розмовляє з Claude, тримає контекст, стрімить відповіді й бачить зображення. Наступний крок — найцікавіший у треку: дати моделі руки. У Модулі 6 Claude почне викликати твої функції — Tool Use.

Підсумок модуля
  • Ключ — секрет: змінні середовища і бекенд; ніколи у фронтенді чи репозиторії.
  • Messages API: model + max_tokens + messages; системний промпт — окреме поле system, а не роль.
  • temperature нижче для фактів і JSON, вище для ідей; stop_sequences ставлять жорстку крапку.
  • API stateless: історію надсилаєш сам — і платиш за неї вхідними токенами.
  • Префіл = останнє повідомлення assistant; не забудь приклеїти його до відповіді.
  • Streaming — для людей перед екраном; vision — блоки image + text, зображення перед питанням.
