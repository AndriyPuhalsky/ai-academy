Фаза C · Агенти й команди агентів

Будуємо агента крок за кроком

Агенти · 8 уроків · ≈ 100 хв

Теорію розібрали — тепер збудуємо справжнього агента, що сам виконує багатокрокову задачу. Зробимо корисну штуку: агент-аналітик, який отримує дані продажів, рахує підсумки, складає звіт і зберігає у файл. Ти отримаєш повний файл, який можна скопіювати й запустити, навчишся читати його роботу крок за кроком і виправляти типові помилки.

13.1Задача й план: думаємо інструментами

Наша мета: «Підготувати тижневий звіт про продажі — порахувати загальну суму й середній чек, скласти короткий текст і зберегти у файл». Це класична багатокрокова задача: треба дані, обчислення й збереження. Ідеально для агента.

Перший навик архітектора агентів — думати інструментами. Запитай себе: які «руки» потрібні моделі, щоб виконати задачу? Для нашої — три:

  • get_sales_data — дістати дані продажів (у реальності — з бази чи таблиці).
  • calculate — порахувати суму й середнє (модель не має рахувати велике сама).
  • save_report — зберегти готовий звіт у файл.

Агент сам пройде ці кроки — наша справа дати йому інструменти й мету

Важливо. Ми не програмуємо послідовність кроків жорстко. Ми лише даємо інструменти й мету — а порядок агент вирішує сам. У цьому й сила: зміниться задача — той самий набір інструментів спрацює інакше, без переписування логіки.

13.2Готуємо інструменти (функції)

Спершу — самі функції (це звичайний Python із Модуля 6):

def get_sales_data():
    # У реальному продукті — запит до бази/таблиці. Тут — приклад.
    return "Пн 1200, Вт 1500, Ср 900, Чт 2100, Пт 1800 (грн)"

def calculate(expression):
    # СПРОЩЕНО для навчання: дозволяємо лише числа й оператори.
    allowed = "0123456789+-*/(). "
    if not all(c in allowed for c in expression):
        return "помилка: дозволені лише числа й математичні оператори"
    return str(eval(expression))

def save_report(filename, content):
    with open(filename, "w", encoding="utf-8") as f:   # відкриваємо файл на запис
        f.write(content)
    return f"Звіт збережено у файл {filename}"

Розбір. with open(filename, "w", ...) as f: — відкриває файл на запис ("w" = write) і гарантовано закриє його після (той самий «менеджер контексту», що й у стрімінгу, Модуль 8). encoding="utf-8" — щоб українські літери збереглись правильно. А у calculate ми навмисно пропускаємо лише цифри й оператори: ніколи не виконуй eval на довільному введенні у проді — це вразливість; для серйозних задач беруть безпечні бібліотеки-калькулятори.

Чому calculate, а не «хай модель порахує сама». Моделі іноді помиляються в арифметиці, особливо з великими числами. Доручаючи підрахунок коду, ти отримуєш точний результат. Модель вирішує, що порахувати, а інструмент рахує надійно — це поділ праці.

13.3Описуємо інструменти для моделі

Тепер — анкети input_schema (Модуль 10), щоб модель знала, які інструменти є й що вони приймають:

tools = [
    {"name": "get_sales_data", "description": "Повертає дані продажів за тиждень",
     "input_schema": {"type": "object", "properties": {}}},

    {"name": "calculate", "description": "Обчислює математичний вираз, напр. '1200+1500'",
     "input_schema": {"type": "object",
                      "properties": {"expression": {"type": "string"}},
                      "required": ["expression"]}},

    {"name": "save_report", "description": "Зберігає текст звіту у файл",
     "input_schema": {"type": "object",
                      "properties": {"filename": {"type": "string"},
                                     "content": {"type": "string"}},
                      "required": ["filename", "content"]}},
]

Дрібниці, що мають значення. У get_sales_data поле properties порожнє {} — бо функція не приймає аргументів. У calculate опис містить приклад ('1200+1500') — це підказує моделі формат. Пиши description зрозуміло: саме за ним модель вирішує, коли який інструмент потрібен. Поганий опис → модель обере не той інструмент.

13.4Збираємо повний agent.py

А тепер — увесь файл цілком. Це не фрагмент: скопіюй у agent.py, запусти — і агент працюватиме. Він поєднує інструменти, їх описи, карту імен, системний промпт (мету) і цикл агента з Модуля 12 (тут із друком кроків і системним промптом): 

import os
from anthropic import Anthropic
from dotenv import load_dotenv

load_dotenv()
client = Anthropic(api_key=os.getenv("ANTHROPIC_API_KEY"))
MODEL = "claude-sonnet-5"   # приклад; актуальні моделі — docs.claude.com

# === 1) ІНСТРУМЕНТИ (функції) ===
def get_sales_data():
    return "Пн 1200, Вт 1500, Ср 900, Чт 2100, Пт 1800 (грн)"

def calculate(expression):
    allowed = "0123456789+-*/(). "
    if not all(c in allowed for c in expression):
        return "помилка: дозволені лише числа й оператори"
    return str(eval(expression))

def save_report(filename, content):
    with open(filename, "w", encoding="utf-8") as f:
        f.write(content)
    return f"Звіт збережено у файл {filename}"

# === 2) ОПИСИ ІНСТРУМЕНТІВ ===
tools = [
    {"name": "get_sales_data", "description": "Повертає дані продажів за тиждень",
     "input_schema": {"type": "object", "properties": {}}},
    {"name": "calculate", "description": "Обчислює математичний вираз, напр. '1200+1500'",
     "input_schema": {"type": "object",
                      "properties": {"expression": {"type": "string"}},
                      "required": ["expression"]}},
    {"name": "save_report", "description": "Зберігає текст звіту у файл",
     "input_schema": {"type": "object",
                      "properties": {"filename": {"type": "string"},
                                     "content": {"type": "string"}},
                      "required": ["filename", "content"]}},
]

# === 3) КАРТА: ім'я -> функція ===
tool_functions = {
    "get_sales_data": get_sales_data,
    "calculate": calculate,
    "save_report": save_report,
}

# === 4) СИСТЕМНИЙ ПРОМПТ (мета агента) ===
SYSTEM = (
    "Ти агент-аналітик продажів. Твоя мета: отримати дані продажів, "
    "порахувати загальну суму й середній чек, скласти короткий звіт "
    "і зберегти його у файл report.txt. Працюй крок за кроком."
)

# === 5) ЦИКЛ АГЕНТА ===
def run_agent(task, max_steps=10):
    messages = [{"role": "user", "content": task}]

    for step in range(max_steps):
        resp = client.messages.create(
            model=MODEL, max_tokens=1500,
            system=SYSTEM, tools=tools, messages=messages,
        )
        messages.append({"role": "assistant", "content": resp.content})

        if resp.stop_reason != "tool_use":     # модель завершила
            return resp.content[0].text

        results = []
        for block in resp.content:
            if block.type == "tool_use":
                print(f"[крок {step+1}] виклик: {block.name}({block.input})")
                func = tool_functions[block.name]
                try:
                    output = func(**block.input)
                except Exception as e:
                    output = f"помилка: {e}"
                results.append({"type": "tool_result",
                                "tool_use_id": block.id,
                                "content": str(output)})
        messages.append({"role": "user", "content": results})

    return "Досягнуто межі кроків"

# === 6) ЗАПУСК ===
print(run_agent("Підготуй тижневий звіт про продажі."))

Як читати цей файл. Блоки 1–3 — підготовка (функції, описи, карта). Блок 4 — мета агента в SYSTEM (Модуль 8). Блок 5 — той самий цикл, що в Модулі 12, лише з додаванням system=SYSTEM у виклик і друком кожного кроку. Блок 6 — запуск. Зверни увагу: послідовність дій (спершу дані, потім підрахунок, потім збереження) ми не прописували — її обере сам агент, керуючись метою.

13.5Запускаємо й спостерігаємо

Запусти у терміналі:

python agent.py        # або python3 agent.py на macOS / Linux

Що ти маєш побачити (приблизно — деталі залежать від моделі):

[крок 1] виклик: get_sales_data({})
[крок 2] виклик: calculate({'expression': '1200+1500+900+2100+1800'})
[крок 3] виклик: calculate({'expression': '7500/5'})
[крок 4] виклик: save_report({'filename': 'report.txt', 'content': '...'})
Звіт готовий: загальна сума 7500 грн, середній чек 1500 грн. Збережено у report.txt.

А ще — у твоїй папці з'явиться файл report.txt із текстом звіту. Відкрий його й переконайся.

Зупинись і осягни, що сталося: ти дав агенту мету й три інструменти — і він сам вирішив узяти дані, двічі звернутись до калькулятора (для суми й середнього), скласти текст і зберегти його. Ти не писав «спочатку це, потім те» — порядок агент склав сам. Це і є автономність.

Якщо нічого не друкується / помилка одразу. Найчастіше — не підвантажився ключ. Перевір, що .env у тій самій папці й містить ANTHROPIC_API_KEY (Модуль 7), і що встановлені бібліотеки (pip install anthropic python-dotenv).

13.6Типові помилки й налагодження

Агенти рідко працюють ідеально з першого разу — і це нормально навіть для досвідчених. Друк кроків ([крок N] виклик: ...) — твій головний діагностичний інструмент. Ось найчастіші проблеми, як їх розпізнати за друком і як виправити:

  • Агент не той інструмент обрав. У друку видно виклик не тієї функції. Причина — нечіткий description. Лік: зроби опис конкретнішим (що робить, коли застосовувати).
  • «Досягнуто межі кроків». Агент крутиться й не завершує. Дивись друк — часто він повторює один виклик. Лік: чіткіший системний промпт («коли звіт збережено — заверши») або підняти max_steps, якщо задача справді довга.
  • Неправильні обчислення. У друку calculate отримав кривий вираз. Лік: уточни в описі формат, або попроси агента спершу пояснити, що рахує («дозволь подумати», Модуль 9).
  • Помилка інструмента. У результаті бачиш помилка: ... — це спрацював наш try/except. Добре: агент не впав, отримав текст помилки й може перепробувати. Прочитай, що саме за помилка, і виправ функцію.
  • KeyError у tool_functions. Модель попросила інструмент, якого немає в карті. Лік: переконайся, що ім'я в tools точно збігається з ключем у tool_functions і з назвою функції.

Золоте правило налагодження агента. Спершу подивись на друк кроків — він майже завжди показує, де саме все пішло не так. А якщо незрозуміло — скопіюй друк і код у Claude Code й попроси: «агент поводиться ось так, ось кроки й код — що не так і як виправити?».

13.7Покращуємо агента через системний промпт

Перша версія працює — тепер зробімо її надійнішою. Якість агента на 80% залежить від системного промпта: чим чіткіша мета, формат і межі, тим стабільніша поведінка. Порівняй слабкий і сильний варіанти: 

# Слабкий (розпливчастий):
SYSTEM = "Ти аналітик. Зроби звіт про продажі."

# Сильний (чітка мета + формат + межі):
SYSTEM = (
    "Ти агент-аналітик продажів. Виконай задачу крок за кроком:\n"
    "1) візьми дані через get_sales_data;\n"
    "2) порахуй загальну суму й середній чек через calculate;\n"
    "3) склади короткий звіт українською: сума, середній чек, один висновок;\n"
    "4) збережи у файл report.txt через save_report і заверши.\n"
    "Не вигадуй дані — бери лише з get_sales_data."
)

Що дає сильний промпт. Чіткі кроки зменшують блукання (менше зайвих викликів = дешевше й швидше). Заданий формат звіту робить результат передбачуваним. Правило «не вигадуй дані» захищає від галюцинацій. Межа «коли збережено — заверши» прибирає ризик зациклення. Це той самий контракт, що й у Модулі 9, лише для агента.

Запобіжники з Модуля 12 у нас уже стоять: межа кроків (max_steps) і обробка збоїв (try/except). Разом із чітким промптом це робить агента справді надійним.

13.8Варіації: гнучкість агентного підходу

Найкраще відчути силу агента — змінити задачу без зміни коду. Той самий agent.py, ті самі інструменти — лише інший запит: 

print(run_agent("Який день був найкращим за продажами і на скільки він кращий за середній?"))
# Агент сам: візьме дані -> порахує середнє -> порівняє -> відповість.

print(run_agent("Підрахуй лише суму продажів за перші три дні тижня."))
# Агент сам: візьме дані -> calculate('1200+1500+900') -> відповість.

Жодного рядка логіки ми не переписали — агент щоразу складає новий план під нову мету. Це і є ключова перевага: ти описуєш можливості (інструменти) і мету, а не жорсткий сценарій.

А щоб розширити можливості — додай інструмент за патерном із Модуля 12 (функція + опис + запис у карту). Наприклад, send_email, щоб агент ще й надсилав звіт:

def send_email(to, subject, body):
    # реально — виклик API пошти; обережно: це ДІЯ назовні (Модуль 15)
    return f"Лист до {to} підготовлено"
# + опис у tools, + запис у tool_functions — і агент зможе ним користуватись.

Обережно з діями назовні. Інструменти, що надсилають чи змінюють щось (пошта, оплата, видалення), потребують підтвердження людини (Модуль 12, і докладніше — Модуль 15). Читати дані — безпечно; діяти назовні — лише свідомо.

Підсумок модуля. Ти збудував повного робочого агента від плану до запуску: визначив задачу, написав інструменти та їх описи, зібрав цілісний agent.py, простежив його роботу, навчився діагностувати типові помилки за друком кроків, посилив системний промпт і побачив гнучкість підходу на варіаціях. Це сильний експонат портфоліо. Наступний крок — Модуль 14: коли одного агента замало, збираємо команду агентів.
