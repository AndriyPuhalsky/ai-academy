Ключі, .env і безпека

Основи · 4 уроки · ≈ 40 хв

Останній крок перед тим, як почати будувати з моделлю. Щоб твоя програма зверталася до Claude, їй потрібен ключ доступу — і поводитися з ним треба обережно, бо це по суті ключ від твого гаманця. Цей короткий модуль навчить зберігати ключ правильно й безпечно. Звичка, яку ти закладеш тут, рятуватиме тебе всю кар'єру.

7.1Що таке ключ доступу й чому він секретний

Ключ доступу (API key) — це секретний рядок, що підтверджує: запит до моделі робиш саме ти, і за нього рахується твоя оплата.

Аналогія. Уяви, що ключ — це твоя банківська картка разом із пін-кодом. Хто її має — той витрачає твої гроші. Тому ключ ніколи нікому не показують, не викладають у публічний доступ і не вставляють у випадкові сайти.

Де взяти ключ:

  1. Зайди в console.anthropic.com (акаунт уже створив у Модулі 2).
  2. Знайди розділ «API Keys» і натисни «Create Key».
  3. Скопіюй ключ одразу — повністю він показується лише раз. Виглядає приблизно як sk-ant-....

Найважливіше правило безпеки. Ніколи не вставляй справжній ключ у код, який потрапить у GitHub, у скриншоти, у чати чи у сторонні онлайн-сервіси. Якщо ключ десь «засвітився» — негайно видали його в консолі й створи новий (це називається «відкликати ключ»).

7.2Файл .env — домівка для секретів

Куди ж тоді покласти ключ? У спеціальний файл .env (від «environment» — оточення), який лежить у папці проєкту й містить секрети у форматі ІМ'Я=значення: 

# файл .env у папці проєкту
ANTHROPIC_API_KEY=sk-ant-твій-справжній-ключ

Зверни увагу: ім'я файлу починається з крапки — просто .env, без назви перед крапкою. На багатьох системах такі файли «приховані», і це нормально.

Найпростіший спосіб створити. Запусти claude у папці проєкту й попроси: «створи файл .env і додай у нього змінну ANTHROPIC_API_KEY» — далі встав туди свій ключ сам (ключ Claude Code давати не треба — просто скажи створити файл, а значення впишеш власноруч).

Чому окремий файл, а не прямо в коді. Так секрет відділено від коду: код можна спокійно показувати й публікувати, а .env залишається лише в тебе на комп'ютері. Як саме не дати йому втекти в GitHub — наступний урок.

7.3.gitignore: не пускаємо секрети в хмару

Пам'ятаєш git push із Модуля 5? Він відправляє файли проєкту на GitHub, де їх може побачити будь-хто. Якщо разом із кодом туди потрапить .env — твій ключ опиниться у відкритому доступі, і його миттєво використають за твій рахунок. Це найпоширеніша й найдорожча помилка новачків.

Рятує файл .gitignore — це список того, що Git має ігнорувати (ніколи не зберігати й не відправляти). Додаємо туди .env: 

# файл .gitignore у папці проєкту
.env

  subgraph PROJ["Папка проєкту"]
    CODE["index.html, код"]
    ENV[".env (ключ)"]
  end
  CODE -->|"потрапляє в git"| GH[("GitHub
(публічно)")]
  ENV -.->|".gitignore блокує"| X["Залишається
лише в тебе"]
  style GH fill:#2A211C,stroke:#D97757,color:#F0EEE6

Код їде на GitHub, а .env завдяки .gitignore нікуди не виходить

Перевір себе. Після додавання .env у .gitignore виконай git status — файл .env не повинен з'являтися у списку до відправлення. Якщо він там є — значить, .gitignore не на місці або названий неправильно. Claude Code теж допоможе налаштувати це коректно, якщо попросиш.

7.4Як код безпечно читає ключ

Залишилось показати, як програма дістає ключ із .env, не вписуючи його в код. Для цього є маленька бібліотека python-dotenv. Ось як це виглядатиме (запустимо вже у наступній фазі): 

import os
from dotenv import load_dotenv     # бібліотека: pip install python-dotenv

load_dotenv()                       # читає файл .env у пам'ять програми
api_key = os.getenv("ANTHROPIC_API_KEY")   # дістаємо ключ за його іменем

print("Ключ завантажено:", api_key is not None)   # НЕ друкуємо сам ключ!

Розбір. load_dotenv() підвантажує все з .env у «оточення» програми. os.getenv("ANTHROPIC_API_KEY") дістає значення за іменем — так само, як зі словника (Модуль 6). Зверни увагу на останній рядок: ми перевіряємо лише, що ключ є (is not None = «не порожній»), але не друкуємо його — виводити секрет на екран чи в логи теж небезпечно.

Підсумок і чек-лист безпеки. Ти отримав ключ, поклав його у .env, захистив .gitignore і знаєш, як код його читає. Запам'ятай три «ніколи»: ніколи не пиши ключ прямо в коді, ніколи не коміт .env, ніколи не друкуй ключ. Це й закриває Фазу A — фундамент готовий. Далі починається найсмачніше: у Фазі B твоя програма вперше по-справжньому заговорить з моделлю Claude.
