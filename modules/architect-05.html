Git і GitHub за руку

Основи · 4 уроки · ≈ 45 хв

Перш ніж будувати складніше, навчимося зберігати роботу так, щоб її не втратити й показати світу. Це Git і GitHub — щоденний інструмент кожного інженера і, що важливо для тебе, основа портфоліо, на яке дивляться роботодавці й клієнти. Зробимо все на твоєму проєкті ai-start, крок за кроком.

5.1Навіщо потрібен Git

Git — це система контролю версій: вона запам'ятовує історію змін твого проєкту.

Аналогія. Це як «збереження» у відеогрі. Зробив крок — зберігся. Щось пішло не так — повернувся до останнього вдалого збереження. Git дозволяє в будь-який момент побачити, що і коли ти змінював, і відкотитися назад, нічого не втративши.

А GitHub — це сайт, де твої проєкти зберігаються в хмарі та стають видимими іншим. Для тебе це важливо одразу з трьох причин:

  • Бекап: навіть якщо з комп'ютером щось станеться, проєкт у безпеці в хмарі.
  • Портфоліо: роботодавець чи клієнт майже завжди дивиться твій GitHub — що ти будував і як часто працюєш.
  • Співпраця й деплой: згодом саме з GitHub ми викладатимемо проєкти в інтернет.

Запам'ятай різницю. Git — це інструмент на твоєму комп'ютері (веде історію локально). GitHub — це онлайн-сервіс, куди ти цю історію «відправляєш». Git може жити й без GitHub, але разом вони — стандарт індустрії.

5.2Встановлюємо й налаштовуємо Git

Спершу перевір, чи Git уже встановлений (часто він є). У терміналі:

git --version

Якщо побачив номер версії — Git уже є, переходь до налаштування нижче. Якщо «не знайдено» — встанови:

Windows: завантаж інсталятор із git-scm.com і пройди «Далі» до кінця (стандартні налаштування підходять).

macOS: у терміналі впиши xcode-select --install і підтвердь (або встанови з git-scm.com).

Linux (Debian/Ubuntu):

sudo apt update
sudo apt install -y git

Одноразове налаштування. Git хоче знати, хто робить зміни (це підписує твою історію). Впиши свої ім'я та пошту (ту саму, якою реєструватимешся на GitHub): 

git config --global user.name "Твоє Імʼя"
git config --global user.email "твоя@пошта.com"

Що ти маєш побачити. Команди config нічого не виводять — це нормально, вони просто тихо зберігають налаштування. Перевірити можна так: git config --global user.name — у відповідь з'явиться введене ім'я.

5.3Перший репозиторій локально

Репозиторій (скорочено «репо») — це папка проєкту, за якою Git стежить. Перетворимо нашу ai-start на репозиторій. Зайди в папку й виконай три команди: 

cd Desktop/ai-start

git init                       # почати стежити за проєктом
git add .                      # підготувати ВСІ файли до збереження (крапка = всі)
git commit -m "Перша сторінка" # зберегти «знімок» проєкту з підписом

Що відбувається — три прості кроки, які стануть звичкою:

Шлях зміни: файли → підготувати (add) → зберегти (commit) → відправити в хмару (push)

Розбір команд. git init створює приховану службову папку, де Git зберігатиме історію (робиться раз на проєкт). git add . — позначає, які зміни ввійдуть у наступний знімок (крапка означає «усі файли»). git commit -m "..." — робить сам знімок із коротким описом, що змінилося. Кожен commit — це точка в історії, до якої можна повернутися.

Що ти маєш побачити. Після commit Git напише щось на кшталт «1 file changed» і покаже короткий код знімка. Якщо попросить спершу налаштувати ім'я/пошту — повернись до уроку 5.2 і зроби git config.

5.4GitHub і перший push

Тепер відправимо проєкт у хмару, щоб він став частиною портфоліо.

  1. Зареєструйся на github.com (пошту бери ту саму, що в git config).
  2. Натисни «New» (новий репозиторій), дай назву (наприклад, ai-start), не додавай жодних файлів-галочок (README тощо) — лиши порожнім, щоб не було конфлікту. Натисни «Create repository».
  3. GitHub покаже адресу репозиторію виду https://github.com/твій-нік/ai-start.git. Скопіюй її.

Повертаємось у термінал (у папці ai-start) і під'єднуємо хмару:

git remote add origin https://github.com/твій-нік/ai-start.git
git branch -M main
git push -u origin main

Розбір команд. git remote add origin ... — каже Git, куди в хмарі відправляти (даємо цьому «пункту призначення» звичне ім'я origin). git branch -M main — називає основну гілку main (стандарт). git push -u origin main — відправляє твої збережені знімки на GitHub. Прапорець -u запам'ятовує зв'язок, щоб надалі вистачало просто git push.

Про вхід під час push. GitHub попросить підтвердити, що це ти. Сучасний GitHub не приймає звичайний пароль — він запропонує увійти через браузер або через спеціальний токен. Просто йди за підказками, які він покаже; якщо щось незрозуміло — відкрий інструкцію з автентифікації в довідці GitHub, вона веде за руку.

Лайфхак у дусі курсу. Усі ці git-команди можна доручити Claude Code: запусти claude в папці й попроси «ініціалізуй git-репозиторій і допоможи запушити цей проєкт на GitHub, пояснюючи кожен крок». Він проведе тебе процесом. Але корисно хоч раз зробити вручну — щоб розуміти, що відбувається.

Що ти маєш побачити. Онови сторінку свого репозиторію на github.com — там з'явиться файл index.html. Вітаю: твій перший проєкт у хмарі й у портфоліо. Підсумок: ти вмієш зберігати історію (commit) і публікувати її (push). Далі — Модуль 6: трохи Python, щоб упевнено читати й правити те, що пише Claude Code.
