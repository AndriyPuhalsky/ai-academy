У минулому модулі модель відповідала вільним текстом — добре для читання очима. Але щоб програма могла надійно обробити відповідь, потрібен передбачуваний, машиночитаний результат. Цей модуль навчить отримувати від моделі стабільний JSON і застосувати це на ділі: ми разом збудуємо реальний видобувач даних — інструмент, що перетворює хаотичні звернення клієнтів на акуратні структуровані записи.

9.1Від «гарної відповіді» до передбачуваної

У чаті ти читаєш відповідь сам — і вільний текст це окей. У коді вільний текст — проблема. Уяви: програма хоче дістати з відповіді ціну. Сьогодні модель пише «Ціна: 200 грн», завтра — «Це коштуватиме близько двохсот гривень». Код, що шукав число, ламається на другому варіанті.

Аналогія. Жива розмова — як базар: щоразу трохи інакше. А програмі потрібен торговий автомат: натиснув «А3» — завжди та сама вода в тому самому місці. Промисловий промптинг — це проєктування запиту так, щоб відповідь була стабільною й машиночитаною.

Три принципи, на яких усе тримається:

  • Будь явним: чітко скажи формат, поля, мову, обмеження. Модель не вгадує — виконує.
  • Дай структуру: проси конкретний формат (JSON із полями), а не «опиши».
  • Перевіряй: код має валідувати відповідь і гідно реагувати, якщо вона не така.

Зміна мислення. Ти більше не «спілкуєшся» з моделлю — ти проєктуєш контракт: «на такий вхід дай рівно такий вихід». Решта модуля — як цей контракт закріпити технічно.

9.2Структурований вивід: надійний JSON

Рішення — попросити відповідь у форматі JSON (Модуль 4) із чітко заданими полями. Аналогія: це різниця між «напиши есе» і «заповни анкету: настрій, тема, чи терміново». Анкету з полями легко прочитати автоматично; есе — ні. 

system = (
    "Ти аналізуєш відгук клієнта. Поверни ЛИШЕ JSON без пояснень, "
    "за схемою: {\"sentiment\": \"позитивний|нейтральний|негативний\", "
    "\"theme\": str, \"urgent\": bool}."
)

response = client.messages.create(
    model=MODEL, max_tokens=300, system=system,
    messages=[{"role": "user", "content": "Замовлення йшло два тижні, жах!"}],
)

import json
data = json.loads(response.content[0].text)   # текст JSON -> словник Python
print(data["sentiment"], data["urgent"])        # негативний True

Розбір. json.loads() перетворює рядок із JSON на словник Python — і далі дістаєш поля як зі звичайного словника (Модуль 6): data["sentiment"]. Назва loads = «load string». Зворотна дія — json.dumps() (словник → рядок). Лапки всередині схеми ми екранували через \" — щоб вони не закрили рядок передчасно.

Іноді модель додає «ввічливий» текст перед JSON («Ось результат: {...}»), і json.loads на цьому спіткнеться. Надійний трюк — префіл: останнім ходом ставиш початок відповіді асистента з {, і модель продовжує одразу з JSON: 

messages = [
    {"role": "user", "content": "Замовлення йшло два тижні, жах!"},
    {"role": "assistant", "content": "{"},      # префіл: змушуємо почати з JSON
]

Чому це працює. Модель завжди продовжує вже написане (Модуль 8: вона передбачає наступний токен). Поставивши за неї {, ти ніби почав речення замість співрозмовника — і їй лишається продовжити саме JSON. Маленька деталь: оскільки { уже «сказав» ти, у відповіді його не буде — тож у коді його треба додати назад (побачиш це в нашому проєкті нижче).

9.3Техніки, що різко підвищують якість

Кілька прийомів, які перетворюють «так собі» на «точно те, що треба»:

  • Дай приклади (few-shot). Покажи 1–3 приклади «вхід → бажаний вихід». Модель чудово наслідує показаний зразок — це найсильніший важіль для формату. Аналогія: краще раз показати заповнену анкету, ніж довго описувати правила.
  • Дозволь подумати. Для складних задач попроси спершу міркування, потім відповідь: «спочатку обґрунтуй, потім дай фінальний JSON». Як людині — подумати вголос перед відповіддю; точність зростає.
  • Низька temperature (Модуль 8) для задач із «правильною» відповіддю.
  • Будь конкретним щодо мови, формату й крайніх випадків.
# Приклад few-shot прямо в системному промпті:
system = (
    "Класифікуй звернення. Поверни лише JSON {\"category\": ..., \"urgent\": ...}.\n"
    "Приклад:\n"
    "Вхід: 'Дякую, кур'єр приїхав вчасно!'\n"
    "Вихід: {\"category\": \"доставка\", \"urgent\": false}"
)

Чому приклад такий сильний. Один зразок бажаного виводу пояснює формат краще за абзац інструкцій. Модель «бачить» точну форму — і повторює її. Це перше, що варто спробувати, коли відповіді «майже, але не зовсім» правильні.

9.4Проєкт: видобувач даних зі звернень

З'єднаємо все в реальний інструмент. Уяви бізнес, що отримує сотні звернень клієнтів вільним текстом. Наш видобувач читатиме кожне й повертатиме акуратний структурований запис, який можна скласти в таблицю чи базу. Ось логіка:

Видобувач: хаотичний текст → модель за схемою → JSON → готові структуровані дані

Попроси Claude Code: «створи файл extractor.py, що класифікує звернення клієнта в JSON за схемою category/sentiment/urgent/summary, з префілом і температурою 0». Вийде приблизно так: 

import os, json
from anthropic import Anthropic
from dotenv import load_dotenv

load_dotenv()
client = Anthropic(api_key=os.getenv("ANTHROPIC_API_KEY"))

SYSTEM = (
    "Ти класифікуєш звернення клієнтів служби підтримки. "
    "Поверни ЛИШЕ JSON без пояснень, за схемою: "
    "{\"category\": \"оплата|доставка|товар|інше\", "
    "\"sentiment\": \"позитивний|нейтральний|негативний\", "
    "\"urgent\": true або false, \"summary\": \"короткий підсумок\"}."
)

def extract(text):
    resp = client.messages.create(
        model="claude-sonnet-5",
        max_tokens=300,
        temperature=0,                      # потрібна стабільність, не творчість
        system=SYSTEM,
        messages=[
            {"role": "user", "content": text},
            {"role": "assistant", "content": "{"},   # префіл: почати з JSON
        ],
    )
    raw = "{" + resp.content[0].text        # додаємо { назад, бо ним почали ми
    return json.loads(raw)                   # рядок JSON -> словник

ticket = "Замовлення йшло два тижні і досі не прийшло, поверніть гроші!"
print(extract(ticket))
# {'category': 'доставка', 'sentiment': 'негативний', 'urgent': True,
#  'summary': 'Затримка доставки, вимога повернення коштів'}

Розбір ключових місць. temperature=0 — бо нам потрібна однаковість, а не фантазія. Префіл {"role": "assistant", "content": "{"} змушує модель почати з JSON. Рядок raw = "{" + resp.content[0].text повертає на місце ту фігурну дужку, яку «сказали» ми (тому її немає у відповіді). json.loads(raw) перетворює текст на словник — і ти вже працюєш зі звичайними полями Python.

Запусти python extractor.py — і побачиш акуратний словник. Підстав свої тексти, спробуй різні звернення. Це вже не іграшка: такий інструмент реально економить години ручного сортування заявок.

9.5Надійність: не довіряй — перевіряй

Модель надійна, але не ідеальна: колись може повернути криве або неповне. Продакшн-код це передбачає й не падає. Додамо «запобіжник» навколо нашого видобувача: 

def safe_extract(text):
    try:
        data = extract(text)                 # пробуємо дістати й розпарсити
        for field in ["category", "sentiment", "urgent", "summary"]:
            if field not in data:            # перевіряємо, що всі поля контракту на місці
                raise ValueError(f"немає поля {field}")
        return data
    except (json.JSONDecodeError, ValueError) as e:
        print("Некоректна відповідь, варто повторити:", e)
        return None                          # тут можна повторити запит

Розбір. try: — пробуємо ризиковану дію; якщо всередині станеться помилка, керування «впаде» в except замість краху (Модуль 6). Цикл перевіряє, що кожне очікуване поле є у відповіді; якщо ні — ми самі кидаємо помилку через raise ValueError(...). except (A, B) ловить обидва типи: і коли JSON не розпарсився, і нашу власну. Повертаючи None, ми сигналізуємо «відповідь непридатна» — і вище можемо повторити запит.

Підсумок модуля. Ти вмієш діставати від моделі надійний JSON (з префілом), підсилювати якість прикладами й «обдумуванням», і валідувати результат — тобто перетворювати модель на передбачуваний компонент продукту. Ти збудував робочий видобувач даних — повноцінний інструмент. Наступний модуль робить крок далі: даємо моделі «руки», щоб вона не лише відповідала, а й діяла — це tool use.
