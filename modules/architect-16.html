Бекенд для AI-продукту

Продакшн · 7 уроків · ≈ 90 хв

Досі весь наш код працював лише в твоєму терміналі — ним не міг скористатися ніхто інший. У цій фазі ми перетворимо код на справжній продукт. Перший крок — бекенд: сервіс, що приймає запити й повертає відповіді, плюс простий вебінтерфейс. Зберемо повний робочий приклад, який запрацює в браузері.

16.1Навіщо потрібен бекенд

Твій скрипт із Модуля 8 чудово працює — але тільки коли ти запускаєш його в терміналі. Щоб ним користувався клієнт чи колега через браузер, код має «жити» на сервері й відповідати на запити. Це і є бекенд.

Аналогія. Уяви, що твій код — кухар, який чудово готує. Але поки він на твоїй домашній кухні, поїсти може лише ти. Бекенд — це ресторан: є зал, офіціант приймає замовлення, кухар готує, страву виносять гостю. Тепер скористатися можуть усі.

І ще одна, критично важлива причина (про неї часто забувають):

Бекенд ховає твій ключ. Пам'ятаєш із Модуля 7 — ключ не можна показувати? Якби браузер звертався до Claude напряму, ключ був би видний кожному відвідувачу (а отже, вкрадений). Бекенд тримає ключ у себе на сервері: браузер говорить лише з твоїм бекендом, а вже бекенд — із Claude. Це головна технічна причина, чому бекенд обов'язковий.

16.2Веб-бекенд, ендпоінти та FastAPI

Бекенд — це програма, що постійно «слухає» запити. Точка, куди надсилають запит, зветься ендпоінт (endpoint) — по суті, адреса-URL із певною функцією. Наприклад, ендпоінт /ask прийматиме питання й повертатиме відповідь моделі.

Згадай клієнт-сервер із Модуля 4: браузер (клієнт) робить запит на ендпоінт, бекенд (сервер) обробляє й повертає відповідь — зазвичай у JSON. Щоб не писати весь сервер з нуля, беремо FastAPI — популярну Python-бібліотеку, що робить створення бекенду простим і швидким.

Що знадобиться. Дві бібліотеки: fastapi (сам бекенд) і uvicorn (сервер, що його запускає). Постав їх або попроси Claude Code: pip install fastapi uvicorn (на macOS/Linux інколи pip3). Ключ читаємо з .env, як завжди (Модуль 7).

16.3Перший бекенд на FastAPI (повний код)

Ось увесь файл main.py — бекенд з одним ендпоінтом /ask, що звертається до Claude. Попроси Claude Code створити його або скопіюй: 

import os
from fastapi import FastAPI
from fastapi.middleware.cors import CORSMiddleware
from pydantic import BaseModel
from anthropic import Anthropic
from dotenv import load_dotenv

load_dotenv()
client = Anthropic(api_key=os.getenv("ANTHROPIC_API_KEY"))
MODEL = "claude-sonnet-5"   # приклад; актуальні моделі — docs.claude.com

app = FastAPI()   # створюємо застосунок-бекенд

# Дозволяємо браузеру звертатися до бекенду (CORS).
# Для навчання дозволяємо всім; у проді — лише свій сайт.
app.add_middleware(
    CORSMiddleware,
    allow_origins=["*"], allow_methods=["*"], allow_headers=["*"],
)

# Опис того, що приймає ендпоінт: об'єкт із полем text (рядок)
class Question(BaseModel):
    text: str

# Сам ендпоінт: приймає POST-запит на /ask
@app.post("/ask")
def ask(q: Question):
    resp = client.messages.create(
        model=MODEL, max_tokens=500,
        messages=[{"role": "user", "content": q.text}],
    )
    return {"answer": resp.content[0].text}   # повертаємо відповідь у JSON

Розбір. app = FastAPI() — створює бекенд. class Question(BaseModel) — описує очікуваний вхід (поле text типу рядок); FastAPI сам перевірить, що запит правильний. @app.post("/ask") — це «декоратор»: він каже «функція нижче обробляє POST-запити на адресу /ask». Усередині — знайомий виклик Claude (Модуль 8), а return {"answer": ...} віддає відповідь у форматі JSON (Модуль 4). Зверни увагу: ключ лишається тут, на бекенді — браузер його не побачить.

16.4Запускаємо й тестуємо бекенд

Бекенд запускає сервер uvicorn. У терміналі, в папці з main.py:

uvicorn main:app --reload

Тут main — ім'я файлу (main.py), app — наш застосунок усередині, а --reload автоматично перезапускає сервер, коли ти змінюєш код (зручно під час розробки).

Що ти маєш побачити у терміналі:

INFO: Uvicorn running on http://127.0.0.1:8000 (Press CTRL+C to quit)
INFO: Application startup complete.

Це означає, що бекенд працює за адресою 127.0.0.1:8000 (це твій власний комп'ютер, «localhost»).

Найзручніший спосіб одразу перевірити ендпоінт — вбудована сторінка документації FastAPI. Відкрий у браузері: 

http://127.0.0.1:8000/docs

Що ти маєш побачити. Сторінку з твоїм ендпоінтом /ask. Натисни на нього → «Try it out» → впиши у поле text якесь питання → «Execute». Нижче з'явиться відповідь моделі у JSON: {"answer": "..."}. Вітаю — твій AI працює як вебсервіс! FastAPI автоматично згенерував цю сторінку для тебе.

Якщо помилка. «Address already in use» — порт зайнятий, додай інший: uvicorn main:app --reload --port 8001. Помилка про ключ — перевір .env (Модуль 7). «command not found: uvicorn» — встанови pip install uvicorn.

16.5Додаємо простий вебінтерфейс

Сторінка /docs — для розробників. Зробимо людський інтерфейс: проста HTML-сторінка з полем і кнопкою, що звертається до нашого бекенду. Створи файл index.html: 

<!DOCTYPE html>
<html lang="uk">
<head><meta charset="UTF-8"><title>AI помічник</title></head>
<body>
  <h1>Запитай AI</h1>
  <input id="q" placeholder="Твоє питання" />
  <button onclick="ask()">Запитати</button>
  <p id="answer"></p>

  <script>
    async function ask() {
      const text = document.getElementById("q").value;
      document.getElementById("answer").textContent = "Думаю...";

      const res = await fetch("http://127.0.0.1:8000/ask", {
        method: "POST",
        headers: { "Content-Type": "application/json" },
        body: JSON.stringify({ text: text }),   // надсилаємо питання у JSON
      });

      const data = await res.json();             // отримуємо {answer: ...}
      document.getElementById("answer").textContent = data.answer;
    }
  </script>
</body>
</html>

Це JavaScript — і це нормально. Інтерфейс у браузері пишуть мовою JavaScript (не Python). Не лякайся: тобі не треба її опановувати — Claude Code напише фронтенд за тебе. Важливо розуміти потік: fetch("...","POST", body) надсилає питання на наш бекенд (Модуль 4), await res.json() отримує відповідь, і ми показуємо її на сторінці. async/await просто означає «зачекай на відповідь, перш ніж показувати».

Навіщо CORS у бекенді. Браузер із міркувань безпеки за замовчуванням блокує запити з однієї адреси на іншу. Рядок із CORSMiddleware у main.py якраз дозволяє нашій сторінці звертатися до бекенду. Без нього браузер показав би помилку CORS — тепер ти знатимеш, що це й де лагодити.

16.6З'єднуємо все докупи

Тепер маємо дві частини. Запусти бекенд (якщо ще не запущений) і відкрий сторінку:

uvicorn main:app --reload          # 1) бекенд працює на :8000
# 2) відкрий index.html у браузері (подвійним кліком або через localhost)

Впиши питання, натисни «Запитати» — і за мить побачиш відповідь. Ось що сталося «під капотом»:

flowchart LR
  U["Браузер
(index.html)"] -->|"POST /ask + питання"| B["Бекенд
(FastAPI, main.py)"]
  B -->|"запит з ключем"| M["Claude API"]
  M -->|"відповідь"| B
  B -->|"JSON {answer}"| U
  class B hl

Повний потік: браузер → твій бекенд → Claude → назад. Ключ живе лише на бекенді

Що ти маєш побачити. На сторінці з'являється «Думаю...», а за секунду — відповідь моделі. У терміналі, де працює uvicorn, з'явиться рядок про отриманий запит (наприклад, POST /ask 200 OK). Це твій перший повноцінний AI-застосунок: інтерфейс + бекенд + модель.

Осягни масштаб: ти пройшов шлях від «скрипт у терміналі» до «продукт, яким можна користуватись у браузері». Будь-який AI-агент із попередніх модулів можна так само загорнути в ендпоінт — і він стане доступним сервісом.

16.7Обробка помилок, структура й безпека

Перш ніж публікувати продукт (наступний модуль), зробімо його охайнішим і безпечнішим.

  • Обробка помилок. Виклик моделі може впасти (збій, ліміт). Обгорни його в try/except (Модуль 6) і повертай зрозумілу помилку, а не «поклади» весь бекенд:
from fastapi import HTTPException

@app.post("/ask")
def ask(q: Question):
    try:
        resp = client.messages.create(
            model=MODEL, max_tokens=500,
            messages=[{"role": "user", "content": q.text}],
        )
        return {"answer": resp.content[0].text}
    except Exception as e:
        raise HTTPException(status_code=500, detail="Не вдалося отримати відповідь")
  • Структура проєкту. Тримай файли охайно: main.py (бекенд), index.html (інтерфейс), .env (ключ, у .gitignore!), requirements.txt (список бібліотек — знадобиться для деплою).
  • Безпека ключа. Повторимо головне: ключ лише на бекенді, у .env, ніколи не у фронтенді й не в Git. Браузер спілкується тільки з твоїм бекендом.
  • Перевірка вводу. FastAPI з BaseModel уже відсіює запити без поля text — це безкоштовний захист від кривих запитів.

Підказка про requirements.txt. Це простий файл зі списком потрібних бібліотек (по одній на рядок: fastapi, uvicorn, anthropic, python-dotenv). Він потрібен, щоб сервер під час деплою знав, що встановити. Claude Code може згенерувати його командою чи на прохання.

Підсумок модуля. Ти зрозумів, навіщо бекенд (доступ для інших + захист ключа), зібрав повний бекенд на FastAPI з ендпоінтом /ask, запустив його через uvicorn, додав простий вебінтерфейс, з'єднав усе докупи й подбав про помилки та безпеку. Твій AI вже працює як застосунок — але поки лише на твоєму комп'ютері. Наступний модуль — деплой: зробимо його доступним в інтернеті 24/7.
