Ти вже збудував вебсторінку, керуючи AI. Тепер коротко зазирнемо «під капот» того, що сталося: що це за файл, що означає «запустити», звідки програми беруть дані. Жодного нового коду — лише ясна картина на прикладі того, що ти щойно зробив. Це фундамент, на який ляже все далі.

4.1Файли й папки — з чого складається проєкт

Пам'ятаєш, Claude Code створив файл index.html у папці ai-start? Розберемо ці два поняття.

  • Файл — це названий «контейнер» із вмістом на диску. У index.html лежить текст твоєї сторінки. Частина після крапки (.html) — це розширення, воно каже, що це за файл: .html — вебсторінка, .py — програма на Python, .txt — простий текст.
  • Папка (директорія) групує файли. ai-start — це папка твого проєкту, де живуть усі його файли.

Подивитися на вміст папки можна двома способами — обидва корисні:

cd Desktop/ai-start    # зайти в папку проєкту
ls                     # показати її файли (побачиш index.html)

Або просто відкрий папку ai-start у провіднику (Windows) чи Finder (macOS) — побачиш той самий файл очима.

Спробуй прямо зараз. Запусти claude у папці й попроси: «покажи вміст файлу index.html і поясни простими словами, що означає кожна частина». Так ти на власні очі побачиш, що код — це просто текст-інструкції, які можна прочитати.

4.2Що означає «запустити» код

Ключова ідея, яку плутають усі новачки: код — це просто текст, доки його хтось не виконає. Файл index.html сам собою нічого не робить — це лежачий текст з інструкціями. «Оживає» він, коли його читає браузер: браузер виконує ці інструкції й показує тобі сторінку з кнопкою.

Тобто є дві різні дії, і важливо їх не плутати:

  • Редагувати файл — змінювати текст інструкцій (це робив Claude Code).
  • Запустити (виконати) — дати програмі прочитати ці інструкції й діяти (це зробив браузер, коли ти відкрив сторінку).

Аналогія. Файл коду — як партитура (ноти). Сама по собі вона мовчить. Музика з'являється, коли музикант (виконавець) її грає. Для вебсторінки виконавець — браузер; для програми на Python виконавцем буде Python (це побачимо в Модулі 6).

Навіщо тобі це розуміти. Коли далі щось «не працює», ти вже зможеш поставити правильне питання: проблема в самому тексті-коді чи в тому, як ми його запускаємо? Це половина успіху в налагодженні.

4.3Клієнт і сервер: звідки беруться дані

Твоя сторінка відкрилася прямо з диска — усе сталося на твоєму комп'ютері. Але справжні застосунки часто потребують даних «ззовні»: курс валют, повідомлення, відповідь моделі. Тоді в гру вступає пара клієнт і сервер.

  • Клієнт — програма користувача (браузер, застосунок), яка просить дані.
  • Сервер — комп'ютер у дата-центрі, що працює цілодобово й відповідає на запити.
sequenceDiagram
  participant K as Клієнт (твоя програма)
  participant S as Сервер
  K->>S: запит — "дай мені дані"
  S->>S: обробляє запит
  S-->>K: відповідь — дані

Будь-яка взаємодія в інтернеті — це цикл «запит → відповідь»

Запити ходять за правилами протоколу HTTP. Інколи у відповідь приходить код стану: 200 — усе добре, 404 — не знайдено (ту саму «404» ти, мабуть, бачив у браузері). Глибоко вникати не треба — досить розуміти сам рух «запит → відповідь».

Чому це для нас критично. Коли в наступній фазі твоя програма звертатиметься до моделі Claude — вона буде клієнтом, а модель — сервером. Тобто весь AI-код, який ми писатимемо, — це варіація цієї простої схеми «надіслав запит — отримав відповідь».

4.4API та JSON: як програми домовляються

Якщо сервер — це «кухня», то API — це її меню: список того, що можна замовити, і що ти за це отримаєш. API (Application Programming Interface) описує, які запити сервіс приймає й що повертає. Звернення до Claude — це виклик API Anthropic: надсилаєш повідомлення — отримуєш відповідь моделі. Уся робота AI-інженера крутиться навколо API.

А «мова», якою програми обмінюються даними, найчастіше — JSON: простий текстовий формат із пар «ключ: значення». Його легко читає і людина, і програма: 

{
  "name": "Андрій",
  "lessons_done": 3,
  "is_active": true,
  "topics": ["вступ", "термінал", "веб"]
}

Бачиш: текст у лапках, числа, true/false і список у квадратних дужках — це майже весь JSON. Саме у такому вигляді модель повертатиме структуровані дані, а різні сервіси обмінюватимуться інформацією між собою.

Зв'язок із попереднім. Пам'ятаєш картку-«меню»? Клієнт робить запит до API сервера, а дані туди-сюди їдуть у форматі JSON. Три поняття — сервер, API, JSON — працюють разом. Тримай це як єдину картинку.

4.5Складаємо все в одну карту

Звʼяжемо докупи. Ось як виглядає твій світ розробки тепер — від твоєї дії до результату: 

flowchart LR
  Y["Ти
(ставиш задачу)"] --> CC["Claude Code
(пише файли)"]
  CC --> F["Файли проєкту
(код = текст)"]
  F --> R["Запуск
(браузер / Python)"]
  R --> NET["За потреби — запит
до API сервера (JSON)"]
  style Y fill:#2A211C,stroke:#D97757,color:#F0EEE6

Загальна карта: від твоєї задачі до працюючої програми, що може звертатись до сервісів

Читається так: ти ставиш задачу → Claude Code створює файли (код-текст) → ти їх запускаєш → за потреби програма звертається до зовнішніх сервісів через API, обмінюючись даними в JSON. Уся подальша інженерія — лише деталі цієї простої карти.

Підсумок. Ти розумієш, що таке файли й папки, що означає «запустити» код, як спілкуються клієнт і сервер, і що API з JSON — це «меню» й «мова» цього спілкування. Перш ніж будувати з моделлю, зробимо ще одну важливу річ — навчимося зберігати свою роботу так, щоб її не втратити й показати світу. Це наступний модуль: Git і GitHub.
