Фаза C · Агенти й команди агентів

Що таке AI-агент

Агенти · 7 уроків · ≈ 90 хв

Ось ми й дійшли до серця твоєї мети. Досі модель робила один крок: відповіла або один раз викликала інструмент. Агент — це коли модель сама проходить багато кроків поспіль, вирішуючи, що робити далі, поки не виконає задачу. У цьому модулі ми розберемо ідею, головний цикл, а потім зберемо повний робочий агент, який ти зможеш скопіювати, запустити й покроково простежити. Це фундамент усієї фази, тому йдемо ґрунтовно.

12.1Агент проти простого виклику

У Модулі 10 модель один раз попросила інструмент, отримала результат — і дала відповідь. Це як відповісти на одне питання. Агент працює інакше: він отримує мету і самостійно робить стільки кроків, скільки треба, щоб її досягти — викликаючи інструменти, дивлячись на результати й вирішуючи, що робити далі.

Аналогія. Простий виклик — як спитати колегу «котра година?»: одна відповідь. Агент — як доручити стажеру «підготуй звіт про продажі за тиждень»: він сам зрозуміє, що треба зібрати дані, порахувати, оформити й зберегти — крок за кроком, без твоїх вказівок на кожен рух.

Порівняймо прямо:

Простий виклик (Модуль 10):
  ти -> модель -> [один інструмент] -> відповідь.   Один прохід, кінець.

Агент (цей модуль):
  ти -> модель -> інструмент -> результат ->
        модель -> інструмент -> результат ->
        модель -> ... -> фінальна відповідь.        Багато проходів, поки не готово.

Коротко. Агент = модель + інструменти + цикл, у якому вона сама керує послідовністю дій до результату. Усе технічне ти вже знаєш із Модуля 10 — лишилось повторити tool use багато разів. Саме цей цикл і розглянемо.

12.2Цикл агента: думай → дій → спостерігай

В основі будь-якого агента — простий повторюваний цикл із трьох кроків. Модель думає, що зробити; діє (викликає інструмент); спостерігає результат; і вирішує — задача виконана чи треба ще крок:

  G["Мета / задача"] --> T["Думай:
що зробити далі?"]
  T --> A["Дій:
виклик інструмента"]
  A --> O["Спостерігай:
результат інструмента"]
  O --> D{"Задача
виконана?"}
  D -- "Ні" --> T
  D -- "Так" --> F["Фінальна відповідь"]

Серце агента: цикл «думай → дій → спостерігай», поки мету не досягнуто

Це майже точно цикл tool use з Модуля 10 — лише замість одного проходу він повторюється. Модель може викликати один інструмент, побачити результат, викликати інший, ще раз перший — будь-яку послідовність, яку вважатиме за потрібне. А коли вирішить, що задача виконана, просто дасть фінальну відповідь замість запиту інструмента.

Звідки агент «знає», коли зупинитись. Згадай stop_reason (Модуль 8): поки модель просить інструменти, він дорівнює "tool_use" — цикл триває. Щойно модель відповідає звичайним текстом (інструмент більше не потрібен) — цикл завершується. Це й буде наша умова виходу в коді.

12.3Коли агент потрібен, а коли — ні

Агенти потужні, але це не «срібна куля». Вони повільніші (багато кроків = багато викликів моделі), дорожчі (за кожен крок платиш токенами) і менш передбачувані (модель сама обирає шлях). Інженер свідомо вирішує, чи справді задача варта агента.

  • Агент доречний: задача багатокрокова, кроки наперед невідомі, потрібні рішення «на ходу» — наприклад, «дослідити тему, зібрати дані з кількох джерел і скласти звіт».
  • Агент зайвий: задача проста й однокрокова. Класифікувати один відгук — достатньо простого виклику (Модуль 9). Відповісти по документах — RAG (Модуль 11).
Питання для себе перед тим, як будувати агента:
  1. Чи потрібно кілька кроків?        Ні -> простий виклик.
  2. Чи кроки відомі наперед?          Так -> звичайний код/конвеєр, не агент.
  3. Чи треба рішення "на ходу"?       Так -> ось тут і потрібен агент.

Правило великого пальця. Починай із найпростішого, що вирішує задачу: простий виклик → tool use → RAG → і лише якщо потрібна справжня багатокрокова автономність — агент. Зайвий агент додає вартість, повільність і місця для помилок без користі.

12.4Будуємо повний мінімальний агент

Тепер — повний робочий файл, який можна скопіювати й запустити (нічого не розкидано по інших модулях). Це той самий tool use з Модуля 10, обгорнутий у цикл. Попроси Claude Code: «створи файл simple_agent.py — агент з інструментом погоди й циклом із межею кроків». Ось весь файл: 

import os
from anthropic import Anthropic
from dotenv import load_dotenv

load_dotenv()
client = Anthropic(api_key=os.getenv("ANTHROPIC_API_KEY"))
MODEL = "claude-sonnet-5"   # приклад; актуальні моделі — docs.claude.com

# 1) Інструмент — звичайна функція
def get_weather(city):
    return f"{city}: +18°C, ясно"   # тут міг би бути реальний виклик API погоди

# 2) Опис інструмента для моделі (анкета з Модуля 10)
tools = [{
    "name": "get_weather",
    "description": "Повертає поточну погоду для вказаного міста",
    "input_schema": {
        "type": "object",
        "properties": {"city": {"type": "string", "description": "Назва міста"}},
        "required": ["city"],
    },
}]

# 3) Карта: ім'я інструмента -> справжня функція
tool_functions = {"get_weather": get_weather}

# 4) Цикл агента
def run_agent(task, max_steps=8):
    messages = [{"role": "user", "content": task}]

    for step in range(max_steps):                # межа кроків — щоб НЕ зациклитись
        resp = client.messages.create(
            model=MODEL, max_tokens=1000, tools=tools, messages=messages
        )
        messages.append({"role": "assistant", "content": resp.content})

        if resp.stop_reason != "tool_use":       # модель відповіла текстом — готово
            return resp.content[0].text

        # інакше виконуємо всі запитані інструменти й повертаємо результати
        results = []
        for block in resp.content:
            if block.type == "tool_use":
                func = tool_functions[block.name]
                try:
                    output = func(**block.input)
                except Exception as e:
                    output = f"помилка: {e}"      # навіть збій повертаємо моделі
                results.append({
                    "type": "tool_result",
                    "tool_use_id": block.id,
                    "content": str(output),
                })
        messages.append({"role": "user", "content": results})

    return "Досягнуто межі кроків"

# 5) Запуск
print(run_agent("Яка погода в Києві та Львові?"))

Розбір по блоках. Блоки 1–3 — підготовка (інструмент, його опис, карта імен). Блок 4 — серце: for step in range(max_steps) повторює цикл із запобіжником. На кожному кроці робимо запит із інструментами; якщо stop_reason != "tool_use" — модель завершила, повертаємо текст. Інакше пробігаємо блоки, для кожного tool_use знаходимо функцію за іменем, виконуємо (**block.input — розпакування аргументів, Модуль 10) і повертаємо всі результати одним повідомленням. Потім — наступне коло.

Чому задача про два міста. Ми спитали погоду в Києві та Львові навмисно: це змусить агента викликати інструмент не один раз — і ти на власні очі побачиш, як цикл повторюється. Саме це й відрізняє агента від одиничного виклику.

12.5Що відбувається крок за кроком

Запусти python simple_agent.py. Зовні ти побачиш одну фінальну відповідь, але всередині цикл прокрутився кілька разів. Ось що там сталося: 

sequenceDiagram
  participant K as Твій код (цикл)
  participant M as Модель
  K->>M: "Яка погода в Києві та Львові?" + інструменти
  M-->>K: виклич get_weather(Київ) і get_weather(Львів)
  K->>K: виконує обидві функції
  K->>M: tool_result: Київ +18, Львів +18
  M-->>K: фінальний текст (stop_reason != tool_use)
  K->>K: цикл завершується, повертаємо текст

Один запуск агента — кілька проходів циклу всередині

Щоб побачити це на власні очі, додай у цикл один рядок-«шпигун»:

        for block in resp.content:
            if block.type == "tool_use":
                print(f"[крок {step+1}] виклик: {block.name}({block.input})")  # <-- додай
                func = tool_functions[block.name]
                ...

Що ти маєш побачити у терміналі (приблизно):

[крок 1] виклик: get_weather({'city': 'Київ'})
[крок 1] виклик: get_weather({'city': 'Львів'})
У Києві та Львові зараз +18°C, ясно.

Бачиш? Модель попросила інструмент двічі (по разу на місто), отримала результати — і аж тоді дала фінальну відповідь. Це і є «думай → дій → спостерігай» у дії.

Чому це важливо. Цей друк («шпигун») — твоє вікно у «голову» агента. Коли щось піде не так, саме він покаже, який інструмент і з якими аргументами викликала модель і де саме збій. Ми активно користуватимемось ним у наступному модулі.

12.6Даємо агенту кілька інструментів

Справжня сила агента — коли в нього кілька інструментів і він сам обирає потрібний під кожен крок. Додамо до погоди ще один — поточний час. Зміни в нашому файлі мінімальні: додаємо функцію, її опис і запис у карту. 

# нова функція-інструмент
def get_time(city):
    return f"У місті {city} зараз 14:30"   # приклад; реально — через бібліотеку часу

# додаємо опис у список tools
tools.append({
    "name": "get_time",
    "description": "Повертає поточний час у вказаному місті",
    "input_schema": {
        "type": "object",
        "properties": {"city": {"type": "string", "description": "Назва міста"}},
        "required": ["city"],
    },
})

# додаємо у карту імен
tool_functions["get_time"] = get_time

# тепер агент сам обере інструмент під запитання:
print(run_agent("Яка погода в Києві і котра там година?"))

Що ти маєш побачити. Агент викличе get_weather (для погоди) і get_time (для часу), а тоді поєднає обидва в одну відповідь. Зверни увагу: ми не вказували, який інструмент коли брати — модель вирішила це сама, прочитавши описи (description). Тому описи мають бути зрозумілі.

Помічаєш патерн? Щоб розширити можливості агента, ти додаєш три речі: функцію, її опис і запис у карту. Сам цикл run_agent не змінюється взагалі. Це масштабований підхід — у наступному модулі ми дамо агенту три інструменти під реальну задачу.

12.7Безпека й межі агента

Агент діє сам — а отже, потрібні запобіжники. Це не формальність: агент із доступом до реальних дій (видалити файл, надіслати лист, витратити гроші) може наробити шкоди, якщо помилиться чи зациклиться.

  • Межа кроків. Завжди обмежуй кількість ітерацій (max_steps у нашому коді) — щоб агент не крутився вічно, спалюючи токени.
  • Підтвердження ризикованих дій. Небезпечні інструменти (видалення, оплата, надсилання) варто виконувати лише після твого «так» — як це робить сам Claude Code (Модуль 3).
  • Обмежені права. Давай агенту лише ті інструменти, що реально потрібні. Менше можливостей — менше способів помилитись.
  • Обробка збоїв. Помітив try/except навколо виклику функції в нашому коді? Він гарантує: навіть якщо інструмент впаде, агент отримає повідомлення про помилку й зможе відреагувати, а не зламається весь процес.
  • Контроль вартості. Цикл = багато викликів. Пам'ятай про токени (Модуль 8) і ліміт витрат у консолі (Модуль 2).

Підсумок модуля. Агент — це модель + інструменти + цикл «думай → дій → спостерігай», що повторюється до результату. Ти зрозумів, коли агент доречний, зібрав повний робочий мінімальний агент, простежив його роботу крок за кроком, додав другий інструмент і знаєш запобіжники. Наступний модуль — велика практика: збудуємо реального агента під бізнес-задачу з трьома інструментами, від плану до запуску й покращень.
